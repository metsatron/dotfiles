#+TITLE: Shortcuts — the keyboard layer contract
#+DESCRIPTION: The modifier→layer law governing every keybinding across terminals, multiplexers, desktops, and editors
#+AUTHOR: Mètsàtron — Sovereign Weaver
#+LANGUAGE: en
#+OPTIONS: toc:2

* What this document is

This is not a keybinding registry. The bindings themselves live in the org sources that own them — =term.org= (kitty), =mux.org= (tmux, Zellij, herdr), =x11.org= (XFCE), =desktop-plasma.org= (SonicDE), =menu.org= (rofi suite), and =emacs-doom.org= / =emacs-spacemacs.org= (Evil/NEIO). Those files are canonical, and any table reproduced here is a *copy* that can drift. When this document and an org source disagree, **the org source wins and this document is the bug**.

What this document owns is the thing no config file can express, because it lives *between* them: the law governing which modifier may claim which key, why each layer was allocated as it was, and what breaks when a layer reaches across its boundary. It exists to be consulted *before* adding a keybinding, so that the next binding is legal by construction rather than by luck. Every collision recorded here was paid for in debugging time; the point of writing them down is to only pay once.

* The two laws

** Law 1 — Colemak-NEIO is the movement contract

Mètsàtron types Colemak-NEIO. The full statement of this law is =agents.org= rule 18 (emitted to =CLAUDE.md=), which is canonical and takes precedence over this summary. In short:

| Key | Means                                 |
|-----+---------------------------------------|
| ~n~ | left / back / previous / close modal  |
| ~e~ | down / next row                       |
| ~i~ | up / previous row                     |
| ~o~ | right / open / confirm / enter column |

And the negative constraints, which are the part that actually gets violated:

- =h= means find/search-next — *never* "left".
- =k= means insert — *never* "up".
- =l= means newline/open-line — *never* "right".
- =h/j/k/l= is never the primary movement contract in any TUI. Vim-style =j/k= may exist as an optional compatibility alias, never as the documented binding.

** Law 2 — each modifier owns exactly one layer

The stack is four layers deep, and a keypress is resolved by the *outermost* layer that claims it. A layer that binds a key steals it from everything inside it. Therefore each layer gets its own modifier namespace, and they do not overlap:

| Modifier            | Layer                             | Owned by                            |
|---------------------+-----------------------------------+-------------------------------------|
| ~ctrl~              | shell, readline, TUI apps         | the applications themselves         |
| ~ctrl+shift~        | terminal emulator (kitty)         | ~term.org~                          |
| ~prefix~ (~ctrl+a~) | multiplexer (tmux, Zellij, herdr) | ~mux.org~                           |
| ~super~             | desktop / window manager          | ~x11.org~, ~desktop-plasma.org~, ~menu.org~ |

Read it outside-in: the window manager grabs =super= before the terminal ever sees the keypress; kitty consumes =ctrl+shift= before the multiplexer sees it; the multiplexer consumes its prefix before the shell sees it; whatever survives reaches the application. This is why the allocation is not a matter of taste. **A binding placed in the wrong namespace does not merely look untidy — it silently eats a key from a layer below and the failure is invisible.**

The one deliberate exception is =super+1..9= for herdr's =focus_agent=, which reaches *inward* from the desktop namespace into the multiplexer. It is legal only because the desktop layer leaves the number row unclaimed (see "The Super namespace" below), and it works only because kitty negotiates the kitty keyboard protocol — legacy terminal key encoding cannot transmit a Super modifier at all.

* The idiom: digits jump, arrows scan

Within every layer, the digit row and the arrow cluster mean two different things, and this is consistent by design:

- **Digits are direct and position-independent.** Tab 3 is =<mod>+3= no matter where you are standing. No counting, no knowing where you are, no thinking.
- **The arrow cluster cycles.** Relative movement, for scanning left and right when you do not know or care what is where.

Cycling always costs a beat of thought, because you must know your current position before you know how many presses you need. Direct selection costs none. Prefer digits; keep cycling for scanning. On the T480s ThinkPad the arrow cluster has PgUp/PgDn directly above Left/Right, so the cycling bindings across kitty and herdr land under the same hand position one row apart.

| Layer        | Direct (jump)     | Cycle (scan)                     |
|--------------+-------------------+----------------------------------|
| kitty tabs   | ~ctrl+shift+1..9~ | ~ctrl+pgup~ / ~ctrl+pgdn~        |
| herdr tabs   | ~prefix+1..9~     | ~prefix+left~ / ~prefix+right~   |
| herdr agents | ~super+1..9~      | ~prefix+up~ / ~prefix+down~      |
| desktops     | ~super+F1..F8~    | (Plasma only) ~meta+ctrl+arrows~ |

* The Super namespace

Super is the desktop layer, and it is the most contended namespace because both XFCE and Plasma ship compiled-in defaults that squat in it. The fleet doctrine is *one set of keys everywhere*: the same key does the same thing on every machine, and where a stock default is in the way, it is displaced explicitly rather than worked around.

| Key            | Action                | XFCE (X230, T480s)   | Plasma / SonicDE (T480) |
|----------------+-----------------------+----------------------+-------------------------|
| ~super+F1..F8~ | switch to desktop 1–8 | yes                  | yes                     |
| ~super+space~  | rofi launcher (drun)  | yes                  | yes                     |
| ~super+x~      | rofi action menu      | yes                  | yes                     |
| ~super+r~      | rofi run dialog       | yes                  | yes                     |
| ~super+w~      | rofi window switcher  | yes                  | yes                     |
| ~super+z~      | clipboard history     | yes                  | yes                     |
| ~super+.~      | emoji picker          | yes                  | yes                     |
| ~super+v~      | speak clipboard       | yes                  | yes                     |
| ~super+m~      | rofi mpd music menu   | yes                  | —                       |
| ~super+t~      | kitty                 | yes                  | —                       |
| ~super+c~      | whisper hotkey        | yes                  | —                       |
| ~super+1..9~   | herdr ~focus_agent~   | free — reaches herdr | **GRABBED** — see below |

Displacements that had to be asserted explicitly, and must not be quietly reverted: Plasma's KWin "Overview" is forced to =none= so =super+w= can reach rofi; Plasma's native Emoji Selector is moved to =meta+ctrl+alt+shift+space= so =super+.= can reach rofimoji; Spectacle's secondary "Record Rectangular Region" is displaced so =super+r= can reach rofi (its primary stays on =meta+shift+r=). =super+e= and =super+b= are deliberately *not* used, because KDE binds them compiled-in to Dolphin and the power-profile switch.

* Known scars

These are live constraints, not history. Each cost real debugging time.

** The xfwm4 one-slot rule (the "Super+4 bug")

xfwm4 binds *exactly one key per action*. Binding =<Super>N= to =workspace_N_key= does not add a second accelerator alongside the stock =<Primary>FN= — the two xfconf properties compete for one slot, and the winner is decided by xfconf's internal hash enumeration order, not by XML order or write recency. =<Primary>F4= won =workspace_4_key= on every fresh start, so =Super+4= was never grabbed at all: an =XGrabKey= probe showed the keycode sitting completely free. Because =Super+1/2/3= happened to win their slots, the failure looked key-specific and sent six rounds of fixes chasing theories (PATH failures, regrab races, off-by-one workspace counts) that were never tested against the X server.

The discipline that came out of it, and which now governs every WM binding on the fleet: **probe the grab before theorising about it.** One =XGrabKey= probe distinguishes "someone stole it" from "nobody ever asked for it" in seconds. And: prefer the stock default unless it is actually in the way — the binding being fought for was a remap of a default that already worked.

This is why =xfce-sanctuary-shortcuts= does not merely *set* each workspace binding but asserts it *exclusively*, clearing every rival property bound to the same action first.

** =ctrl+a= shadows readline =beginning-of-line=

The multiplexer prefix is =ctrl+a= across tmux, Zellij and herdr — chosen for reach (=a= is home row; =ctrl+b= makes the hand hunt) and for cross-multiplexer consistency. The cost is real: =ctrl+a= is readline's =beginning-of-line=, and a multiplexer swallows it before the shell sees it.

tmux patches this with =bind C-a send-prefix= — press it twice and a literal =^A= reaches the shell. **herdr has no =send_prefix= action at all** (verified absent from both its default config and its binary), so inside a herdr pane there is no escape hatch: use =Home=. This is accepted, not a bug to fix.

Related: prefix presses do not add linearly when multiplexers are nested, they *double*. Each layer intercepts every =ctrl+a= that reaches it, and the only way to push a literal =^A= through a layer is =C-a C-a=. So depth 1 needs 1 press, depth 2 needs 2, and depth 3 needs **4** — not 3. This is why deep nesting "randomly stops working". Flatten with workspaces instead of nesting sessions.

** herdr cannot bind PageUp/PageDown

herdr's keybind parser has no page-key token in any spelling. Its accepted key vocabulary includes the arrows, =home=, =end=, =tab=, =esc=, =enter=, =space=, =insert= and =delete=, but nothing for page up/down — the only page-key strings in the binary are crossterm's internal enum names and a scrollback help line. A =prefix+pgup= binding is rejected with =unsupported key= in the =reload-config= diagnostics. herdr *receives* the page keys (it scrolls with them internally); it just will not let you *bind* them. Hence tab cycling on =prefix+left= / =prefix+right=. This is an upstream gap, not a config error.

** =alt+1..9= and =ctrl+1..9= are both unavailable for tab/agent selection

Two tempting alternatives to the digit bindings above, both rejected for cause:

- =alt+1..9= is Emacs' *numeric prefix argument*. Binding it at the terminal or multiplexer layer steals it from Emacs.
- =ctrl+1..9= is worse: half that range *is* control characters in legacy terminal encoding — =ctrl+3= emits ESC, =ctrl+6= is =^^= (Vim's alternate-file toggle), =ctrl+4/5/7/8= are =^\=, =^]=, =^_= and DEL — while =ctrl+1= and =ctrl+9= have no legacy encoding at all and only exist under the kitty keyboard protocol. It would be simultaneously flaky at the ends and destructive in the middle.

This is the concrete reason Law 2 exists. =ctrl= belongs to the applications; the terminal and multiplexer layers must stay out of it.

* Adding a new binding — the checklist

1. **Which layer does the action belong to?** Application → =ctrl=. Terminal → =ctrl+shift=. Multiplexer → =prefix=. Desktop → =super=. Bind it in that namespace and no other.
2. **Is it movement?** Then it is =n/e/i/o=, and =h/k/l= keep their Colemak meanings. No exceptions, no "just this once for vim muscle memory".
3. **Is it selection or cycling?** Digits for direct jumps, arrow cluster for scanning.
4. **Does anything already hold the key?** Grep is not sufficient — bindings are sometimes *generated in loops* (Plasma's =meta+1..9= is written as =Meta+$n=, invisible to a literal search) and compiled-in WM defaults appear in no config file at all. For a WM binding, probe the grab.
5. **Does it reach across a layer?** If so, say why in the org prose, next to the binding. =super+1..9= reaching into herdr is legal *and documented*; the next one must earn it the same way.
6. **Write the rejected alternatives down.** The reasoning is what gets lost, and lost reasoning is what gets re-litigated.
