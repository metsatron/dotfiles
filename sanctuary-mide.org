* Purpose

=sanctuary-mide= hosts *MiDesktop 1.2* — Libranext Computer Systems' maintained fork of KDE 1.1.2, the last release of the 1.x series, ported to their *Osiris* toolkit (a maintained fork of Qt 2.3.2). Upstream: https://centre.libranext.com/libranext/mide (branch =1.2=) and https://centre.libranext.com/libranext/osiris (tag =2.4.4=, meson build). This is genuine period KDE 1 — kwm, kpanel, kfm, krootwm, konsole, kvt, kcontrol, kdehelp — kept alive by a small independent shop entirely outside the modern KDE foundation orbit, which is exactly the lineage this habitat exists to preserve. It joins the KDE 1 continuity thread already running through =sanctuary-redstone-9x-kde1-history.org= and the =KDE-1-*= icon payloads.

Like every sanctuary it rides the one-store-many-rooms Guix substrate from =sanctuary-distrobox.org=: base image =sanctuary-base:guix=, host =/gnu/store= read-only, a dedicated =sanctuary-mide= Guix profile providing only the build toolchain and libraries, and the desktop itself compiled from source inside the container. Xephyr display is *=:95=* (=:90= qtile, =:91= gnustep, =:92= cde, =:93= redstone-9x, =:94= godzilla-xs and retropie, =:96= nscde).

* The /opt/kde1 persistence decision

MiDesktop hard-requires the install prefix =/opt/kde1= (upstream README: it must always live under =/opt= and cannot coexist with another KDE otherwise). The container's own writable layer is disposable by design, so an install there would die with every recreate. The fix is a create-time bind volume in =create_one()= (=sanctuary-distrobox.org=): =--volume "${GUESTS_DIR}/sanctuary-mide/opt-kde1:/opt/kde1:rw"= — a real directory at the exact required absolute path, backed by host storage next to the guest home, surviving container recreation identically to the home itself. The rejected alternative — an =--init-hooks= symlink from =/opt/kde1= into the guest home — lives in the disposable layer and invites CMake realpath/RPATH surprises. =preflight_one()= pre-creates the host-side directory because rootless podman refuses a missing bind source.

Osiris co-installs into the same =/opt/kde1= prefix: one =CMAKE_PREFIX_PATH=, one =PKG_CONFIG_PATH=, one =LD_LIBRARY_PATH=, matching the KDE1-era convention of merged =QTDIR=/=KDEDIR= trees. The per-stage build sentinels also live inside the bind volume, so build idempotence survives recreation too.

* Source build: sanctuary-mide-build

Host-side build driver following the =sanctuary-cde-build= pattern: an inner script heredoc executed through =sanctuary-exec= inside the container. Build order is Osiris 2.4.4 (meson), then MiDesktop =libs= → =base= → =utils= (CMake + Ninja, =CMAKE_BUILD_TYPE=Debug= per upstream README). Each stage is guarded by its own sentinel file inside =/opt/kde1= and the whole script is safe to re-run; a re-run after success is a fast no-op. Upstream notes CMake may warn about missing xcb/xkb/libtiff even when they are present — ignorable as long as compilation succeeds.

#+BEGIN_SRC bash :tangle linux/.local/bin/sanctuary-mide-build :shebang "#!/usr/bin/env bash"
# Build Osiris 2.4.4 + MiDesktop 1.2 from source inside sanctuary-mide.
# Run once from the host: sanctuary-mide-build
# Sources: https://centre.libranext.com/libranext/{osiris,mide}
set -euo pipefail

usage() {
  cat <<EOF
sanctuary-mide-build - build Osiris + MiDesktop inside sanctuary-mide

Usage: sanctuary-mide-build
       sanctuary-mide-build -h | --help

No arguments. Clones, compiles, and installs the Osiris toolkit (2.4.4)
and MiDesktop (branch 1.2: libs, base, utils) into /opt/kde1 — a bind
volume backed by the host at
~/.local/share/dotcortex/guests/sanctuary-mide/opt-kde1, so the install
and its stage sentinels survive container recreation. Idempotent:
completed stages are skipped via sentinel files.
EOF
}

if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
  usage
  exit 0
fi

if (( $# > 0 )); then
  usage >&2
  exit 1
fi

OSIRIS_TAG="2.4.4"
MIDE_BRANCH="1.2"
SANCTUARY="sanctuary-mide"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"

# Heredoc builds the inner script — outer-shell vars (OSIRIS_TAG, MIDE_BRANCH,
# GUIX_PROFILES) expand at heredoc time; inner-shell vars are deferred via \$.
INNER_SCRIPT=$(cat <<INNER_EOF
set -eo pipefail

PREFIX=/opt/kde1
SRC=\${HOME}/.local/share/mide-src

# Pre-declare vars the Guix profile scripts append to — they run under set -u
# semantics in some layers and must never hit an unbound variable.
export PKG_CONFIG_PATH="\${PKG_CONFIG_PATH:-}"
export LD_LIBRARY_PATH="\${LD_LIBRARY_PATH:-}"
export CMAKE_PREFIX_PATH="\${CMAKE_PREFIX_PATH:-}"

GUIX_PROFILE=${GUIX_PROFILES}/desktop-common/desktop-common
. \${GUIX_PROFILE}/etc/profile
GUIX_PROFILE=${GUIX_PROFILES}/sanctuary-mide/sanctuary-mide
. \${GUIX_PROFILE}/etc/profile
export CURL_CA_BUNDLE=\${GIT_SSL_CAINFO}

if [ ! -d "\${PREFIX}" ] || [ ! -w "\${PREFIX}" ]; then
  echo "\${PREFIX} is missing or not writable — the opt-kde1 bind volume is absent." >&2
  echo "Recreate the container: distrobox-sanctuaries-create sanctuary-mide" >&2
  exit 1
fi

# Single merged prefix: Osiris and MiDesktop both live in /opt/kde1
# (KDE1-era merged QTDIR/KDEDIR convention).
export QTDIR=\${PREFIX}
export KDEDIR=\${PREFIX}
export CMAKE_PREFIX_PATH=\${PREFIX}\${CMAKE_PREFIX_PATH:+:\${CMAKE_PREFIX_PATH}}
export PKG_CONFIG_PATH=\${PREFIX}/lib/pkgconfig\${PKG_CONFIG_PATH:+:\${PKG_CONFIG_PATH}}
# Osiris (meson, --libdir=lib) installs to lib; MiDesktop (CMake) detects
# lib64 — both are live library dirs in this prefix.
export LD_LIBRARY_PATH=\${PREFIX}/lib:\${PREFIX}/lib64\${LD_LIBRARY_PATH:+:\${LD_LIBRARY_PATH}}
export PATH=\${PREFIX}/bin:\${PATH}

mkdir -p "\${SRC}"
cd "\${SRC}"

if [ ! -d osiris ]; then
  echo "Cloning Osiris ${OSIRIS_TAG}..."
  git clone --depth 1 --branch ${OSIRIS_TAG} https://centre.libranext.com/libranext/osiris.git
fi
if [ ! -d mide ]; then
  echo "Cloning MiDesktop ${MIDE_BRANCH}..."
  git clone --depth 1 --branch ${MIDE_BRANCH} https://centre.libranext.com/libranext/mide.git
fi

# ── Stage 1: Osiris toolkit (meson) ─────────────────────────────────────────
if [ ! -f "\${PREFIX}/.sentinel-osiris-${OSIRIS_TAG}" ]; then
  echo "Building Osiris ${OSIRIS_TAG}..."
  cd "\${SRC}/osiris"
  # Osiris' post-install script writes /etc/ld.so.conf.d and /etc/profile.d,
  # which are root-owned container-layer paths an unprivileged sanctuary user
  # cannot touch — and unnecessary here: the launcher and this build export
  # PATH/LD_LIBRARY_PATH explicitly. Neutralize it (idempotent).
  if ! grep -q 'DotCortex: skipped' _install_generate_ldconfig_profile.sh; then
    sed -i '1a exit 0 # DotCortex: skipped — /etc unwritable in sanctuary; env set by launcher' \
      _install_generate_ldconfig_profile.sh
  fi
  # --libdir=lib pins the meson libdir so PKG_CONFIG_PATH/LD_LIBRARY_PATH above
  # stay correct regardless of platform-detected multiarch defaults.
  meson setup build --prefix="\${PREFIX}" --libdir=lib
  ninja -C build
  ninja -C build install
  touch "\${PREFIX}/.sentinel-osiris-${OSIRIS_TAG}"
else
  echo "Osiris ${OSIRIS_TAG} already installed (sentinel present)"
fi

# MiDesktop's OsirisMacros.cmake hardcodes /opt/osiris/bin/moc; Osiris is
# co-installed in /opt/kde1 here — repoint it (idempotent).
sed -i 's|/opt/osiris/bin/moc|/opt/kde1/bin/moc|g' \
  "\${SRC}/mide/libs/cmake/OsirisMacros.cmake"
# libs installs its CMake modules (FindKDE1.cmake etc.) into CMAKE_ROOT and an
# ld.so.conf.d snippet into /etc — the former is the read-only Guix store, the
# latter is disposable container layer. Keep both inside the prefix; base and
# utils get the module dir via -DCMAKE_MODULE_PATH below. (idempotent)
sed -i \
  -e 's|DESTINATION \${CMAKE_ROOT}/Modules)|DESTINATION \${CMAKE_INSTALL_PREFIX}/share/cmake/Modules)|' \
  -e 's|DESTINATION "/etc/ld.so.conf.d/")|DESTINATION "\${CMAKE_INSTALL_PREFIX}/etc/ld.so.conf.d/")|' \
  "\${SRC}/mide/libs/CMakeLists.txt"
# base likewise installs a profile.d snippet and a display-manager xsession
# entry to absolute system paths — unwritable and pointless in the sanctuary
# (the launcher execs startmidesktop directly). Keep them in the prefix.
sed -i \
  -e 's|DESTINATION "/etc/profile.d/"|DESTINATION "\${CMAKE_INSTALL_PREFIX}/etc/profile.d/"|' \
  -e 's|DESTINATION "/usr/share/xsessions/"|DESTINATION "\${CMAKE_INSTALL_PREFIX}/share/xsessions/"|' \
  "\${SRC}/mide/base/CMakeLists.txt"

# kwm's init-phase X error handler (base/kwm/main.C) aborts the whole window
# manager on ANY X error except BadWindow/BadColor. In a nested Xephyr, kwm
# intermittently gets a transient X_CopyArea(0x0): BadDrawable while building a
# titlebar decoration whose pixmap momentarily loads as 0x0 — one async error
# then kills the session (observed 2026-07-30). Extend the existing ignore list
# to also tolerate BadDrawable/BadPixmap during init, exactly as it already
# tolerates BadWindow/BadColor. Idempotent (guarded); invalidate the base
# sentinel so kwm is rebuilt when the patch is first applied.
if ! grep -q 'DotCortex: tolerate transient pixmap' "\${SRC}/mide/base/kwm/main.C"; then
  # NB: use '#' as the sed delimiter — the C pattern contains '||', which would
  # collide with a '|' delimiter and mis-parse the command.
  sed -i 's#e->error_code == BadWindow || e->error_code == BadColor))#e->error_code == BadWindow || e->error_code == BadColor || e->error_code == BadDrawable || e->error_code == BadPixmap)) /* DotCortex: tolerate transient pixmap errors during init */#' \
    "\${SRC}/mide/base/kwm/main.C"
  rm -f "\${PREFIX}/.sentinel-mide-base"
fi

# ── Stages 2-4: MiDesktop libs → base → utils (CMake + Ninja) ───────────────
for section in libs base utils; do
  if [ -f "\${PREFIX}/.sentinel-mide-\${section}" ]; then
    echo "MiDesktop \${section} already installed (sentinel present)"
    continue
  fi
  echo "Building MiDesktop \${section}..."
  cd "\${SRC}/mide/\${section}"
  mkdir -p build
  cd build
  # MiDesktop's bundled FindOsiris.cmake searches only the hardcoded
  # /opt/osiris prefix; point it at the co-installed /opt/kde1 tree instead.
  cmake -G Ninja \
    -DCMAKE_INSTALL_PREFIX="\${PREFIX}" \
    -DCMAKE_BUILD_TYPE=Debug \
    -DCMAKE_PREFIX_PATH="\${PREFIX}" \
    -DOSIRIS_INCLUDE_DIR="\${PREFIX}/include/osiris" \
    -DOSIRIS_LIBRARY_DIR="\${PREFIX}/lib" \
    -DCMAKE_MODULE_PATH="\${PREFIX}/share/cmake/Modules" \
    -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
    ..
  ninja
  ninja install
  touch "\${PREFIX}/.sentinel-mide-\${section}"
done

if [ -x "\${PREFIX}/bin/startmidesktop" ]; then
  echo "MiDesktop ${MIDE_BRANCH} installed to \${PREFIX}"
  echo "Session starter: \${PREFIX}/bin/startmidesktop"
  echo "Launch with: sanctuary-mide-launch"
else
  echo "Build finished but \${PREFIX}/bin/startmidesktop is missing — inspect the base stage." >&2
  exit 1
fi
INNER_EOF
)
sanctuary-exec "${SANCTUARY}" sh -c "${INNER_SCRIPT}"
#+END_SRC

* Launcher: sanctuary-mide-launch

Same shape as =sanctuary-qtile-launch=: dedicated Xephyr display, stale-session teardown, clipboard bridge, trash shield, then the session inside the container via =sanctuary-exec=. If the desktop has not been built yet the launcher falls back to a bare xterm with instructions rather than dying silently. Never run kdm inside Xephyr — it is a display manager wanting VT/PAM control.

*Session start order (why we do not exec startmidesktop).* Upstream's =startmidesktop= launches the window manager =kwm= LAST, after =kpanel= and =kfm=. In KDE1 the panel and the desktop reserve their screen area by sending =kwm= a single =KWM_WINDOW_REGION_CHANGED= client message, and register as modules the same fire-and-forget way (=KWMModuleApplication::connectToKWM=). =kwm= ingests the reserved region *only* from that live message — it never re-reads the =KWM_WINDOW_REGION_*= root property at startup (=libs/kdecore/kwm.cpp=, =base/kwm/manager.C:663=). So when the modules start before =kwm= is listening, the reservation is lost and both consumers fall back to =getWindowRegion='s full-screen default anchored at =(0,0)=. That default coincides with a bottom panel (so it looks fine) but places window titlebars and desktop icons *under* a top panel — the exact symptom seen 2026-07-30. The launcher therefore runs its own ordered sequence: =kwm= first, wait until it publishes =KWM_RUNNING= on the root window (polled with =xprop=), then =kfm=/=krootwm=/=kpanel=/=kbgndwm=/=miwelcome=, and finally =wait= on the =kwm= PID so session lifetime matches upstream's =exec kwm=. The session entry MiDesktop declares for a login-manager XSession is =/opt/kde1/bin/startmidesktop= (=base/configfiles_in/mi.desktop.in=); we reproduce its meaningful steps in the correct order rather than inheriting its ordering bug.

#+BEGIN_SRC bash :tangle linux/.local/bin/sanctuary-mide-launch :shebang "#!/usr/bin/env bash"
# Launch sanctuary-mide: Xephyr :95 + MiDesktop (KDE 1.1.2 fork) inside the Guix container.
set -euo pipefail

if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
  cat <<EOF
sanctuary-mide-launch - launch sanctuary-mide (Xephyr :95 + MiDesktop, KDE 1 sanctuary)

Usage: sanctuary-mide-launch

No arguments. Requires a completed sanctuary-mide-build (session starter
/opt/kde1/bin/startmidesktop inside the container).
Normally invoked via: sanctuary-enter sanctuary-mide
EOF
  exit 0
fi

DISPLAY_NUM=":95"
HOST_DISPLAY="${DISPLAY}"
SANCTUARY="sanctuary-mide"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"

sanctuary-teardown-stale-session "${SANCTUARY}" "${DISPLAY_NUM}"

mapfile -t XEPHYR_GEOMETRY < <(sanctuary-xephyr-geometry)
Xephyr "${DISPLAY_NUM}" "${XEPHYR_GEOMETRY[@]}" -br -ac -no-host-grab &
XEPHYR_PID=$!
trap "kill ${XEPHYR_PID} 2>/dev/null || true" EXIT

timeout 10 sh -c "until DISPLAY=${DISPLAY_NUM} xdpyinfo >/dev/null 2>&1; do sleep 0.1; done" \
  || { echo "Xephyr ${DISPLAY_NUM} did not become ready"; kill "${XEPHYR_PID}"; exit 1; }

sanctuary-clip-bridge "${HOST_DISPLAY}" "${DISPLAY_NUM}" &
CLIP_BRIDGE_PID=$!
trap "kill ${XEPHYR_PID} ${CLIP_BRIDGE_PID} 2>/dev/null || true" EXIT

# ── Shield trash:/// from host fleet NFS mounts (see sanctuary-trash-shield) ──
sanctuary-trash-shield "${SANCTUARY}" "${HOME}"

echo "${SANCTUARY}: Xephyr ${DISPLAY_NUM} ready — sourcing Guix profiles and starting MiDesktop…"
DISPLAY="${DISPLAY_NUM}" sanctuary-exec "${SANCTUARY}" sh -c "
  GUIX_PROFILE=${GUIX_PROFILES}/desktop-common/desktop-common
  . \${GUIX_PROFILE}/etc/profile
  GUIX_PROFILE=${GUIX_PROFILES}/sanctuary-mide/sanctuary-mide
  . \${GUIX_PROFILE}/etc/profile
  export QTDIR=/opt/kde1
  export KDEDIR=/opt/kde1
  export PATH=/opt/kde1/bin:\${PATH}
  export LD_LIBRARY_PATH=/opt/kde1/lib:/opt/kde1/lib64\${LD_LIBRARY_PATH:+:\${LD_LIBRARY_PATH}}
  # KDE1's kprocess needs a valid \$SHELL; sanctuary-exec's env allowlist drops
  # it, which produced 'Could not find a valid shell'. Point it at a real
  # interpreter present inside the container.
  export SHELL=\"\$(command -v bash || command -v zsh || echo /bin/sh)\"
  if [ ! -x /opt/kde1/bin/kwm ]; then
    echo 'MiDesktop not built — run sanctuary-mide-build first.' >&2
    exec xterm -title 'sanctuary-mide: run sanctuary-mide-build first'
  fi
  # Pre-create the runtime dirs the components stat during init so kwm and the
  # modules never race a half-populated tree (kdisknav lives in the rw /opt
  # bind volume; the theme Work dir and Games target live in the guest home).
  mkdir -p /opt/kde1/share/apps/kdisknav \
           \"\${HOME}/.kde/share/apps/kthememgr/Work\" \
           \"\${HOME}/Games\" 2>/dev/null || true
  # Start the session in the correct order — DELIBERATELY NOT via upstream's
  # startmidesktop, which execs the window manager LAST. In KDE1 the panel
  # (kpanel) and desktop (kfm) reserve their screen area by sending kwm a
  # one-shot KWM_WINDOW_REGION_CHANGED client message, and register as modules
  # the same fire-and-forget way (KWMModuleApplication::connectToKWM). kwm only
  # ingests the region on that live message — it never re-reads the root
  # property at startup — so if the modules start before kwm is listening, the
  # reservation is lost forever and kwm/kfm fall back to the full-screen
  # default anchored at (0,0). That default silently masks a bottom panel but
  # puts window titlebars and desktop icons UNDER a top panel. Fix: bring kwm
  # up FIRST, wait until it publishes KWM_RUNNING on the root window, then
  # start the modules so their announcements are heard. Session lifetime tracks
  # kwm, exactly as upstream's 'exec kwm' did.
  kcontrol -init 2>/dev/null || true
  # Bring kwm up FIRST and supervise it. kwm's init-phase X error handler can
  # abort on a transient BadDrawable while building titlebar decorations
  # (patched to tolerate that in sanctuary-mide-build; this retry is
  # belt-and-braces and also catches any other transient init failure). Each
  # attempt clears any stale KWM_RUNNING (an aborted kwm can leave the property
  # behind), launches kwm, and accepts it only once KWM_RUNNING is present AND
  # kwm is still alive a second later (init aborts happen within ~1-2s).
  KWM_PID=
  kwm_attempt=1
  while [ \"\${kwm_attempt}\" -le 5 ]; do
    xprop -root -remove KWM_RUNNING 2>/dev/null || true
    kwm &
    KWM_PID=\$!
    if timeout 12 sh -c 'until xprop -root KWM_RUNNING 2>/dev/null | grep -q =; do sleep 0.2; done'; then
      sleep 1
      if kill -0 \"\${KWM_PID}\" 2>/dev/null && xprop -root KWM_RUNNING 2>/dev/null | grep -q =; then
        break
      fi
    fi
    echo \"sanctuary-mide: kwm failed to initialise (attempt \${kwm_attempt}/5), retrying…\" >&2
    kill \"\${KWM_PID}\" 2>/dev/null || true
    wait \"\${KWM_PID}\" 2>/dev/null || true
    KWM_PID=
    kwm_attempt=\$((kwm_attempt+1))
  done
  if [ -z \"\${KWM_PID}\" ]; then
    echo 'sanctuary-mide: kwm would not stay up after 5 attempts.' >&2
    exec xterm -title 'sanctuary-mide: kwm failed to start (see terminal output)'
  fi
  # Audio is unsupported upstream (no sound); best-effort, never fatal.
  kaudioserver 2>/dev/null || true
  kwmsound 2>/dev/null &
  kfm &
  krootwm &
  kpanel &
  kbgndwm &
  miwelcome &
  wait \"\${KWM_PID}\"
"

kill "${XEPHYR_PID}" 2>/dev/null || true
#+END_SRC
