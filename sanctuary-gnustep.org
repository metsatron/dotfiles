* Purpose

=sanctuary-gnustep= is the GNU/NeXT lineage room: Window Maker proving the NeXTSTEP grammar today, GNUstep restoring the OpenStep runtime underneath it, and — per the NEXTSPACE ruling (2026-07-03, =MetaCortex/Projects/Virtual-Habitat/Distrobox-Sanctuaries.md=) — [[https://github.com/trunkmaster/nextspace][NEXTSPACE]] as the direction of travel: "Window Maker proves the grammar; NEXTSPACE completes the sentence." The icon layer is non-negotiable: NeXTSTEP isometric icons, period-correct substitutions.

Like every sanctuary it rides the one-store-many-rooms Guix substrate from =sanctuary-distrobox.org=: base image =sanctuary-base:guix=, host =/gnu/store= read-only, a dedicated =sanctuary-gnustep= Guix profile (manifest in =package-guix-habitat.org=). Xephyr display is *=:91=*, host Desktop 3 (=Ctrl+F3=) — the full lineage: =:90= qtile, =:91= gnustep, =:92= cde, =:93= redstone-9x, =:94= godzilla-xs and retropie, =:95= mide, =:96= nscde.

The authenticity build-out is phased (plan sealed 2026-07-30):
- *Phase A — NeXT look* (this file, live): tangled Window Maker defaults with black focused titlebars and NeXT grays, =NewStyle = next= caption buttons, solid =#505170= workspace — the full-color NeXTSTEP/OPENSTEP default desktop background (Mètsàtron's ruling; the monochrome-era MegaPixel =#555555= is NOT the color-era value) — TeX Gyre Heros (Helvetica-metric) titles, a curated root menu, and a declarative right-edge dock carrying the Guix dockapp roster.
- *Phase B — GNUstep runtime*: source build in-guest (=gnustep-base/gui/back= are not in Guix; there is no apt in the sanctuary — ruled 2026-07-30), gnustep-make + libobjc2 from Guix, GWorkspace as the Workspace Manager. Follows the =sanctuary-nscde-build= sentinel pattern. Stage 0 also builds the dockapps Guix lacks (asclock — the canonical NeXT dock clock — wmmon, wmmemload, wmnet, wmmoonclock).
- *Phase C — NEXTSPACE alternative session* (research gate closed 2026-07-30, ruled 2026-07-31): NEXTSPACE's Workspace.app *embeds* a modified Window Maker in-process (wmaker's =main()= disabled via =#ifndef NEXTSPACE=, event loop on a libdispatch queue) — it can never run atop the stock wmaker session. So it arrives, if at all, as a *second session entry* where Workspace replaces wmaker (Login skipped — launchers exec sessions directly; =libudisks2= linkage satisfied from Guix with mounting degraded). Bounded experiment against a slowed upstream (0.95, June 2024); GWorkspace stays the primary session's Workspace Manager either way.
- *Phase D — icon layer*: =NeXT-Isometric= repo icon payload, gaps generated via the proven ChatGPT pixel-art workflow (Irixium precedent), wired into dock tiles, GWorkspace, and the host =.desktop=.

* Source build: sanctuary-gnustep-build

Phase B: the GNUstep runtime and GWorkspace, built from source inside the guest — =gnustep-base/gui/back= are not in Guix channels and the sanctuary has no apt (ruled 2026-07-30). Host-side driver following the =sanctuary-nscde-build= pattern: inner script heredoc through =sanctuary-exec=, sentinel-guarded stages, everything under the persistent guest home. Toolchain is *clang + libobjc2* from the Guix profile (=ng-gnu-gnu= library combo — Guix has no =gcc-objc=, so the GCC ObjC runtime is not an option). =gnustep-make= is built from source too (2.9.3) rather than taking Guix's 2.7.0 — base 1.31 wants the newer make, and one prefix-owned make keeps the whole chain coherent. Releases pinned 2026-08-01 from GitHub (=ftp.gnustep.org= was unreachable): make 2.9.3, base 1.31.1, gui 0.32.0, back 0.32.0, GWorkspace 1.0.0 — all published 2025-02. The asclock/wmmon dockapp stage is deferred until a verifiable upstream URL is pinned; it must never sit between the stages and the GWorkspace payload.

#+BEGIN_SRC bash :tangle linux/.local/bin/sanctuary-gnustep-build :shebang "#!/usr/bin/env bash"
# Build the GNUstep runtime + GWorkspace from source inside sanctuary-gnustep.
# Run once from the host: sanctuary-gnustep-build
# Sources: https://github.com/gnustep/{tools-make,libs-base,libs-gui,libs-back,apps-gworkspace}
set -euo pipefail

usage() {
  cat <<EOF
sanctuary-gnustep-build - build GNUstep (make/base/gui/back) + GWorkspace inside sanctuary-gnustep

Usage: sanctuary-gnustep-build
       sanctuary-gnustep-build -h | --help

No arguments. Clones pinned release tags from github.com/gnustep and installs
into ~/.local/share/gnustep inside the persistent guest home, using the Guix
profile's clang + libobjc2 (ng-gnu-gnu runtime). Idempotent: completed stages
are skipped via sentinel files.
EOF
}

if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
  usage
  exit 0
fi

if (( $# > 0 )); then
  usage >&2
  exit 1
fi

MAKE_TAG="make-2_9_3"
BASE_TAG="base-1_31_1"
GUI_TAG="gui-0_32_0"
BACK_TAG="back-0_32_0"
GWORKSPACE_TAG="gworkspace-1_0_0"
SANCTUARY="sanctuary-gnustep"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"

# Heredoc builds the inner script — outer-shell vars (tags, GUIX_PROFILES)
# expand at heredoc time; inner-shell vars are deferred via \$.
INNER_SCRIPT=$(cat <<INNER_EOF
set -eo pipefail

PREFIX=\${HOME}/.local/share/gnustep
SRC=\${HOME}/.local/share/gnustep-src

# Pre-declare vars the Guix profile scripts append to — they run under set -u
# semantics in some layers and must never hit an unbound variable.
export PKG_CONFIG_PATH="\${PKG_CONFIG_PATH:-}"
export LD_LIBRARY_PATH="\${LD_LIBRARY_PATH:-}"
export CPATH="\${CPATH:-}"
export LIBRARY_PATH="\${LIBRARY_PATH:-}"

GUIX_PROFILE=${GUIX_PROFILES}/desktop-common/desktop-common
. \${GUIX_PROFILE}/etc/profile
GUIX_PROFILE=${GUIX_PROFILES}/sanctuary-gnustep/sanctuary-gnustep
. \${GUIX_PROFILE}/etc/profile
export CURL_CA_BUNDLE=\${GIT_SSL_CAINFO}
export CC=clang CXX=clang++
# libobjc2 lives in the profile's lib/ which is on no default linker path —
# configure's "whether objc really works" probe RUNS its test binary, so both
# link-time and run-time search paths must see it explicitly.
GS_PROFILE_LIB=${GUIX_PROFILES}/sanctuary-gnustep/sanctuary-gnustep/lib
export LIBRARY_PATH="\${GS_PROFILE_LIB}:\${LIBRARY_PATH}"
export LD_LIBRARY_PATH="\${GS_PROFILE_LIB}:\${LD_LIBRARY_PATH}"
export LDFLAGS="-L\${GS_PROFILE_LIB} -Wl,-rpath,\${GS_PROFILE_LIB} -Wl,--copy-dt-needed-entries \${LDFLAGS:-}"
# clang 22 hard-errors on incompatible-pointer-types; base 1.31.1's own
# configure conftests (Feb 2025, pre-clang-22) trip it. Demote back to warning.
export CFLAGS="-g -O2 -Wno-error=incompatible-pointer-types"

mkdir -p "\${SRC}" "\${PREFIX}"
cd "\${SRC}"

clone_tag() {
  # clone_tag <repo> <tag> — shallow clone of one pinned release tag
  if [ ! -d "\$1" ]; then
    git clone --depth 1 --branch "\$2" "https://github.com/gnustep/\$1.git"
  fi
}

# ── Stage 1: gnustep-make ${MAKE_TAG} ────────────────────────────────────────
if [ ! -f "\${PREFIX}/.sentinel-${MAKE_TAG}" ]; then
  echo "Building gnustep-make (${MAKE_TAG})..."
  clone_tag tools-make ${MAKE_TAG}
  cd "\${SRC}/tools-make"
  ./configure --prefix="\${PREFIX}" --with-library-combo=ng-gnu-gnu
  make && make install
  touch "\${PREFIX}/.sentinel-${MAKE_TAG}"
  cd "\${SRC}"
else
  echo "gnustep-make ${MAKE_TAG} already installed (sentinel present)"
fi

# Everything downstream builds and runs inside the GNUstep environment.
. "\${PREFIX}/share/GNUstep/Makefiles/GNUstep.sh"

# ── Stage 2: gnustep-base ${BASE_TAG} ────────────────────────────────────────
if [ ! -f "\${PREFIX}/.sentinel-${BASE_TAG}" ]; then
  echo "Building gnustep-base (${BASE_TAG})..."
  clone_tag libs-base ${BASE_TAG}
  cd "\${SRC}/libs-base"
  ./configure
  make && make install
  touch "\${PREFIX}/.sentinel-${BASE_TAG}"
  cd "\${SRC}"
else
  echo "gnustep-base ${BASE_TAG} already installed (sentinel present)"
fi

# ── Stage 3: gnustep-gui ${GUI_TAG} ──────────────────────────────────────────
if [ ! -f "\${PREFIX}/.sentinel-${GUI_TAG}" ]; then
  echo "Building gnustep-gui (${GUI_TAG})..."
  clone_tag libs-gui ${GUI_TAG}
  cd "\${SRC}/libs-gui"
  ./configure
  make && make install
  touch "\${PREFIX}/.sentinel-${GUI_TAG}"
  cd "\${SRC}"
else
  echo "gnustep-gui ${GUI_TAG} already installed (sentinel present)"
fi

# ── Stage 4: gnustep-back ${BACK_TAG} (cairo) ────────────────────────────────
if [ ! -f "\${PREFIX}/.sentinel-${BACK_TAG}" ]; then
  echo "Building gnustep-back (${BACK_TAG})..."
  clone_tag libs-back ${BACK_TAG}
  cd "\${SRC}/libs-back"
  ./configure --enable-graphics=cairo
  make && make install
  touch "\${PREFIX}/.sentinel-${BACK_TAG}"
  cd "\${SRC}"
else
  echo "gnustep-back ${BACK_TAG} already installed (sentinel present)"
fi

# ── Stage 5: GWorkspace ${GWORKSPACE_TAG} — the Workspace Manager ────────────
if [ ! -f "\${PREFIX}/.sentinel-${GWORKSPACE_TAG}" ]; then
  echo "Building GWorkspace (${GWORKSPACE_TAG})..."
  clone_tag apps-gworkspace ${GWORKSPACE_TAG}
  cd "\${SRC}/apps-gworkspace"
  ./configure
  # The ObjC EH personality symbol lives in libobjc, which is only an INDIRECT
  # dependency (via libgnustep-base's DT_NEEDED) of GWorkspace's tools — bfd ld
  # refuses that by default ("DSO missing from command line"). LDFLAGS carries
  # -Wl,--copy-dt-needed-entries to allow it. Sentinel is the LAST link of the
  # success chain: a failed make can never forge it (a fall-through here did
  # exactly that once, 2026-07-30).
  make \
    && make install \
    && touch "\${PREFIX}/.sentinel-${GWORKSPACE_TAG}" \
    || { echo "GWorkspace stage failed" >&2; exit 1; }
  cd "\${SRC}"
else
  echo "GWorkspace ${GWORKSPACE_TAG} already installed (sentinel present)"
fi

GWS_BIN=\$(find "\${PREFIX}" -type f -name GWorkspace -path '*GWorkspace.app*' | head -1)
if [ -n "\${GWS_BIN}" ] && [ -x "\${GWS_BIN}" ]; then
  echo "GNUstep + GWorkspace installed under \${PREFIX}"
  echo "GWorkspace: \${GWS_BIN}"
  echo "Launch the room with: sanctuary-enter sanctuary-gnustep"
else
  echo "Build finished but no executable GWorkspace.app found under \${PREFIX} — inspect stage 5." >&2
  exit 1
fi
INNER_EOF
)
sanctuary-exec "${SANCTUARY}" sh -c "${INNER_SCRIPT}"
#+END_SRC

* Launcher: sanctuary-gnustep-launch

Moved here from =sanctuary-distrobox.org= (2026-07-30) and extended with the config projection preamble: the three Defaults files above are projected into the guest home every launch (=project_file= copies, redstone pattern — Window Maker rewrites Defaults at runtime, so these must be copies, never symlinks). Dock X is computed from the live Xephyr root once the display is up.

#+BEGIN_SRC bash :tangle linux/.local/bin/sanctuary-gnustep-launch :shebang "#!/usr/bin/env bash"
# Launch sanctuary-gnustep: Xephyr :91 + Window Maker inside the Guix container.
# Switch to Desktop 3 (Ctrl+F3) first.
set -euo pipefail

if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
  cat <<EOF
sanctuary-gnustep-launch - launch sanctuary-gnustep (Xephyr :91 + Window Maker, GNU/NeXT Sanctuary)

Usage: sanctuary-gnustep-launch

No arguments. Switch to host Desktop 3 (Ctrl+F3) before launching.
Normally invoked via: sanctuary-enter sanctuary-gnustep
EOF
  exit 0
fi

DISPLAY_NUM=":91"
HOST_DISPLAY="${DISPLAY}"
SANCTUARY="sanctuary-gnustep"
GUESTS_DIR="${XDG_DATA_HOME:-$HOME/.local/share}/dotcortex/guests"
GUEST_HOME="${GUESTS_DIR}/${SANCTUARY}/home"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"
DEFAULTS_SRC="${HOME}/DotCortex/linux/.config/gnustep-sanctuary/Defaults"

sanctuary-teardown-stale-session "${SANCTUARY}" "${DISPLAY_NUM}"

mapfile -t XEPHYR_GEOMETRY < <(sanctuary-xephyr-geometry)
Xephyr "${DISPLAY_NUM}" "${XEPHYR_GEOMETRY[@]}" -br -ac -no-host-grab &
XEPHYR_PID=$!
trap "kill ${XEPHYR_PID} 2>/dev/null || true" EXIT

timeout 10 sh -c "until DISPLAY=${DISPLAY_NUM} xdpyinfo >/dev/null 2>&1; do sleep 0.1; done" \
  || { echo "Xephyr ${DISPLAY_NUM} did not become ready"; kill "${XEPHYR_PID}"; exit 1; }

sanctuary-xephyr-place "${DISPLAY_NUM}" "${HOST_DISPLAY}" "${SANCTUARY}"

sanctuary-clip-bridge "${HOST_DISPLAY}" "${DISPLAY_NUM}" &
CLIP_BRIDGE_PID=$!
trap "kill ${XEPHYR_PID} ${CLIP_BRIDGE_PID} 2>/dev/null || true" EXIT

# ── Shield trash:/// from host fleet NFS mounts (see sanctuary-trash-shield) ──
sanctuary-trash-shield "${SANCTUARY}" "${HOME}"

# ── Project DotCortex-managed Window Maker config into the guest home ──
# Copies, not symlinks: Window Maker rewrites Defaults files at runtime, and a
# symlinked WMState would let the room dirty the repo checkout. Projection every
# launch is deliberate — the desktop is declarative, in-room rearrangements are
# ephemeral (ruled 2026-07-30).
project_file() {
  local src="$1" dst="$2"
  mkdir -p "$(dirname "${dst}")"
  rm -f "${dst}"
  cp -f "${src}" "${dst}"
}
project_file "${DEFAULTS_SRC}/WindowMaker" "${GUEST_HOME}/GNUstep/Defaults/WindowMaker"
project_file "${DEFAULTS_SRC}/WMRootMenu"  "${GUEST_HOME}/GNUstep/Defaults/WMRootMenu"

# Dock on the right edge at live room geometry: tiles are 64px, so x = width-64.
ROOM_WIDTH="$(DISPLAY=${DISPLAY_NUM} xdpyinfo | awk '/dimensions:/{split($2,a,"x"); print a[1]; exit}')"
DOCK_X=$(( ROOM_WIDTH - 64 ))
mkdir -p "${GUEST_HOME}/GNUstep/Defaults"
sed "s/@DOCK_X@/${DOCK_X}/" "${DEFAULTS_SRC}/WMState.template" \
  > "${GUEST_HOME}/GNUstep/Defaults/WMState"

echo "${SANCTUARY}: Xephyr ${DISPLAY_NUM} ready — sourcing Guix profiles and starting Window Maker…"
DISPLAY="${DISPLAY_NUM}" sanctuary-exec "${SANCTUARY}" sh -c "
  GUIX_PROFILE=${GUIX_PROFILES}/desktop-common/desktop-common
  . \${GUIX_PROFILE}/etc/profile
  GUIX_PROFILE=${GUIX_PROFILES}/sanctuary-gnustep/sanctuary-gnustep
  . \${GUIX_PROFILE}/etc/profile
  # GNUstep runtime (Phase B, sanctuary-gnustep-build). When built, source its
  # environment so the root menu and Tools resolve, and boot GWorkspace as the
  # Workspace Manager — NeXT starts in Workspace, not a bare WM.
  GS_ROOT=\${HOME}/.local/share/gnustep
  if [ -f \${GS_ROOT}/share/GNUstep/Makefiles/GNUstep.sh ]; then
    . \${GS_ROOT}/share/GNUstep/Makefiles/GNUstep.sh
    GWS_BIN=\$(find \${GS_ROOT} -type f -name GWorkspace -path '*GWorkspace.app*' | head -1)
    if [ -n \"\${GWS_BIN}\" ] && [ -x \"\${GWS_BIN}\" ]; then
      ( sleep 2 && exec \"\${GWS_BIN}\" ) &
    fi
  fi
  exec wmaker
"

kill "${XEPHYR_PID}" 2>/dev/null || true
#+END_SRC
