#+TITLE: Rofi Launcher and Menus
#+PROPERTY: header-args :mkdirp yes :results silent

* Purpose

This file declares the shared Rofi launcher, theme, and small helper scripts for DotCortex so application launching, quick actions, emoji insertion, and clipboard recall stay declarative and can be tangled into the Linux overlay without mixing in keybindings or mutable runtime state.

* Rofi Config

This file is the single switch point for the whole suite: one =@import= line selects the active theme, and every keybind (=drun=, =window=, the =-dmenu= action menu, emoji, clipboard) inherits it because =config.rasi= is read on every invocation. Overrides placed *after* the import win — verified on this machine, not assumed — which is why =modi= is restored here: upstream's =style-1= declares =drun,run,filebrowser= and would otherwise drop the =window= tab that =Super+w= relies on. (=rofi -show window= works regardless, since built-in modes are always reachable via =-show=; only the mode-switcher tabs are affected.)

Icons stay off, as upstream's =style-1= intends — that spare two-column text grid *is* the style. Add =show-icons: true;= to the override block below to bring them back. The LainCore theme remains on disk; swapping the import line for =@theme "laincore"= reverts to it.

Navigation stays on rofi's default arrow keys. Bare =h/j/k/l= are deliberately not bound: they collide with type-to-filter and violate the Colemak-NEIO law. A future pass could consider =kb-row-up: "Up,Control+i"= and =kb-row-down: "Down,Control+e"=, but only after checking =rofi -dump-config= for Control+i/e default collisions, so v1 leaves that disabled.

#+BEGIN_SRC css :tangle all/.config/rofi/config.rasi :tangle-mode (identity #o644)
@import "launchers/type-1/style-1.rasi"

configuration {
    modi: "drun,run,window";
}
#+END_SRC

* adi1090x Theme — type-1 / style-1

Vendored from [[https://github.com/adi1090x/rofi][adi1090x/rofi]] (GPL-3.0, Aditya Shakya). The upstream author headers are preserved verbatim, as the licence requires. Lineage is clean for a public repo: a single-author theme collection, GPL-3.0, no Contributor Covenant, no foundation or corporate control.

Only =type-1/style-1= and the =onedark= palette are carried here. Upstream ships seven types × fifteen styles and sixteen palettes; each additional one is a further block, not a new mechanism.

Verified against the Guix =rofi 2.0.0= on this machine — upstream targets rofi 1.7.3, but =-dump-theme= parses it with a zero exit and no warnings, and the palette resolves through the two-hop import chain (=style-1.rasi= → =shared/colors.rasi= → =colors/onedark.rasi=). The font upstream requests, ="JetBrains Mono Nerd Font"=, is spelled with a space that matches no installed family, yet fontconfig still resolves it to the installed =JetBrainsMono Nerd Font=; that was control-tested (a deliberately bogus family falls back to Noto Sans instead), so the name is left verbatim rather than "fixed".

One org-specific escape: rasi's global selector =* {= sits at column zero, where org-mode reads it as a headline and silently skips the rest of the block. Each occurrence is written =,* {= in this source; org strips the comma on tangle, so the emitted =.rasi= is byte-faithful to upstream.

* Rofi Launch Wrapper

This wrapper composes `XDG_DATA_DIRS` before calling `rofi-core` so `drun` can still see user, system, and Flatpak desktop entries even when the Guix profile environment would otherwise narrow discovery too aggressively.

#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-launch :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
# Source the Guix core profile FIRST (before set -u): it puts rofi on PATH and its
# own reference to an unset GIO_EXTRA_MODULES would abort under nounset. This is why
# we call bare `rofi` here rather than rofi-core (which sources under its own set -u
# and dies in a session that never exported GIO_EXTRA_MODULES — the Super+space bug).
P="$HOME/.guix-extra-profiles/core/core"; [ -r "$P/etc/profile" ] && . "$P/etc/profile"
set -euo pipefail
compose() { case ":${XDG_DATA_DIRS:-}:" in *":$1:"*) ;; *) XDG_DATA_DIRS="${XDG_DATA_DIRS:+$XDG_DATA_DIRS:}$1";; esac; }
compose "$HOME/.local/share"; compose /usr/local/share; compose /usr/share
compose "$HOME/.local/share/flatpak/exports/share"; compose /var/lib/flatpak/exports/share
export XDG_DATA_DIRS
exec rofi -show drun "$@"
#+END_SRC

* Window Switcher

Binds =Super+w= to Rofi's built-in =window= modi — a fuzzy switcher across all open windows. Sources the Guix core profile first (bare =rofi=, same robust source-before-`set -u` pattern as the launcher), and needs no XDG_DATA_DIRS compose since it enumerates live windows rather than desktop entries. Picks up the shared LainCore theme from =config.rasi= automatically.

#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-window :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
P="$HOME/.guix-extra-profiles/core/core"; [ -r "$P/etc/profile" ] && . "$P/etc/profile"
set -euo pipefail
exec rofi -show window "$@"
#+END_SRC

* Run Dialog

Binds =Super+r= to Rofi's built-in =run= modi — bare =$PATH= executables, as distinct from =Super+space='s =drun=, which lists =.desktop= entries. Same source-before-=set -u= pattern as the other wrappers.

=Super+r= is not a free key: XFCE ships it as a *default* shortcut at =/commands/default/<Super>r= bound to =xfce4-appfinder -c= (the appfinder's collapsed run dialog). A =/commands/custom/= entry on the same key takes precedence over the default, so the sanctuary shortcut script simply writes the custom entry and the XFCE default is shadowed without needing removal.

Because this wrapper does not compose =XDG_DATA_DIRS= (=run= scans =$PATH=, not desktop entries), executables live wherever the Guix core profile puts them.

#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-run :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
P="$HOME/.guix-extra-profiles/core/core"; [ -r "$P/etc/profile" ] && . "$P/etc/profile"
set -euo pipefail
exec rofi -show run "$@"
#+END_SRC

* Custom Action Menu

This menu provides a plain-text control panel for common desktop actions, duplicates the Sanctuary workspace jumps already available on Super+2/3/4 for discoverability, and routes power/session commands through `xfce4-session-logout` where possible so accidental one-keystroke shutdowns are avoided even though some backend behavior on Devuan remains best-effort and refinable later.

Unlike the other wrappers this one calls =rofi-core= (from =guix.org=) rather than bare =rofi=, because it needs the profile on PATH for =wmctrl= and the =xfce4-*= helpers too. That wrapper used to run =set -euo pipefail= *before* sourcing the Guix profile, and the profile dereferences an unset =GIO_EXTRA_MODULES=, so under =nounset= it aborted with =unbound variable= before ever reaching rofi — which is exactly why =Super+x= did nothing while the source-first wrappers worked. =rofi-core= now sources the profile first, so this menu opens.

#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-actions :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
set -euo pipefail
ROFI="$HOME/.local/bin/rofi-core"
declare -A ACT=(
  ["Lock screen"]="xflock4"
  ["Screenshot"]="xfce4-screenshooter"
  ["Display settings"]="xfce4-display-settings"
  ["Task manager"]="xfce4-taskmanager"
  ["App finder"]="xfce4-appfinder"
  ["Emoji picker"]="$HOME/.local/bin/rofi-emoji-menu"
  ["Clipboard history"]="$HOME/.local/bin/clipmenu-rofi"
  ["Sanctuary: Qtile (WS2)"]="wmctrl -s 1"
  ["Sanctuary: GNUstep (WS3)"]="wmctrl -s 2"
  ["Sanctuary: CDE (WS4)"]="wmctrl -s 3"
  ["Suspend"]="xfce4-session-logout --suspend"
  ["Power / session…"]="xfce4-session-logout"
)
ORDER=("Lock screen" "Screenshot" "Display settings" "Task manager" "App finder" "Emoji picker" "Clipboard history" "Sanctuary: Qtile (WS2)" "Sanctuary: GNUstep (WS3)" "Sanctuary: CDE (WS4)" "Suspend" "Power / session…")
choice="$(printf '%s\n' "${ORDER[@]}" | "$ROFI" -dmenu -i -p actions)"
[ -n "${choice:-}" ] || exit 0
cmd="${ACT[$choice]:-}"
[ -n "$cmd" ] || exit 0
setsid -f sh -c "$cmd" >/dev/null 2>&1 || eval "$cmd" &
#+END_SRC

* Clipmenu Daemon Launcher

The autostart entry points here rather than at =clipmenud= directly, so the daemon reliably finds =clipmenud=, =xsel=, and =clipnotify= on PATH regardless of the graphical session's environment. It sources the Guix core profile first — exactly like the other Rofi mode wrappers — then execs the daemon. Without this, a graphical-login shell that never sourced the Guix profile would leave =clipmenud= unfound and the clipboard picker permanently empty.

#+BEGIN_SRC bash :tangle linux/.local/bin/clipmenud-start :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
P="$HOME/.guix-extra-profiles/core/core"; [ -r "$P/etc/profile" ] && . "$P/etc/profile"
set -euo pipefail
exec clipmenud
#+END_SRC

* Clipmenu Daemon Autostart

This autostart entry ensures the clipboard history daemon is present in graphical sessions so the Rofi clipboard picker has data to show. It launches =clipmenud-start= by bare name, which self-sources the Guix core profile before starting the daemon.

A correction, recorded because it cost a debugging session: an earlier revision of this prose asserted that the bare name "resolves from =~/.local/bin= on the session PATH". That was false. =xfce4-session= launches XDG autostart entries with the PATH inherited from Xsession, which never contained =~/.local/bin= — so this entry died silently at every login and the clipboard was permanently empty, while running =clipmenud-start= by hand always worked (an interactive shell *does* have =~/.local/bin= on PATH). The lesson generalises: where a name resolves in your shell says nothing about where it resolves for a GUI-launched process.

There are two independent fixes and both are kept. One layer down, =x11.org='s =.xsessionrc.d/40-local-bin.sh= puts =~/.local/bin= on the session PATH for every autostart entry (=clipmenud-start=, =xfce-sanctuary-shortcuts=, =appmenu-boot-setup=, =plank=, =twistpatch= — all were affected, all silently). Here, the =Exec== names the script by absolute path so it does not consult PATH at all.

Belt and braces is deliberate. The PATH snippet only takes effect if =~/.xsessionrc= is sourced, which is a property of the display manager, not of this repo; a login path that skips it must not silently disable the clipboard again. An autostart entry should not depend on PATH to find a file whose location it already knows.

#+BEGIN_SRC conf :tangle linux/.config/autostart/clipmenud.desktop :tangle-mode (identity #o644) :comments no
[Desktop Entry]
Type=Application
Name=clipmenud
Comment=Clipboard history daemon for rofi clipboard picker
Exec=sh -c 'exec "$HOME/.local/bin/clipmenud-start"'
Terminal=false
X-GNOME-Autostart-enabled=true
#+END_SRC
