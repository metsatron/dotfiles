* What this is

The 1994 single-floppy =Best of Microsoft Entertainment Pack= — thirteen Windows 3.x games — installed into the Redstone 9X Wine prefix and given a proper home in the Start menu's Wine → Games branch, wearing the icons pulled straight out of the 1994 binaries.

Everything here is genuine Win16: every executable is an NE (New Executable) targeting *Windows 3.00, protected mode*. That matters more than it sounds, because it decides whether any of this can run at all.

** Why this works — the WoW64 question

16-bit code needs real 16-bit segments, and those only exist inside a 32-bit host address space. Wine's *new* WoW64 mode (a 64-bit build with no 32-bit Unix libraries) therefore cannot run Win16 at all, no matter how the prefix is configured. This is the single fact that decides the whole feature, so it was measured rather than assumed.

Guix's =wine64= 11.0 is built multiarch — the old-style WoW64 — which is why the pack runs:

- =lib/wine/i386-unix/ntdll.so= is a genuine *ELF 32-bit i386* shared object, alongside 843 other 32-bit host libraries
- =lib/wine/i386-windows/= carries 50 real 16-bit modules, including =krnl386.exe16=, =user.exe16=, =gdi.exe16=, =win87em.dll16= and =sound.drv16=
- the games are hosted by =winevdm.exe=, Wine's 16-bit virtual DOS machine

A =win64= prefix is fine — verified, not assumed. The existing Redstone prefix (=#arch=win64=) runs these unmodified, so no separate 32-bit prefix is needed.

** Verified state (2026-07-27, host T480s, isolated =Xvfb :97=)

Twelve of the thirteen run and render correctly. Each was launched headlessly, polled until its own window mapped, and screenshotted — window titles and pixels both checked, not just a zero exit code.

** Disk provenance

Internet Archive item =wep_best-of= (=floppysoftware= / =vintagesoftware=), a 1.44 MB MFM sector image of the 1994 single-floppy release, uploaded 2025-02-16 and malware-checked by the IA curator. The image is *not* vendored into DotCortex — these are copyrighted Microsoft binaries and this repo is public. Provisioning reads a local image the operator supplies, exactly as =redstone-9x-font-provision= reads locally-staged Microsoft fonts.

** Original install layout, recovered from the disk

The setup script (=BOWEP.MST=, a Microsoft Setup Toolkit MST) and =SETUP.INF= give the authentic layout, which the provisioner reproduces:

- games, help files, sounds and data → =DEST$=, defaulting to =C:\BOWEP=
- =weputil.dll= and =vbrun100.dll= → the Windows directory (the =[Windows Files]= section)
- a Program Manager group named "Best of Entertainment" holding thirteen items

The menu labels in this module are Microsoft's own strings, lifted verbatim from the =CreateProgmanItem= calls — including =Free Cell= as two words. The installer's own window title, for the record, reads "Best of Microsoft Entertainmnet Pack"; the typo shipped.

The original 16-bit =SETUP.EXE= is deliberately *not* used. It is an interactive Setup Toolkit GUI that wants dialog clicks and writes Program Manager groups no one here reads, and driving it headlessly would be far more fragile than reproducing its declared file layout. The provisioner does what the INF says instead, which is inspectable, idempotent, and needs no GUI.

* Provisioner — redstone-9x-wep-provision

Runs on the *host*, not in the guest: every path it touches is a host path (the guest home and its Wine prefix both live under =~/.local/share/dotcortex/guests/=), and the guest's =python3= is a broken shim while the host's is real. Nothing here needs the container to be running.

Dependency-free by construction. The embedded Python reads the FAT12 image and expands the SZDD compression itself rather than shelling out to =mtools= and =msexpand=, neither of which is declared anywhere in DotCortex. The only external tools are =wrestool=/=icotool= from =icoutils= in the =room-windows-compat= profile, and those are used *only* for icons — if they are missing the games still install and the menu falls back to the generic Wine icon.

Idempotent: a completion marker short-circuits repeat runs. =--force= redoes everything.

** Where the icons have to go, and where they emphatically do not

Two different consumers resolve these names, and *neither* reads a flat PNG dropped in =~/.local/share/icons= — the first cut of this provisioner did exactly that and produced a menu with thirteen blank entries.

- *IceWM* (the Start menu) cannot resolve XDG icon-theme names at all. It reads its own flat directory, =~/.icewm/icons/=, with an explicit size suffix: =wep-tetris_24x24.png=. This is the same constraint =redstone-9x-icons-graft= exists to work around for theme icons, documented in =sanctuary-redstone-9x.org=; it applies identically to icons that come from anywhere else. Note IceWM draws *no fallback* — an unresolved name in the toolbar drops the button entirely, so the symptom looks like a missing entry rather than a missing icon.
- *GTK / PCManFM* (the Program Manager folder, whose =.desktop= files carry =Icon=wep-tetris=) uses real XDG lookup, which needs a genuine theme layout: =~/.local/share/icons/hicolor/<size>x<size>/apps/wep-tetris.png=. =hicolor= is the always-searched fallback theme, so it needs no scheme awareness.

So each icon is written twice, at 16/22/24/32/48. The live menu draws at =MenuIconSize=24=, which is the size to judge legibility at — not 32, and not whatever looks nice enlarged.

Scaling is nearest-neighbour. The sources are 32x32 16-colour pixel art, and any smoothing filter turns them to mush at exactly the sizes that matter. The 16px variant is a clean 2:1 reduction; 22 and 24 are not integer ratios and will alias slightly, which is still far more legible than a blurred downscale.

These icons are never vendored. They are Microsoft's art, extracted from Microsoft's binaries, into a guest directory that is not part of the public repo — =icon-theme-inject= must not be used for them, because it writes into the icon-theme git submodules.

"""Read a FAT12 floppy image and expand its SZDD-compressed members.

Deliberately dependency-free: mtools and msexpand are not declared anywhere in
DotCortex, and this must work on any machine that can run the sanctuary. Both
formats are simple and fully specified, so implementing them is cheaper and more
portable than adding two packages.
"""
import os
import struct
import sys

img_path, out_dir = sys.argv[1], sys.argv[2]
data = open(img_path, "rb").read()

# --- FAT12 -----------------------------------------------------------------
bps = struct.unpack_from("<H", data, 0x0B)[0]      # bytes per sector
spc = data[0x0D]                                   # sectors per cluster
reserved = struct.unpack_from("<H", data, 0x0E)[0]
nfats = data[0x10]
root_entries = struct.unpack_from("<H", data, 0x11)[0]
spf = struct.unpack_from("<H", data, 0x16)[0]      # sectors per FAT

fat_start = reserved * bps
root_start = fat_start + nfats * spf * bps
root_bytes = root_entries * 32
data_start = root_start + root_bytes
fat = data[fat_start:fat_start + spf * bps]


def fat_entry(cluster):
    off = cluster + (cluster // 2)
    val = struct.unpack_from("<H", fat, off)[0]
    return val & 0x0FFF if cluster % 2 == 0 else val >> 4


def read_chain(first, size):
    out = bytearray()
    cluster = first
    while 2 <= cluster < 0xFF0 and len(out) < size:
        off = data_start + (cluster - 2) * spc * bps
        out += data[off:off + spc * bps]
        cluster = fat_entry(cluster)
    return bytes(out[:size])


def root_files():
    for i in range(root_entries):
        e = data[root_start + i * 32:root_start + i * 32 + 32]
        if e[0] in (0x00,):
            break
        if e[0] == 0xE5:                 # deleted
            continue
        attr = e[0x0B]
        if attr & 0x08 or attr & 0x10:   # volume label / directory
            continue
        if attr & 0x02:                  # hidden
            continue
        name = e[0:8].decode("ascii", "replace").rstrip()
        ext = e[8:11].decode("ascii", "replace").rstrip()
        first = struct.unpack_from("<H", e, 0x1A)[0]
        size = struct.unpack_from("<I", e, 0x1C)[0]
        yield (f"{name}.{ext}" if ext else name), read_chain(first, size)


# --- SZDD ------------------------------------------------------------------
MAGIC = b"SZDD\x88\xf0\x27\x33"
# The archived disk stores 0x00 as the "missing character", so the final letter
# of each extension is recovered by convention instead of from the header.
EXT_MAP = {
    ".EX_": "E", ".DL_": "L", ".HL_": "P", ".WA_": "V", ".MI_": "D",
    ".DA_": "T", ".VB_": "X", ".IN_": "F", ".MS_": "T",
}


def szdd_expand(blob):
    if blob[8:9] != b"A":
        raise ValueError(f"unsupported SZDD mode {blob[8:9]!r}")
    size = struct.unpack_from("<I", blob, 10)[0]
    window = bytearray(b"\x20" * 4096)
    pos = 4096 - 16
    out = bytearray()
    i, end = 14, len(blob)
    while i < end and len(out) < size:
        control = blob[i]
        i += 1
        for bit in range(8):
            if i >= end or len(out) >= size:
                break
            if control & (1 << bit):
                b = blob[i]
                i += 1
                out.append(b)
                window[pos] = b
                pos = (pos + 1) & 0xFFF
            else:
                if i + 1 >= end:
                    break
                lo, hi = blob[i], blob[i + 1]
                i += 2
                match = lo | ((hi & 0xF0) << 4)
                for _ in range((hi & 0x0F) + 3):
                    if len(out) >= size:
                        break
                    b = window[match]
                    match = (match + 1) & 0xFFF
                    out.append(b)
                    window[pos] = b
                    pos = (pos + 1) & 0xFFF
    if len(out) != size:
        raise ValueError(f"short expand: {len(out)} of {size}")
    return bytes(out)


def target_name(name):
    stem, ext = os.path.splitext(name)
    if len(ext) == 4 and ext.endswith("_"):
        tail = EXT_MAP.get(ext.upper())
        if tail is None:
            raise ValueError(f"no extension mapping for {ext} ({name})")
        return stem + ext[:-1] + tail
    return name


os.makedirs(out_dir, exist_ok=True)
expanded = copied = 0
for name, blob in root_files():
    if blob[:8] == MAGIC:
        blob = szdd_expand(blob)
        name = target_name(name)
        expanded += 1
    else:
        copied += 1
    with open(os.path.join(out_dir, name), "wb") as f:
        f.write(blob)
print(f"redstone-9x-wep: expanded {expanded}, copied {copied}")
PYWEP

SRC="${STAGE}/expanded"

import sys

src = sys.argv[1]
games = ["TETRIS", "FREECELL", "PIPE", "CHIPS", "TP", "TUTSTOMB", "RODENT",

bad = []
for g in games:

    try:
        d = open(p, "rb").read()
        ne = struct.unpack_from("<I", d, 0x3C)[0]
        if d[ne:ne + 2] != b"NE":
            bad.append(f"{g}: not an NE binary")
    except Exception as exc:
        bad.append(f"{g}: {exc}")
if bad:

print(f"redstone-9x-wep: {len(games)} NE binaries verified")

    # exactly one survived the loop.
    rm -rf "${TMPICO:?}/work"

    # -t 14 is RT_GROUP_ICON. wrestool names its output <exe>_14_<id>.ico, and
    # some of these carry several groups (ids 1, 100, 256); the lowest-numbered
    # one is the application icon.
    "${WRESTOOL}" -x -t 14 -o "${TMPICO}/work" "${DEST}/${exe}.EXE" 2>/dev/null || true

    png="$(find "${TMPICO}/work/out" -type f -name '*.png' \

  # Fan the 32x32 originals out to every size IceWM and GTK actually look for.
  # Nearest-neighbour: this is 16-colour pixel art and any smooth filter turns it

import sys

staged, icewm_dir, hicolor = sys.argv[1], sys.argv[2], sys.argv[3]

    if not name.endswith(".png"):
        continue
    stem = name[:-4]
    src = Image.open(os.path.join(staged, name)).convert("RGBA")
    for size in sizes:
        img = src if src.size == (size, size) else src.resize((size, size), Image.NEAREST)

        apps = os.path.join(hicolor, f"{size}x{size}", "apps")
        os.makedirs(apps, exist_ok=True)
        img.save(os.path.join(apps, f"{stem}.png"))
        written += 1
print(f"redstone-9x-wep: {written} icon files across {len(sizes)} sizes")

  # Retire the flat ~/.local/share/icons/wep-*.png drop from the first cut: it is
  # not a layout either consumer resolves, and leaving it invites the same wrong
  # conclusion next time.
  rm -f "${ICONDIR}"/wep-*.png

  echo "redstone-9x-wep: ${n} icons -> ${ICEWM_ICONS} and ${HICOLOR}"
else

  echo "  need icoutils in room-windows-compat (make guix-room-windows-compat) and a python3 with Pillow"

echo "  Launch one with: redstone-9x-wep tetris"

* Launcher — redstone-9x-wep

Takes a slug, runs the matching binary. Sources the same Guix profiles and Wine environment as the other Redstone Wine wrappers, and runs from =C:\BOWEP= so each game finds its help file, sounds and data alongside it.

=DISPLAY= defaults to =:93= exactly as the sibling wrappers do — correct in the room, and the reason no test may ever invoke this without setting =DISPLAY= explicitly.

*The shebang must be =#!/bin/bash=, never =#!/usr/bin/env bash=.* The sanctuary guest has no =/usr/bin/env= at all — it is a Guix-populated container where =/bin/bash= is a store symlink and the =/usr/bin= coreutils shims were never created. An =env= shebang therefore fails at =exec= time with =ENOENT=, which IceWM reports as *"Failed to execute …: No such file or directory"* — naming the launcher, so it reads as a missing file rather than a missing interpreter, and sends you looking at the symlink. Every other =redstone-9x-*= wrapper already uses =#!/bin/bash= for exactly this reason.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-wep :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -euo pipefail

GUESTS_DIR="${XDG_DATA_HOME:-$HOME/.local/share}/dotcortex/guests"
GUEST_HOME="${GUESTS_DIR}/${SANCTUARY}/home"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"

export WINEPREFIX="${WINEPREFIX:-${GUEST_HOME}/.wine-redstone}"
BOWEP="${WINEPREFIX}/drive_c/BOWEP"

source_guix_profile() {
  local profile="$1" status=0 had_nounset=0
  case $- in *u*) had_nounset=1; set +u ;; esac
  GUIX_PROFILE="$profile"; export GUIX_PROFILE
  . "$profile/etc/profile" || status=$?
  (( had_nounset )) && set -u
  return "$status"
}

for _prof in desktop-common room-gaming room-windows-compat; do
  source_guix_profile "${GUIX_PROFILES}/${_prof}/${_prof}"
done

export DISPLAY="${DISPLAY:-:93}"
export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"
export WINEDEBUG="${WINEDEBUG:--all}"

case "${1:-}" in
  tetris)   EXE=TETRIS.EXE ;;
  freecell) EXE=FREECELL.EXE ;;
  pipe)     EXE=PIPE.EXE ;;
  chips)    EXE=CHIPS.EXE ;;
  taipei)   EXE=TP.EXE ;;
  tutstomb) EXE=TUTSTOMB.EXE ;;
  rodent)   EXE=RODENT.EXE ;;
  tripeaks) EXE=TRIPEAKS.EXE ;;
  golf)     EXE=GOLF.EXE ;;
  ski)      EXE=SKI.EXE ;;
  jezzball) EXE=JEZZBALL.EXE ;;
  blakjak)  EXE=BLAKJAK.EXE ;;
  tetravex) EXE=TETRAVEX.EXE ;;
  ""|-h|--help)
    echo "usage: redstone-9x-wep <game>"
    echo "  tetris freecell pipe chips taipei tutstomb rodent"
    echo "  tripeaks golf ski jezzball blakjak tetravex"
    exit 0 ;;
  *)
    echo "redstone-9x-wep: unknown game '${1}'" >&2
