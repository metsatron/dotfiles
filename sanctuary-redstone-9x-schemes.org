#+AUTHOR: Mètsàtron

Full-layer theme switching for the Redstone 9X sanctuary. Split out of =sanctuary-redstone-9x-desktop.org= on 2026-07-19 (module budget) — the scheme declarations and the apply/graft/host-gtk helpers live here; the theme builders, converters, and the SerenityOS asset importer moved to =sanctuary-redstone-9x-scheme-builders.org= on 2026-07-20 (module budget); the menu entries, IceWM startup hook, and GTK/qt6ct base configs they act on remain in the desktop module.

* Desktop Schemes — full-layer theme switching

A *Desktop Scheme* swaps every appearance layer at once: IceWM theme, GTK2/GTK3 theme, icon theme, cursor theme, fonts, desktop background, selection colours, Qt palette, and sound scheme. Before this existed (2026-07-19 audit) the Windows 95 look was smeared across nine uncoordinated mechanisms — a session-frozen =GTK_THEME= export, five absolute Chicago95 paths in the menu, a launcher-time icon graft, projected GTK/Qt files, and a dead =gtk-cursor-theme-name=Win95= reference. A scheme is one declarative file; =redstone-9x-scheme-apply= is the single mover.

Mechanism per layer:
- *IceWM*: writes =~/.icewm/theme= and restarts the WM. The curated Win2k IceWM themes remain reachable as "window borders only" variants that do not change the rest of the scheme.
- *GTK (new apps)*: rewrites =settings.ini= / =.gtkrc-2.0=. The session-wide =GTK_THEME= export is gone — it overrides both settings.ini and XSETTINGS, which would make switching impossible. Host-spawned browsers get their =GTK_THEME= from =redstone-9x-host-gtk=, which reads the *active* scheme at click time.
- *GTK (running apps)*: =xsettingsd= (desktop-common) is started by the IceWM startup hook; scheme-apply rewrites its config and SIGHUPs it, so already-running GTK3 apps restyle live.
- *Icons*: IceWM does not resolve XDG icon-theme names (a name it can't find silently drops the whole menu button), so the launcher grafts a curated set into =~/.icewm/icons/= — the graft is now scheme-aware via =redstone-9x-icons-graft=, sourcing from the scheme's icon theme with Chicago95 fallback.
- *Sounds*: =~/.local/share/sounds/sanctuary= becomes a symlink to =~/.local/share/sounds/schemes/<scheme>/= (the flat dir from the first sound landing migrates automatically).
- *Persistence*: the choice lands in =~/.config/redstone-9x/scheme=; the launcher re-asserts the active scheme after every projection pass (=--boot= mode, file effects only), so projection no longer resets appearance to Windows 95.

** CDE dynasty schemes

The nIceCDE family (Stéphane Lassalvy, LGPL-3, based on Alexander Voigt's FMotif IceWM theme) recreates the Common Desktop Environment's 1990s-2000s HP-UX/Solaris workstation look. Five native IceWM themes are already vendored at =linux/.icewm/themes/nIceCDE.{Default,Green,Mustard,Sandy,Crimson}/= with their own tiled CDE backdrop patterns under =backgrounds/*.xpm=. Unlike the Windows dynasty these themes carry no flat =ColorActiveTitleBar= key — the titlebar is painted from a pixmap (=titleAM.xpm=), so titlebar/backdrop tones below were sampled from the actual pixmaps (Pillow dominant-colour pass over =titleAM.xpm= and each theme's named backdrop), not invented; menu/button/selection tones came straight from each theme's =Color*= keys.

GTK theme is the plain =cdetheme= (not =cdetheme1.3=/=cdetheme1.4=, which ship only a =cdepanel= PyInstaller build with no =gtk-3.0= dir at all; not =cdetheme-solaris=, whose =gtk-3.0/= is byte-for-byte the same widget set as =cdetheme='s — verified by directory diff, so the plain name is the natural pick with no functional loss). Qt goes through Kvantum instead of qt6ct's built-in Windows style (=QT_STYLE="kvantum"=) — CDE's Motif look has no equivalent in Qt6's stock styles, but Kvantum's =Commonality= family (pulled from T480, itself CDE-derived) does. =Commonality='s neutral tan base (=window.color=#c6b3a9=) suits Green/Mustard/Sandy; =commonalitygris= (grey base =#56585a=) was chosen for Default over the tan default because Default's own palette is already warm brown/orange (Paver backdrop, =#eda870= accent) and the grey base keeps widget chrome from fighting the backdrop; =commonalitysienna= (terracotta base =#c37b6a=, brick =highlight.color=#6d443c=) was chosen for Crimson because its magenta/red accent (=#b24d7a=/=#b54a7b=) sits on the same warm-red wheel as sienna's brick highlight — confirmed by reading each variant's =.kvconfig= =window.color=/=highlight.color= keys, not guessed from the name.

*** BeOS tab dynasty (icedano fork)

The Be lineage's flat titlebars never read as true BeOS *tabs* — IceWM painted the whole caption as one solid fill. Tverdov's =icedano= (J.S., 2005; a "Beish" =Look=metal= theme) is the one that pulls off the real illusion: a discrete tab hugging the title text and buttons at top-left, then a thin strip running to the window edge. We fork it and correct its two flaws — the wrong caption glyphs (a bare X, an eject shape, and a double-square for maximise) and a navy accent bar that continues past the tab. The fork (=redstone-9x-icewm-derive --warm= plus a documented button graft) yields three vendored theme dirs under =linux/.icewm/themes/=:

- =icedano= — the untouched upstream fork, kept for reference (menu entry "icedano (raw)"). Its own slate desktop =#748093= and flat =#e7e7e7= panel are preserved so the donor is visible as it shipped.
- =BeOS-Max-Tab= — the merged base: icedano's yellow tab, the navy accent neutralised to the frame grey (=#B8BCF3/#7479B9/#5B5E8D= → =#BDBDBD/#9C9C9C/#4A4A4A=, matching icedano's own inactive strip), the grafted BeOS-r5 caption buttons (2-frame, 25px, correct glyphs), =TitleBarHeight=25= with =TitleButtonsLeft="xmi"=, and the fleet's grey BeOS Deskbar panel (=taskbar/= grafted from =BeOS-Personal=). Verified in a headless IceWM render, wide and narrow.
- =BeOS-Personal-Tab= — the terracotta colourway, generated from =BeOS-Max-Tab= by =redstone-9x-icewm-derive … '#6b3c28' '#efc6ad' --warm=. The warm ramp recolours tab AND buttons together (one family), leaving the neutral bevels, black outlines, and grey strip byte-identical — so Personal's rare non-yellow tab lines up automatically. Future Haiku/BeOS colourways are one dark/light pair away.

The new schemes take over the plain "BeOS Personal" / "BeOS Max" names; the earlier flat-fill schemes are retitled "BeOS Inspired Personal" / "BeOS Inspired Max" and kept. Every non-chrome layer (GTK, Qt, icons, cursor, sound, desktop colour) is inherited unchanged from the matching Inspired scheme — the only difference is the tab titlebar.

** Desktop icon-label typography

Desktop schemes declare PCManFM's normal icon-label treatment alongside the
desktop foreground and background colours.  =DESKTOP_ICON_LABEL_MODE= accepts
exactly =shadow=, =box=, or =plain=:

- =shadow= paints one crisp glyph shadow at the configured integer offset,
  followed by one foreground pass.  PCManFM suppresses the shadow when the
  resolved foreground is dark, so a dark label never receives a dark halo.
- =box= paints one opaque, square-cornered rectangle around the complete Pango
  layout using =DESKTOP_ICON_LABEL_BACKGROUND= and the configured X/Y padding,
  followed by the foreground glyphs.  The rectangle follows wrapped labels
  rather than filling the icon cell.
- =plain= paints foreground glyphs only.

The remaining declarative keys are
=DESKTOP_ICON_LABEL_FOREGROUND=, =DESKTOP_ICON_LABEL_BACKGROUND=,
=DESKTOP_ICON_LABEL_SHADOW_COLOR=, =DESKTOP_ICON_LABEL_SHADOW_X=,
=DESKTOP_ICON_LABEL_SHADOW_Y=, =DESKTOP_ICON_LABEL_PADDING_X=, and
=DESKTOP_ICON_LABEL_PADDING_Y=.  Selection and drop highlighting always replace
the normal mode with PCManFM's existing scheme-selected background and text
colours; the existing focus rectangle and deterministic rubber-band selection
remain authoritative.

Full scheme application stops only the PCManFM desktop process matching the
Redstone =DISPLAY= and =HOME=, updates its =[*]= configuration, then restarts
that scoped renderer for a clean full redraw.  Boot application updates files
without touching a live process.  A persistent wallpaper override does not
change the scheme's label mode unless a future wallpaper declaration explicitly
carries such an override.

# --- Readability guard -------------------------------------------------------
# The old guard here compared colours for *exact string equality* and rewrote the
# accent only when it was byte-identical to the background.  That caught exactly
# one scheme (BeOS, which really does alias FOX_BASE to FOX_MENU_BG) and silently
# passed everything else, because the failure mode is almost never equality — it
# is FOX_BASE and FOX_MENU_BG being two different tones of the same light grey or
# beige.  Measured across all 104 tangled schemes, 86 fell below the WCAG AA 4.5:1
# ratio on foreground or accent, and 79 of those put the prompt accent under 3:1
# against its own background — cde-default at 1.05:1, serenity at 1.14:1, the whole
# BeOS family at 2.02:1.  That is the "not all the colours are ideally visible"
# report, and equality could never have found it.
#
# So measure instead of compare.  _term_contrast returns the real WCAG ratio, and
# _term_readable blends a colour toward black or white — away from whichever end
# the background sits at — in small steps until it clears the threshold, keeping
# the scheme's hue rather than flattening every terminal to black-on-white.  A
# scheme that wants its own unmodified palette can set REDSTONE_TERM_CONTRAST_MIN=0.
#
# _term_contrast rounds to two decimals, which makes the threshold a tolerance
# rather than a cliff. That is deliberate: serenity-redmond-zehn puts pure white
# on #0078D7 for 4.4989:1, and bending authentic Windows-10 white off-white to
# recover 0.0011 of a ratio would cost more than it buys. Anything that misses by
# a perceptible margin still gets corrected.
: "${REDSTONE_TERM_CONTRAST_MIN:=4.5}"

# Both helpers are deliberately POSIX awk.  strtonum() is a gawk extension: the
# guest carries gawk 5.3 and would have run it, but the host runs mawk, where it
# fails at *run time* with "function strtonum never defined" while still exiting
# cleanly and emitting empty colours — a silent miscolour that a syntax check and
# a successful tangle both wave through.  Parsing the hex by hand costs four lines
# and makes a host-side test a valid statement about guest behaviour.
_term_awk_lib='
    function hx(s,   i,c,d,n){
      n=0; s=tolower(s)
      for(i=1;i<=length(s);i++){
        c=substr(s,i,1); d=index("0123456789abcdef",c)-1
        if(d<0) return -1
        n=n*16+d
      }
      return n
    }
    function chan(v){v/=255; return (v<=0.03928)? v/12.92 : ((v+0.055)/1.055)^2.4}
    function norm(c){
      gsub(/^#/,"",c)
      if (length(c)==3) c=substr(c,1,1) substr(c,1,1) substr(c,2,1) substr(c,2,1) substr(c,3,1) substr(c,3,1)
      return (length(c)==6)? c : ""
    }
    function lum(c,  n,r,g,b){
      n=norm(c); if (n=="") return -1
      r=hx(substr(n,1,2)); g=hx(substr(n,3,2)); b=hx(substr(n,5,2))
      if (r<0||g<0||b<0) return -1
      return 0.2126*chan(r) + 0.7152*chan(g) + 0.0722*chan(b)
    }
    function ratio(l1,l2,  hi,lo){hi=(l1>l2)?l1:l2; lo=(l1>l2)?l2:l1; return (hi+0.05)/(lo+0.05)}
'

_term_contrast() {
  # _term_contrast <hex-a> <hex-b> -> WCAG ratio (1.00–21.00), or 0 if unparseable
  awk -v a="${1}" -v b="${2}" "${_term_awk_lib}"'
    BEGIN{
      la=lum(a); lb=lum(b)
      if (la<0 || lb<0) { print "0"; exit }
      printf "%.2f", ratio(la,lb)
    }'
}

_term_readable() {
  # _term_readable <hex-fg> <hex-bg> <min-ratio> -> hex that clears min against bg
  #
  # Try BOTH directions rather than guessing one from a lightness threshold.  An
  # earlier cut here picked the target with `(lbg > 0.35) ? black : white`, which
  # is wrong for every mid-tone background: on serenity-nord's #7E9DBC it chose
  # white and reached 2.82:1, where black reaches 7.4:1 — and when the colour was
  # already white it blended white toward white and changed nothing at all.  That
  # single constant accounted for all 18 schemes still failing after the first
  # pass.  Whichever direction clears the threshold with the smaller blend wins,
  # so the scheme's own hue is disturbed as little as the target allows.
  awk -v fg="${1}" -v bg="${2}" -v min="${3}" "${_term_awk_lib}"'
    BEGIN{
      lbg=lum(bg); n=norm(fg)
      if (lum(fg)<0 || lbg<0) { print fg; exit }
      r=hx(substr(n,1,2)); g=hx(substr(n,3,2)); b=hx(substr(n,5,2))
      best=""; bestt=99; bestratio=-1; bestfallback=""
      split("0 255", tgts, " ")
      for (k=1; k<=2; k++) {
        tgt=tgts[k]+0
        for (t=0; t<=1.0001; t+=0.02) {
          nr=r+(tgt-r)*t; ng=g+(tgt-g)*t; nb=b+(tgt-b)*t
          c=sprintf("#%02x%02x%02x", int(nr+0.5), int(ng+0.5), int(nb+0.5))
          rr=ratio(lum(c), lbg)
          if (rr>bestratio) { bestratio=rr; bestfallback=c }
          if (rr >= min) { if (t < bestt) { bestt=t; best=c } ; break }
        }
      }
      # If neither direction can reach the threshold (a background whose luminance
      # sits too near the middle), emit the most legible colour available rather
      # than an arbitrary endpoint.
      print (best!="") ? best : bestfallback
    }'
}

# else a shell prints — ls, git, grep, zsh completion, diff — draws from the

# --- Re-theme already-open default terminals, live -------------------------
# The module above only reaches terminals opened *after* a scheme switch, so a
# window that was already up kept the previous scheme's colours until it was
# closed and reopened. URxvt accepts OSC escapes at runtime, and writing them to
# a terminal's pts slave is exactly how that terminal receives output — so the
# repaint costs nothing but an escape string per window.
#
# Targeting is deliberately narrow. Only the scheme-aware default terminal is
# touched, identified by the -name redstone-zsh-default it is launched with. The
# fixed-identity terminals are period costumes with palettes of their own and
# must never be repainted: CMD, the CMD-themed Bash, the PowerShell frame, the
# PowerShell-themed Zsh, plain URxvt, XTerm and dosemu2 all keep their colours
# through every theme change. Matching on that one resource name is what keeps
# them out — a broader match on "urxvt" would recolour the lot.
_retheme_osc() {
  local dev="$1" i=0 _c
  # 10/11/12 = foreground / background / cursor; 4;N = ANSI slot N.
  printf '\033]10;%s\007\033]11;%s\007\033]12;%s\007' \
    "${REDSTONE_TERM_FG}" "${REDSTONE_TERM_BG}" "${REDSTONE_TERM_CURSOR}" > "${dev}" 2>/dev/null || return 1
  for _c in ${REDSTONE_TERM_ANSI}; do
    printf '\033]4;%d;%s\007' "${i}" "${_c}" > "${dev}" 2>/dev/null || return 1
    i=$((i + 1))
  done
  return 0
}

_retheme_count=0
while read -r _pid; do
  [[ -n "${_pid}" ]] || continue
  # The urxvt process owns the pty; its descendants are what hold it open as
  # their controlling terminal, which is the device that must be written to.
  while read -r _tty; do
    [[ -n "${_tty}" && "${_tty}" != "?" ]] || continue
    _dev="/dev/${_tty}"
    [[ -w "${_dev}" ]] || continue
    if _retheme_osc "${_dev}"; then
      _retheme_count=$((_retheme_count + 1))
    fi
    break
  done < <(ps -o tty= --ppid "${_pid}" 2>/dev/null)
  # Enumerate real urxvt processes by exact binary name, then confirm the
  # resource name from the cmdline. A bare `pgrep -f redstone-zsh-default` also
  # matches any shell whose own command line merely mentions the string — this
  # session hit exactly that, matching three processes where one urxvt existed.
done < <(for _p in $(pgrep -x urxvt 2>/dev/null); do
           if tr '\0' ' ' < "/proc/${_p}/cmdline" 2>/dev/null \
              | grep -q -- '-name redstone-zsh-default'; then
             echo "${_p}"
           fi
         done)

if [[ "${_retheme_count}" -gt 0 ]]; then
  echo "redstone-9x-scheme-apply: re-themed ${_retheme_count} live default terminal(s)" >&2
fi

# --- Backstop for IceWM's corrupt compiled font defaults ------------------
# icewm 4.0.0 ships a malformed default for QuickSwitchFontNameXft and
# StatusFontNameXft: two comma-separated entries lost the comma between them, so
# the chain contains the single unloadable entry
# "Sans Mono:monospace:size=12DejaVu Sans:size=12". It is wrong in the shipped
# share/icewm/preferences too (lines 1351 and 1387), which makes it upstream's
# bug rather than anything in this tree — the visible symptom is
#   IceWM: Warning: Could not load font "Sans Mono:monospace:size=12DejaVu Sans:size=12:lang=en-us"
# every time a theme that does not set those two prefs is loaded. Of the 110
# themes here exactly three qualify — BeOS-Max-Tab, BeOS-Personal-Tab and
# icedano, all of which set QuickSwitch but not Status.
#
# Rather than patch three theme files (two of which are regenerated by
# redstone-9x-icewm-derive and would lose the fix), close the hole where nothing
# can fall through it: prefoverride outranks the theme, so any font pref the
# active theme leaves unset gets filled here. A theme that sets its own value
# keeps it — this only supplies what would otherwise reach the broken default,
# and it borrows the theme's own menu/title font so typography stays per-theme
# instead of flattening every scheme to one face.
_theme_file=""
for _cand in \
  "${HOME}/.icewm/themes/${ICEWM_THEME}" \
  "${HOME}/.icewm/themes/${ICEWM_THEME}/default.theme" \
  "${HOME}/.icewm/themes/${ICEWM_THEME%%/*}/default.theme"; do
  [[ -f "${_cand}" ]] && { _theme_file="${_cand}"; break; }
done
if [[ -n "${_theme_file}" ]]; then
  _theme_font="$(sed -n 's/^[[:space:]]*MenuFontNameXft[[:space:]]*=[[:space:]]*"\(.*\)".*/\1/p' "${_theme_file}" | head -1)"
  [[ -n "${_theme_font}" ]] || _theme_font="$(sed -n 's/^[[:space:]]*TitleFontNameXft[[:space:]]*=[[:space:]]*"\(.*\)".*/\1/p' "${_theme_file}" | head -1)"
  # Last resort is a chain that is valid — the point is never to reach icewm's.
  [[ -n "${_theme_font}" ]] || _theme_font="DejaVu Sans:size=12,Sans:size=12"
  for _fp in QuickSwitchFontNameXft StatusFontNameXft; do
    if ! grep -qE "^[[:space:]]*${_fp}[[:space:]]*=" "${_theme_file}"; then
      ICEWM_PREFS="${ICEWM_PREFS:+${ICEWM_PREFS};}${_fp}=\"${_theme_font}\""
    fi
  done
fi

redstone_pcmanfm_desktop_pids() {
  local proc pid arg has_desktop proc_display="" proc_home=""
  local target_display="${DISPLAY:-}"
  local -a argv

  target_display="${target_display%.0}"
  [[ -n "${target_display}" ]] || return 0
  for proc in /proc/[0-9]*; do
    [[ -O "${proc}" && -r "${proc}/cmdline" && -r "${proc}/environ" ]] || continue
    pid="${proc##*/}"
    argv=()
    while IFS= read -r -d '' arg; do argv+=("${arg}"); done < "${proc}/cmdline"
    [[ "${#argv[@]}" -gt 0 && "${argv[0]##*/}" == "pcmanfm" ]] || continue
    has_desktop=0
    for arg in "${argv[@]:1}"; do
      [[ "${arg}" == "--desktop" ]] && has_desktop=1
    done
    [[ "${has_desktop}" -eq 1 ]] || continue
    proc_display=""
    proc_home=""
    while IFS= read -r -d '' arg; do
      case "${arg}" in
        DISPLAY=*) proc_display="${arg#DISPLAY=}" ;;
        HOME=*) proc_home="${arg#HOME=}" ;;
      esac
    done < "${proc}/environ"
    proc_display="${proc_display%.0}"
    [[ "${proc_display}" == "${target_display}" && "${proc_home}" == "${HOME}" ]] || continue
    printf '%s\n' "${pid}"
  done
}

# A running PCManFM saves its in-memory desktop config while exiting. Stop the
# exact Redstone desktop renderer before editing the file so it cannot overwrite
# the new label mode during the restart.
redstone_pcmanfm_pids=()
if [[ "${BOOT}" -eq 0 ]]; then
  mapfile -t redstone_pcmanfm_pids < <(redstone_pcmanfm_desktop_pids)
  for pid in "${redstone_pcmanfm_pids[@]}"; do
    kill "${pid}" 2>/dev/null || true
  done
  for pid in "${redstone_pcmanfm_pids[@]}"; do
    for _wait in {1..20}; do
      kill -0 "${pid}" 2>/dev/null || break
      sleep 0.05
    done
  done
fi

** Smooth title-gradient renderer

IceWM's =Gradients== theme key scales listed pixmaps instead of tiling them — so a rendered 1024px-wide gradient becomes a genuinely SMOOTH titlebar, ending the banded-ramp era. Used by the Serenity importer and the Windows 98 builder.

#+BEGIN_SRC python :tangle linux/.local/bin/redstone-9x-title-gradient :shebang "#!/usr/bin/env python3" :tangle-mode (identity #o755)
"""redstone-9x-title-gradient <theme-dir> <activeDark> <activeLight> <inactiveDark> <inactiveLight> [height]
Render smooth horizontal-gradient titleAT.png/titleIT.png into an IceWM theme
and ensure Gradients= declares them (scaled, not tiled)."""
import sys, os
from PIL import Image

theme, ad, al, idk, il = sys.argv[1:6]
height = int(sys.argv[6]) if len(sys.argv) > 6 else 20

def hx(h):
    h = h.lstrip('#')
    return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def render(dark, light, name):
    # 2px colour-stop image in XPM format. IceWM 4.0 registers gradient slots
    # by EXACT filename ("titleAT.xpm" — wpixres.cc GradientResource): a .png
    # can never enter the gradient path and silently tiles instead. XPM stops
    # interpolate smoothly across the full segment width at any window size.
    stem = name.rsplit('.', 1)[0]
    var = stem.replace('-', '_')
    lines = [f'/* XPM */',
             f'static char * {var}_xpm[] = {{',
             f'"2 {height} 2 1",',
             f'"a\tc {dark}",',
             f'"b\tc {light}",']
    lines += [f'"ab",'] * (height - 1) + [f'"ab"}};']
    with open(os.path.join(theme, stem + '.xpm'), 'w') as f:
        f.write('\n'.join(lines) + '\n')
    # remove any stale png twin from earlier eras
    png = os.path.join(theme, stem + '.png')
    if os.path.exists(png):
        os.remove(png)

render(ad, al, 'titleAT.png')
render(idk, il, 'titleIT.png')
render(ad, al, 'titleAB.png')
render(idk, il, 'titleIB.png')

# Caption buttons carry BAKED title-colour margins from the flat-title era.
# The ice2k technique (and the answer to "how does the XP theme do it?"):
# buttons sit at the bar's RIGHT end where the gradient has reached its
# light endpoint — so their margins are painted EXACTLY that end colour and
# blend seamlessly. (Transparency was wrong: IceWM composites buttons on
# their own fill, so cleared pixels rendered garbage.)
AD, AL, ID, IL = hx(ad), hx(al), hx(idk), hx(il)
CLEAR = {(0,0,128), (0,0,130), (0x84,0x35,0x1A)}
# Caption buttons sit at the bar's RIGHT (light) end; the sysmenu/menuButton
# sits at the LEFT (dark) end — each margin gets its own gradient endpoint.
# Base themes ship some buttons as .xpm (solid navy menuButtonA in the 95
# base) — those are read, baked, rewritten as .png, and the .xpm removed.
# Margins are POSITIONAL, not chromatic: the 95 base's inactive buttons use
# #808080 both as their outer margins AND as bevel shadow inside the glyph
# (Golden Era demo 2026-07-19: grey boxes around inactive captions on a sage
# gradient). A colour-global replace would kill the bevels, so margins are
# found by flood-fill from the pixmap edges — only edge-connected pixels of
# a clearable colour bake to the gradient endpoint; enclosed bevel pixels of
# the same colour survive.
from collections import deque
def bake_margins(im, endc, clearset):
    px = im.load(); W, H = im.size
    def clearable(x, y):
        r, g, b, a2 = px[x, y]
        return a2 == 0 or (r, g, b) in clearset
    q = deque()
    q.extend((x, y) for x in range(W) for y in (0, H - 1))
    q.extend((x, y) for y in range(H) for x in (0, W - 1))
    seen, ch = set(), False
    while q:
        x, y = q.popleft()
        if (x, y) in seen or not clearable(x, y):
            continue
        seen.add((x, y))
        px[x, y] = (*endc, 255); ch = True
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < W and 0 <= ny < H and (nx, ny) not in seen:
                q.append((nx, ny))
    return ch

BAKE = ([(s, {'A': (AL, CLEAR), 'I': (IL, CLEAR | {(0x80,0x80,0x80)})}) for s in
         ('close', 'minimize', 'maximize', 'restore', 'hide', 'rollup')]
        + [('menuButton', {'A': (AD, CLEAR | {(0x80,0x80,0x80)}),
                           'I': (ID, CLEAR | {(0x80,0x80,0x80)})})])
# GLYPH_FG (set by the converter for dark faces): caption glyph strokes are
# pure black in the base art and invisible on dark chrome. Only pure black —
# bevels are white/#808080/#404040 in the 95 base, so this touches exactly
# the X / _ / [] strokes. menuButton has no glyph and is excluded.
GLYPH = os.environ.get('GLYPH_FG', '')
GL = hx(GLYPH) if GLYPH else None

# SerenityOS-sourced conversions (redstone-9x-theme-convert sets these two
# only when the input was a SerenityOS .ini, never for Windows .theme/Plus!
# packs): swap the 95-donor's minimize underline-bar / maximize square-
# outline for SerenityOS's own glyphs — WindowFrame.cpp falls back to
# Base/res/icons/16x16/downward-triangle.png / upward-triangle.png when no
# window-minimize.png/window-maximize.png theme override exists. Runs BEFORE
# the GL pass below so a dark face's triangle gets the same black->GL flip
# the original bar/square glyph would have gotten — one recolour path, two
# shapes (Mètsàtron 2026-07-24, ported from the single serenity.scheme fix
# to cover all 31 "SerenityOS Themes" submenu variants).
SERENITY_FACE = os.environ.get('SERENITY_FACE', '')
FRAMES = [(8, 6), (9, 24)]

def down_triangle_pixels(cx, top):
    pts = []
    for i, w in enumerate((7, 5, 3, 1)):
        y = top + i
        x0 = cx - w // 2
        pts += [(x, y) for x in range(x0, x0 + w)]
    return pts

def up_triangle_pixels(cx, top):
    pts = []
    for i, w in enumerate((1, 3, 5, 7)):
        y = top + i
        x0 = cx - w // 2
        pts += [(x, y) for x in range(x0, x0 + w)]
    return pts

for stem, ends in BAKE:
    for st, (endc, clearset) in ends.items():
        png = os.path.join(theme, f'{stem}{st}.png')
        xpm = os.path.join(theme, f'{stem}{st}.xpm')
        bp = png if os.path.isfile(png) else xpm
        if not os.path.isfile(bp):
            continue
        im = Image.open(bp).convert('RGBA')
        ch = bake_margins(im, endc, clearset)
        if SERENITY_FACE and stem in ('minimize', 'maximize'):
            px = im.load()
            face = hx(SERENITY_FACE)
            for y in range(im.height):
                for x in range(im.width):
                    if px[x, y][:3] == (0, 0, 0):
                        px[x, y] = (*face, 255)
            glyph_fn = down_triangle_pixels if stem == 'minimize' else up_triangle_pixels
            for cx, top in FRAMES:
                for x, y in glyph_fn(cx, top):
                    if 0 <= x < im.width and 0 <= y < im.height:
                        px[x, y] = (0, 0, 0, 255)
            ch = True
        if GL and stem != 'menuButton':
            px = im.load()
            for y in range(im.height):
                for x in range(im.width):
                    if px[x, y][:3] == (0, 0, 0):
                        px[x, y] = (*GL, 255); ch = True
        if ch or bp == xpm:
            im.save(png)
            if os.path.isfile(xpm):
                os.remove(xpm)

# The INVERTED START FLAG (Mètsàtron's revelation, 2026-07-19): on dark
# themes the start button's black art (text, flag outline, trail) inverts to
# the theme fg — but POSITIONALLY: edge-connected black is the bevel's
# bottom/right shadow and must stay dark; only enclosed black inverts.
if GL:
    sp = os.path.join(theme, 'taskbar', 'start.png')
    if os.path.isfile(sp):
        im = Image.open(sp).convert('RGBA')
        px = im.load(); W2, H2 = im.size
        seen2, q2 = set(), deque()
        q2.extend((x, y) for x in range(W2) for y in (0, H2 - 1))
        q2.extend((x, y) for y in range(H2) for x in (0, W2 - 1))
        while q2:
            x, y = q2.popleft()
            if (x, y) in seen2 or px[x, y][:3] != (0, 0, 0):
                continue
            seen2.add((x, y))
            for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
                nx, ny = x + dx, y + dy

        n2 = 0

        if n2:
            im.save(sp)
            print(f"inverted start flag: {n2} px -> {GLYPH} (bevel {len(seen2)} px kept)")
th = os.path.join(theme, 'default.theme')
