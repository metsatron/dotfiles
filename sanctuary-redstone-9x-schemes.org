#+TITLE: Redstone 9X — Desktop Schemes
#+AUTHOR: Mètsàtron

Full-layer theme switching for the Redstone 9X sanctuary. Split out of =sanctuary-redstone-9x-desktop.org= on 2026-07-19 (module budget) — the scheme declarations and the apply/graft/host-gtk helpers live here; the theme builders, converters, and the SerenityOS asset importer moved to =sanctuary-redstone-9x-scheme-builders.org= on 2026-07-20 (module budget); the menu entries, IceWM startup hook, and GTK/qt6ct base configs they act on remain in the desktop module.

* Desktop Schemes — full-layer theme switching

A *Desktop Scheme* swaps every appearance layer at once: IceWM theme, GTK2/GTK3 theme, icon theme, cursor theme, fonts, desktop background, selection colours, Qt palette, and sound scheme. Before this existed (2026-07-19 audit) the Windows 95 look was smeared across nine uncoordinated mechanisms — a session-frozen =GTK_THEME= export, five absolute Chicago95 paths in the menu, a launcher-time icon graft, projected GTK/Qt files, and a dead =gtk-cursor-theme-name=Win95= reference. A scheme is one declarative file; =redstone-9x-scheme-apply= is the single mover.

Mechanism per layer:
- *IceWM*: writes =~/.icewm/theme= and restarts the WM. The curated Win2k IceWM themes remain reachable as "window borders only" variants that do not change the rest of the scheme.
- *GTK (new apps)*: rewrites =settings.ini= / =.gtkrc-2.0=. The session-wide =GTK_THEME= export is gone — it overrides both settings.ini and XSETTINGS, which would make switching impossible. Host-spawned browsers get their =GTK_THEME= from =redstone-9x-host-gtk=, which reads the *active* scheme at click time.
- *GTK (running apps)*: =xsettingsd= (desktop-common) is started by the IceWM startup hook; scheme-apply rewrites its config and SIGHUPs it, so already-running GTK3 apps restyle live.
- *Icons*: IceWM does not resolve XDG icon-theme names (a name it can't find silently drops the whole menu button), so the launcher grafts a curated set into =~/.icewm/icons/= — the graft is now scheme-aware via =redstone-9x-icons-graft=, sourcing from the scheme's icon theme with Chicago95 fallback.
- *Sounds*: =~/.local/share/sounds/sanctuary= becomes a symlink to =~/.local/share/sounds/schemes/<scheme>/= (the flat dir from the first sound landing migrates automatically).
- *Persistence*: the choice lands in =~/.config/redstone-9x/scheme=; the launcher re-asserts the active scheme after every projection pass (=--boot= mode, file effects only), so projection no longer resets appearance to Windows 95.

** Border-only test library

The =Window Borders Only= menu deliberately changes only =~/.icewm/theme=; it
does not touch the active Desktop Scheme's GTK, Qt, icons, wallpaper, sounds, or
label-colour contract.  Its payload is additive and keeps every existing
Redstone theme intact:

- =Tosh= is the unmodified =Tosh 0.2= archive supplied by Mètsàtron as
  =2266-tosh-02.tgz=, SHA-256
  =256d67162fa17565b40f14b99f43c7ddc234e6a65c6c25d837584714c1abf63f=.
  David Cañadas describes it as a Finder-related decoration; the included
  =readme= declares GPL-2.0-or-later and states that its graphics are original
  recreations rather than Apple artwork.  The relative title-pixmap symlinks
  are preserved as shipped.
- Ninety-one extra themes are vendored unmodified from
  =https://github.com/ice-wm/icewm-extra= at commit
  =903c784f825be1a70e062ef2e03ee436b471054b=.  The upstream GPL-3.0 license is
  preserved at =linux/.icewm/themes/icewm-extra.LICENSE.md=, and cross-theme
  relative symlinks remain intact so related families such as =metal=,
  =daniel4/5=, =pkde2/bluemetal2=, and =tubes/yak= keep sharing their native
  artwork.

The curated submenu calls out likely period donors (Macintosh, KDE/Motif,
OpenLook, OS/2, and Windows-classic families).  The companion dynamic menu
scans every deployed =~/.icewm/themes/*/default.theme= at open time and groups
the complete set A-Z, so future vendored themes become testable without another
hand-maintained menu edit.

** CDE dynasty schemes

The nIceCDE family (Stéphane Lassalvy, LGPL-3, based on Alexander Voigt's FMotif IceWM theme) recreates the Common Desktop Environment's 1990s-2000s HP-UX/Solaris workstation look. Five native IceWM themes are already vendored at =linux/.icewm/themes/nIceCDE.{Default,Green,Mustard,Sandy,Crimson}/= with their own tiled CDE backdrop patterns under =backgrounds/*.xpm=. Unlike the Windows dynasty these themes carry no flat =ColorActiveTitleBar= key — the titlebar is painted from a pixmap (=titleAM.xpm=), so titlebar/backdrop tones below were sampled from the actual pixmaps (Pillow dominant-colour pass over =titleAM.xpm= and each theme's named backdrop), not invented; menu/button/selection tones came straight from each theme's =Color*= keys.

GTK theme is the plain =cdetheme= (not =cdetheme1.3=/=cdetheme1.4=, which ship only a =cdepanel= PyInstaller build with no =gtk-3.0= dir at all; not =cdetheme-solaris=, whose =gtk-3.0/= is byte-for-byte the same widget set as =cdetheme='s — verified by directory diff, so the plain name is the natural pick with no functional loss). Qt goes through Kvantum instead of qt6ct's built-in Windows style (=QT_STYLE="kvantum"=) — CDE's Motif look has no equivalent in Qt6's stock styles, but Kvantum's =Commonality= family (pulled from T480, itself CDE-derived) does. =Commonality='s neutral tan base (=window.color=#c6b3a9=) suits Green/Mustard/Sandy; =commonalitygris= (grey base =#56585a=) was chosen for Default over the tan default because Default's own palette is already warm brown/orange (Paver backdrop, =#eda870= accent) and the grey base keeps widget chrome from fighting the backdrop; =commonalitysienna= (terracotta base =#c37b6a=, brick =highlight.color=#6d443c=) was chosen for Crimson because its magenta/red accent (=#b24d7a=/=#b54a7b=) sits on the same warm-red wheel as sienna's brick highlight — confirmed by reading each variant's =.kvconfig= =window.color=/=highlight.color= keys, not guessed from the name.

IceWM 4.0.0 also has no analogue clock renderer anywhere in its source (grep for "analog" across =src/= returns nothing) — =ClockCommand="i2kcal"= only fires the calendar app on click, it doesn't change the clock face — so the digital =ATClock= in a larger serif font is the shipped approximation. *** Clock refinements (2026-07-28)

Digit cells shrunk from 44×66 to 26×38 (see the =TaskBarClockLeds= comment in =HP-VUE/default.theme= for the full citation) — regenerated at =pointsize 34= from the same =PxPlus IBM VGA 9x14= font, not scaled from the old PNGs, so the pixel edges stay crisp. =YClock::autoSize()= still sizes the whole clock widget to =TaskBarGraphHeight=80= regardless of digit-cell size, so the row is unaffected; only the digits read smaller within it.

Date letters: =YClock::getPixmap()= (=src/aclock.cc=, lines ~434-462) only has pixmap-backed cases for =0-9=, space, =:=, =/=, =.=, and =a/p/m= (as an am/pm run, guarded by a look-ahead/look-behind so a bare "a" inside another word wouldn't misfire). Every OTHER letter falls through with no case — not a null pixmap, a genuinely unhandled character — into =YClock::makePixmap()= (line ~525), a real hybrid fallback already built into IceWM: it flips =prettyClock= false just long enough to render that one character via the plain Xft path (=paintPlain()=), then flips it back true and composites the result alongside the real LED digits — no letter-glyph art needed in principle, and no font-fallback disables LED mode for the rest of the string.

First implemented as =TimeFormat="%b %d %a %H:%M:%S"= and tested live — it does NOT look acceptable, and the cause is a genuine, source-confirmed defect rather than a styling choice: =YClock::paintPlain()= (=aclock.cc= line ~412) computes its vertical text position as =clockFont->ascent() + (height() - 1 - clockFont->height()) / 2=, where =height()= is =YClock::height()= — the WHOLE WIDGET's height (=TaskBarGraphHeight=80=) — not the small per-character pixmap =makePixmap()= actually draws into (sized to the LED digit's own height, =ledPixNum[8]->height()=). At the ORIGINAL 66px-tall digit cell that mismatch was small enough to mostly hide; shrunk to this pass's 38px cell (item 1, above) the text draws centred for an 80px canvas onto a 38px one and gets clipped to a barely-visible sliver at the very bottom edge — confirmed in a live headless =:97= render, not assumed. The two requests are genuinely in tension: a small elegant clock (his ask) and readable font-fallback letters both depend on the SAME =height()= call, and shrinking one breaks the other — this is not fixable from theme/config, only from a =paintPlain()= source patch.

Recommendation, implemented: drop the letters and ship an LED-native numeric/AM-PM format instead of anything relying on the broken font-fallback path — every character in the shipped format is a real LED pixmap, so nothing gets clipped. =DateFormat="%A, %d %B %Y"= (unchanged) still carries the full spelled-out date as a mouse-hover tooltip.

*** 12-hour AM/PM, no seconds (2026-07-28, second refinement)

=ledclockPixRes= (=src/wpixres.cc=, lines ~305-323) DOES enumerate dedicated am/pm slots — =ledPixA= ("a.xpm"), =ledPixP= ("p.xpm"), =ledPixM= ("m.xpm") — separately from the generic letter-fallback path covered above; =YClock::getPixmap()='s switch (=aclock.cc= lines ~460-471) handles =a/A=, =p/P=, =m/M= as real pixmap lookups, gated by a look-ahead/look-behind guard (=strchr("AMPamp", str[k])=) that only accepts them as part of an actual "AM"/"PM"/"am"/"pm" run — so unlike the month/weekday letters, AM/PM does NOT fall through to the height-broken =makePixmap()= fallback at all. Authored =ledclock/{a,p,m}.png= in the same 26×38 cell, same =PxPlus IBM VGA 9x14=-plus-shadow treatment as the digits, confirmed clean in isolation (no clipping — these are genuine pixmap slots, not the font-fallback path).

Shipped: =TimeFormat="%m/%d %I:%M %p"= — =%I= (zero-padded 12-hour) rather than =%l= (space-padded): chosen so the digit count stays fixed as minutes/hours change, matching how a real VFD/LED clock behaves, rather than the display width jittering by one digit-cell whenever the hour crosses single/double digits.

Dropping seconds does have a confirmed, sourced side effect on repaint frequency, though not on the underlying timer: =clockTimer->setTimer(1000, this, true)= (=aclock.cc= lines 65, 283-286) re-arms unconditionally every 1000ms regardless of format — the timer itself still fires once a second. What changes is =YClock::paint()='s own guard (=aclock.cc= line ~298): =if (toolTipVisible() || strcmp(str, lastTime))= — only actually calls =paintPretty()=/=paintPlain()= (and therefore only submits real X drawing) when the formatted string has changed since the last tick. With seconds in the format the string changes every second; without them (=%I:%M %p=) it's unchanged for up to 59 of every 60 ticks, so real repaints drop to roughly once a minute. Confirmed in the source, not assumed.

*** Two-line layout: NEEDS-PATCH, scope assessed

=YClock= has no multi-line rendering path of any kind. =YClock::paintPretty()= (=aclock.cc= lines ~367-405) is a single horizontal walk: one =x= cursor, one fixed =y= (=`y = (height() - z->height()) / 2`=, centred on the WHOLE widget), pixmaps placed at decreasing =x= as the string is walked right-to-left. The per-character redraw cache — =int positions[TimeSize]= / =char previous[TimeSize]= (=aclock.h= lines 69-70) — is a flat, single-dimension array indexed by position within ONE string; there is no second array, no line index, nothing =\n=-aware anywhere in =aclock.cc=. =strftime()= would happily put a literal newline byte into the formatted string if =TimeFormat= contained one, but =getPixmap()= has no case for it, so it would fall through to the same height-broken =makePixmap()= fallback as any other stray letter — it would NOT start a second line, it would render (badly) as a tofu/blank glyph inline. Two real lines is not reachable without a patch.

Verdict: **NEEDS-PATCH**. Scope, named honestly: =YClock::paintPretty()= would need to become two passes (split the formatted string on a delimiter, lay out row 1 in the top half of the widget's height and row 2 in the bottom half); =calcWidth()=/=autoSize()= would need to compute each line's width independently and take the max, rather than one flat sum; and the =positions=/=previous= cache arrays would need doubling (or restructuring per-line) since they currently assume exactly one string. All of this is contained to =aclock.cc= plus the member-array declarations in =aclock.h= — one file pair, no cross-module changes — but it is not a one-line patch: realistically 60-120 changed/added lines, most of the complexity being the position-cache restructuring rather than the drawing math itself. Not attempted this pass. This stacks as a third named patch candidate alongside the two already on record for this scheme: =wmtaskbar.cc= row-placement (quick-launch/tray to the bottom row) and this two-line clock patch — both real, bounded, single-file-pair changes to the same =icewm-gradients= fork this project already accepts patching (=room-gaming.scm=), not a reason on their own to avoid it, just not exercised in this pass.

Implemented unpatched instead (option b-adjacent): a single LED-native line, =%m/%d %I:%M %p= (e.g. "07/28 01:52 PM"), with the full spelled-out date still available as a =DateFormat= tooltip on hover.

*** Quick-launch icon size ceiling, restated for the record

Re-confirmed from source, not just the earlier single-call finding: grepped every =setIcon(=call site in the whole checkout (=browse.cc=, =wmapp.cc=, =objbar.cc=, =objmenu.cc=, =ymenu.cc=, =atasks.cc=, =themes.cc=, =wmwinmenu.cc=) — =objbar.cc:31='s =button->setIcon(icon, YIcon::smallSize())= is the ONLY call passing an explicit size for a toolbar-adjacent button, and it is unconditional. =themable.h= does register =ColorToolButton=/=ColorToolButtonText=/=ToolButtonFontName= (colour and font only) but no =ToolButtonIconSize= or equivalent — confirmed there is no existing preference of any kind that could decouple the toolbar's icon size from the rest of the WM's "small icon" contexts.

=SmallIconSize=32= (measured, this scheme's earlier pass): bottom row grows to 40px (=`YIcon::smallSize() + 8`= floor in =TaskBar::updateLayout()=, =wmtaskbar.cc=) — captured live in =hpux-vue-polish-before-smalliconsize32.png=. =SmallIconSize=24= (shipped): bottom row holds at exactly 32px, top row unaffected at 80px — both measured via =xwininfo=. 24 is the honest ceiling for a toolbar icon size that does not reopen the bottom-row spec; going bigger is available at the cost of exactly that trade, his call to make.

Patch scope for decoupling, named: a dedicated =ToolbarIconSize= (or similarly-named) preference, registered once in =themable.h= (one =OUV= line, matching the existing =SmallIconSize=/=MenuIconSize=/=LargeIconSize=/=HugeIconSize= entries at lines 188-191) and consumed at the single real call site, =objbar.cc:31=, replacing =YIcon::smallSize()= with the new variable. Two files, on the order of 2-3 changed lines plus the one new registration line — the smallest of the three patch candidates now on record for this scheme (row-placement in =wmtaskbar.cc=, two-line clock in =aclock.cc=/=aclock.h=, and this one), and arguably the natural first patch to land if Mètsàtron wants to start building out the =icewm-gradients= patch set this project already treats as an accepted fork point.

*** Compact 64px pass — Mètsàtron's OPTION A ruling (2026-07-28)

His ruling: the whole taskbar becomes 64px total, 32 top + 32 bottom, no patches this round. Design philosophy stated alongside it — "carrying forward, not replicating — make the current limitations look like intentional design constraints" — governed every judgment call below.

*Background strip.* Cut from a scratch copy of his =~/Pictures/HP-UX/taskbar-bg.png= (originals untouched, never touched) — kept rows 0-31 (top 32) and rows 80-111 (bottom 32) of the original 1×112 strip, joined into a new 1×64 =taskbar/taskbarbg.png=. Numeric pixel comparison (not eyeballed) of the join: the original's rows 77→80 already carry a hard transition (solid =#768CA1= body → =#3E4A55= dark shadow → =#C3CCD6= highlight, a real bevel edge in his own design). The straight middle-cut removes that two-row shadow cushion, so the new join goes body-tone directly into the highlight — a real, visible, but not severe seam (similar magnitude of jump to transitions already present elsewhere in his own gradient, e.g. the alternating =#3E4A55=/=#C8C8C8= groove stripes). Shipped as instructed (his explicit call, straight middle cut); if he wants it smoothed, the least-invasive alternative is shifting the cut window a few rows so the join lands inside the existing shadow band instead of past it (e.g. keep rows 0-31 and 78-109 instead of 80-111), preserving the natural cushion — not attempted, his call whether the seam bothers him in person.

*Top row 80→32.* =TaskBarGraphHeight=32= is still the lever (theme-honored, unchanged mechanism) — but at 32 it exposed a defect the 80px row had been silently absorbing: =ShowDesktop='s own icon (=taskbar/desktop.xpm=, inherited unmodified from =nIceCDE.Default=, 37×37) and =ShowWindowList='s glyph (this scheme's own =windows.png=, 32×32) both exceed 32px once run through =YButton::updateSize()='s =+4= formula (41px and 36px respectively) — at 80 they were comfortably swallowed, at 32 either one would have reopened the row. Both regenerated to 28×28 canvases (desktop icon resized with normal lanczos resampling — general iconography, not pixel-font art, so scaling is fine here unlike the LED digits) so =28+4=32= exactly. =windows.xpm=/=desktop.xpm= deleted from the theme (same shadowing trap as =start.xpm= before them) and replaced with =.png=.

*Clock.* Fourth generation of the same digit set, still regenerated at the new pointsize rather than scaled: 13×19 cells (pointsize 17), 1px drop shadow (2px would have swallowed most of an 11×17 glyph). Same =PxPlus IBM VGA 9x14= face, same =#3f2e40= shadow tone. =TimeFormat="%m/%d %I:%M %p"= unchanged.

*Pager and meters at 32px* — judged from the render, not assumed: =PagerShowPreview=1= kept ON. At 32px the per-workspace thumbnails still show a legible small window rectangle for workspace 1 (the only occupied one in the test render) and plain numbers for the empty workspaces 2-4 — a sensible, intentional-looking degrade, not a broken squint. CPU/MEM/NET graphs and the clock all stayed fully readable at the smaller row height in the live capture. No toggle to plain buttons was needed.

*Task-button groove continuity.* His ask: the bottom row should read as one continuous machined surface, groove running unbroken through every task button rather than each button floating as its own flat patch. IceWM's real pixmap names, confirmed the same way as every other pixmap this scheme ships (=src/wpixres.cc=, =taskbar2PixRes=): =taskbuttonbg.xpm= (normal), =taskbuttonactive.xpm= (focused), =taskbuttonminimized.xpm= (minimized) — none existed in this theme or its =nIceCDE.Default= ancestor before this pass (task buttons were falling back to flat =Color*TaskBarApp= fills). Built from the actual bottom-32px band of the newly-cut =taskbarbg.png= (rows 32-63 of the 64px strip) — checked alignment against a live render rather than assumed: =TaskPane= sits at bar-relative y=33 (=xwininfo=), matching the tiled background's own phase closely enough (the 1px =y[1]=1= gap the whole scheme already carries) that the groove lines up seamlessly, confirmed in the zoom crop below. Three variants: =taskbuttonbg.png= is the band as-is (continuous with the strip behind it), =taskbuttonactive.png= is the same band flipped vertically and darkened ~18% (Motif "pressed" convention — inverted bevel direction plus a darken, rather than a flat highlight), =taskbuttonminimized.png= is the same band desaturated ~45%. The HP badge (=MENU_BUTTON="hp-vue"=, sits in the same bottom row) and the window-list button (confirmed still hardcoded to the TOP row, not this one, per the bottom-row-population finding above — it never shares this groove context at all) were both judged from the render: the HP badge's own neutral grey bevel already reads as part of the same continuous surface without needing the groove treatment applied to it directly — no changes made there.

**** Live-room defects and the groove revert (2026-07-28)

The headless =:97= render above was clean, but the live =:93= room showed three defects: the panel never resized, the =taskbarbg.png= strip tiled as visibly repeated bands instead of a single continuous span, and the task-button groove pixmaps appeared on every button on the desktop, not just task buttons. Root cause of the first two, read directly from the live guest's =~/.icewm/prefoverride=: =TaskBarGraphHeight=80=, stale from before this pass, while =HP-VUE/default.theme= correctly carries =TaskBarGraphHeight=32=. =prefoverride= outranks the theme (per its own man page and the shadowing trap already on record in this file), so the live top row stayed at the old 80px height and the 64px background strip tiled to fill it. The stale value traced to this scheme's own =ICEWM_PREFS= string below — =TaskBarGraphHeight=80= was never updated to =32= when the rest of this pass moved to it, so every =redstone-9x-scheme-apply= run kept re-writing the old height into =prefoverride=. Fixed here (=TaskBarGraphHeight=32= in =ICEWM_PREFS=, matching =default.theme=); confirmed no other stale row/height keys in the same string.

Root cause of the third defect, confirmed from the actual IceWM 4.0.0 checkout (=src/wpixres.cc=, =taskbarPixRes=): =PixmapResource(buttonIPixmap, "buttonI.xpm", "taskbuttonbg.xpm")= and the =buttonAPixmap= line beneath it are a fallback chain — IceWM tries =buttonI.xpm=/=buttonA.xpm= (the theme's generic button pixmaps) first, and falls back to =taskbuttonbg.xpm=/=taskbuttonactive.xpm= if those don't exist. HP-VUE has never shipped =buttonI.xpm=/=buttonA.xpm= (confirmed: no such files in the theme directory), so the moment =taskbuttonbg.xpm=/=taskbuttonactive.xpm= existed, they became the fallback =buttonIPixmap=/=buttonAPixmap= — and =ybutton.cc= (lines 506-507) uses exactly those two for the background of every =YButton= on the desktop, task buttons or not. This is a real, source-confirmed IceWM 4.0.0 behaviour, not a Redstone bug in the pixmap content itself — but it makes the groove experiment unshippable as a scoped task-button-only effect in this engine.

Mètsàtron's ruling: the groove experiment is dead. =taskbuttonbg.png=, =taskbuttonactive.png=, and =taskbuttonminimized.png= are removed from =HP-VUE/taskbar/= entirely — task buttons (and every other =YButton= that was collaterally affected) return to the flat =Color*TaskBarApp= fills from before this pass. The 64px total bar (32 top + 32 bottom) and the single-span background strip remain the goal and are unaffected by this revert.

**** Clock defect on the live room, second confirmation

Mètsàtron additionally reported the date slash alternating along with the colon — consistent with the =TimeFormatAlt= root cause above being a full alternate-format string (=%m %d %I %M %p=, every separator swapped for a space on odd seconds), not just a colon-specific effect. The fix already covers it: =TimeFormatAlt= is removed entirely from this scheme's =ICEWM_PREFS= (=sanctuary-redstone-9x-schemes.org=, the tangled =hp-vue-default.scheme= block below) — it carried the shadowing value. Per the root-cause section above, this scheme's live route to =:93= for any =default.h=-only preference (which includes =TimeFormat=/=TimeFormatAlt=) runs through =prefoverride=, which — confirmed from its own man page — only honors themable preferences; =TimeFormat=/=TimeFormatAlt= are =default.h=-registered, so neither ever reaches a real running guest through the existing =scheme-apply= pipeline regardless of what this scheme sets. Fixed at the source (removed here) and verified correct in an isolated headless render; the live-guest gap is the same pipeline-level finding already on record, not a new defect.

The Be lineage's flat titlebars never read as true BeOS *tabs* — IceWM painted the whole caption as one solid fill. - =BeOS-Personal-Tab= — the terracotta colourway, generated from =BeOS-Max-Tab= by =redstone-9x-icewm-derive … '#6b3c28' '#efc6ad' --warm=. chrome or serif fonts — so it pairs cleanly with Win9x frames + Win95 fonts.

set2/5/6 face =#c0c0c0=, set4 fields =#ffffff=, set8 desktop =#008081=). A

*** KDE 1 Alpha IceWM payload builder

The Alpha payload is a deterministic fork of =KDE-0.1=.  It preserves every
caption glyph, frame, taskbar pixmap, cursor, font, and inactive-title setting;
only the theme identity, desktop pre-paint colour, and focused titlebar change.
The procedural backdrop generator owns =backgrounds/=, which this builder
preserves across rebuilds.

#+BEGIN_SRC python :tangle all/.local/bin/redstone-9x-kde-alpha-build :shebang "#!/usr/bin/env python3" :tangle-mode (identity #o755)
from __future__ import annotations

import argparse
import hashlib
import os
import re
import shutil
import tempfile
from pathlib import Path


def fingerprint(root: Path) -> list[tuple[str, str]]:
    result = []
    for path in sorted(root.rglob("*")):
        relative = path.relative_to(root)
        if relative.parts and relative.parts[0] == "backgrounds":
            continue
        if path.is_file():
            result.append((str(relative), hashlib.sha256(path.read_bytes()).hexdigest()))
        elif path.is_symlink():
            result.append((str(relative), f"link:{os.readlink(path)}"))
    return result


def replace_required(text: str, pattern: str, replacement: str) -> str:
    updated, count = re.subn(pattern, replacement, text, count=1, flags=re.MULTILINE)
    if count != 1:
        raise SystemExit(f"KDE Alpha donor missing required setting: {pattern}")
    return updated


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--repo-root", default=str(Path.home() / "DotCortex"))
    args = parser.parse_args()
    repo = Path(args.repo_root).expanduser().resolve()
    donor = repo / "linux/.icewm/themes/KDE-0.1"
    output = repo / "linux/.icewm/themes/KDE-1-Alpha"
    if not (donor / "default.theme").is_file():
        raise SystemExit(f"missing KDE 0.1 donor: {donor}")

    with tempfile.TemporaryDirectory(prefix=".KDE-1-Alpha-", dir=output.parent) as tmp:
        built = Path(tmp) / "KDE-1-Alpha"
        shutil.copytree(donor, built, symlinks=True)
        default = built / "default.theme"
        text = default.read_text(encoding="utf-8")
        text = replace_required(
            text, r'^ThemeDescription=.*$', 'ThemeDescription="KDE 1 Alpha"'
        )

    return 0

** Desktop icon-label typography

Desktop schemes declare one shared text-colour contract for PCManFM's icon
labels and XOSD's lower-right build label.  =DESKTOP_LABEL_FOREGROUND= and
=DESKTOP_LABEL_SHADOW= must either both be literal =#rrggbb= colours or both be
=auto=.  Explicit values are copied unchanged into both renderers.  =auto= asks
the build-stamp backdrop sampler to resolve one dark-on-light or light-on-dark
pair; scheme-apply records that resolved pair atomically and gives it to both
consumers.  Neither renderer makes a second independent contrast decision.

The older =DESKTOP_ICON_LABEL_FOREGROUND=,
=DESKTOP_ICON_LABEL_SHADOW_COLOR=, =BUILDSTAMP_FOREGROUND=, and
=BUILDSTAMP_SHADOW= keys remain migration inputs for existing declarations and
private overrides.  They are collapsed into the same shared pair at apply time,
so even legacy schemes cannot leave PCManFM and XOSD with different colours.
New and edited schemes should declare only the shared =DESKTOP_LABEL_*= pair.

=DESKTOP_ICON_LABEL_MODE= accepts exactly =shadow=, =box=, or =plain=:

- =shadow= paints one crisp glyph shadow at the configured integer offset,
  followed by one foreground pass.  PCManFM suppresses the shadow when the
  resolved foreground is dark, so a dark label never receives a dark halo.
- =box= paints one opaque, square-cornered rectangle around the complete Pango
  layout using =DESKTOP_ICON_LABEL_BACKGROUND= and the configured X/Y padding,
  followed by the foreground glyphs.  The rectangle follows wrapped labels
  rather than filling the icon cell.
- =plain= paints foreground glyphs only.

The renderer-specific geometry keys are =DESKTOP_ICON_LABEL_BACKGROUND=,
=DESKTOP_ICON_LABEL_SHADOW_X=, =DESKTOP_ICON_LABEL_SHADOW_Y=,
=DESKTOP_ICON_LABEL_PADDING_X=, and =DESKTOP_ICON_LABEL_PADDING_Y=.  Selection
and drop highlighting always replace the normal mode with PCManFM's existing
scheme-selected background and text colours; the existing focus rectangle and
deterministic rubber-band selection remain authoritative.

Full scheme application stops only the PCManFM desktop process matching the
Redstone =DISPLAY= and =HOME=, updates its =[*]= configuration, then restarts
that scoped renderer for a clean full redraw.  Boot application updates files
without touching a live process.  A persistent wallpaper override does not
change the scheme's label mode unless a future wallpaper declaration explicitly
carries such an override.

# report, and equality could never have found it.
#
# So measure instead of compare.  _term_contrast returns the real WCAG ratio, and
# _term_readable blends a colour toward black or white — away from whichever end
# the background sits at — in small steps until it clears the threshold, keeping
# the scheme's hue rather than flattening every terminal to black-on-white.  A
# scheme that wants its own unmodified palette can set REDSTONE_TERM_CONTRAST_MIN=0.
#
# _term_contrast rounds to two decimals, which makes the threshold a tolerance
# rather than a cliff. That is deliberate: serenity-redmond-zehn puts pure white
# on #0078D7 for 4.4989:1, and bending authentic Windows-10 white off-white to
# recover 0.0011 of a ratio would cost more than it buys. Anything that misses by
# a perceptible margin still gets corrected.
: "${REDSTONE_TERM_CONTRAST_MIN:=4.5}"

# Both helpers are deliberately POSIX awk.  strtonum() is a gawk extension: the
# guest carries gawk 5.3 and would have run it, but the host runs mawk, where it
# fails at *run time* with "function strtonum never defined" while still exiting
# cleanly and emitting empty colours — a silent miscolour that a syntax check and
# a successful tangle both wave through.  Parsing the hex by hand costs four lines
# and makes a host-side test a valid statement about guest behaviour.
_term_awk_lib='
    function hx(s,   i,c,d,n){
      n=0; s=tolower(s)
      for(i=1;i<=length(s);i++){
        c=substr(s,i,1); d=index("0123456789abcdef",c)-1
        if(d<0) return -1
        n=n*16+d
      }
      return n
    }
    function chan(v){v/=255; return (v<=0.03928)? v/12.92 : ((v+0.055)/1.055)^2.4}
    function norm(c){
      gsub(/^#/,"",c)
      if (length(c)==3) c=substr(c,1,1) substr(c,1,1) substr(c,2,1) substr(c,2,1) substr(c,3,1) substr(c,3,1)
      return (length(c)==6)? c : ""
    }
    function lum(c,  n,r,g,b){
      n=norm(c); if (n=="") return -1
      r=hx(substr(n,1,2)); g=hx(substr(n,3,2)); b=hx(substr(n,5,2))
      if (r<0||g<0||b<0) return -1
      return 0.2126*chan(r) + 0.7152*chan(g) + 0.0722*chan(b)
    }
    function ratio(l1,l2,  hi,lo){hi=(l1>l2)?l1:l2; lo=(l1>l2)?l2:l1; return (hi+0.05)/(lo+0.05)}
'

_term_contrast() {
  # _term_contrast <hex-a> <hex-b> -> WCAG ratio (1.00–21.00), or 0 if unparseable
  awk -v a="${1}" -v b="${2}" "${_term_awk_lib}"'
    BEGIN{
      la=lum(a); lb=lum(b)
      if (la<0 || lb<0) { print "0"; exit }
      printf "%.2f", ratio(la,lb)
    }'
}

_term_readable() {
  # _term_readable <hex-fg> <hex-bg> <min-ratio> -> hex that clears min against bg
  #
  # Try BOTH directions rather than guessing one from a lightness threshold.  An
  # earlier cut here picked the target with `(lbg > 0.35) ? black : white`, which
  # is wrong for every mid-tone background: on serenity-nord's #7E9DBC it chose
  # white and reached 2.82:1, where black reaches 7.4:1 — and when the colour was
  # already white it blended white toward white and changed nothing at all.  That
  # single constant accounted for all 18 schemes still failing after the first
  # pass.  Whichever direction clears the threshold with the smaller blend wins,
  # so the scheme's own hue is disturbed as little as the target allows.
  awk -v fg="${1}" -v bg="${2}" -v min="${3}" "${_term_awk_lib}"'
    BEGIN{
      lbg=lum(bg); n=norm(fg)
      if (lum(fg)<0 || lbg<0) { print fg; exit }
      r=hx(substr(n,1,2)); g=hx(substr(n,3,2)); b=hx(substr(n,5,2))
      best=""; bestt=99; bestratio=-1; bestfallback=""
      split("0 255", tgts, " ")
      for (k=1; k<=2; k++) {
        tgt=tgts[k]+0
        for (t=0; t<=1.0001; t+=0.02) {
          nr=r+(tgt-r)*t; ng=g+(tgt-g)*t; nb=b+(tgt-b)*t
          c=sprintf("#%02x%02x%02x", int(nr+0.5), int(ng+0.5), int(nb+0.5))
          rr=ratio(lum(c), lbg)
          if (rr>bestratio) { bestratio=rr; bestfallback=c }
          if (rr >= min) { if (t < bestt) { bestt=t; best=c } ; break }
        }
      }
      # If neither direction can reach the threshold (a background whose luminance
      # sits too near the middle), emit the most legible colour available rather
      # than an arbitrary endpoint.
      print (best!="") ? best : bestfallback
    }'
}

# so it used its built-in defaults. Those defaults assume a dark background:
# on a light scheme like serenity (#d2c0b6) or the BeOS greys, ANSI yellow
# (#cdcd00) and bright yellow (#ffff00) are effectively invisible. That is the
# "some colours are still hard to see" that survived the first pass.
#
# The base row is the fleet's own canon — style.org's lc/base16
# 'dreamweaver-cc2017, the palette already behind kitty's colour0-15, Rofi,
# Emacs, nvim, ranger, yazi and superfile — mapped onto ANSI in the standard
# base16 order. Semantics stay put (red is red, green is green) instead of being
# recoloured per scheme, which would make error output change meaning between
# themes. Each slot is then pushed through the same readability guard as the
# foreground, so a light scheme darkens the row and a dark scheme lightens it.
# On a light background that legitimately flips "white" to a dark tone — which
# is what every light terminal theme does, Solarized Light included.

# --- Re-theme already-open default terminals, live -------------------------
# The module above only reaches terminals opened *after* a scheme switch, so a
# window that was already up kept the previous scheme's colours until it was
# closed and reopened. URxvt accepts OSC escapes at runtime, and writing them to
# a terminal's pts slave is exactly how that terminal receives output — so the
# repaint costs nothing but an escape string per window.
#
# Targeting is deliberately narrow. Only the scheme-aware default terminal is
# touched, identified by the -name redstone-zsh-default it is launched with. The
# fixed-identity terminals are period costumes with palettes of their own and
# must never be repainted: CMD, the CMD-themed Bash, the PowerShell frame, the
# PowerShell-themed Zsh, plain URxvt, XTerm and dosemu2 all keep their colours
# through every theme change. Matching on that one resource name is what keeps
# them out — a broader match on "urxvt" would recolour the lot.
_retheme_osc() {
  local dev="$1" i=0 _c
  # 10/11/12 = foreground / background / cursor; 4;N = ANSI slot N.
  printf '\033]10;%s\007\033]11;%s\007\033]12;%s\007' \
    "${REDSTONE_TERM_FG}" "${REDSTONE_TERM_BG}" "${REDSTONE_TERM_CURSOR}" > "${dev}" 2>/dev/null || return 1
  for _c in ${REDSTONE_TERM_ANSI}; do
    printf '\033]4;%d;%s\007' "${i}" "${_c}" > "${dev}" 2>/dev/null || return 1
    i=$((i + 1))
  done
  return 0
}

_retheme_count=0
while read -r _pid; do
  [[ -n "${_pid}" ]] || continue
  # The urxvt process owns the pty; its descendants are what hold it open as
  # their controlling terminal, which is the device that must be written to.
  while read -r _tty; do
    [[ -n "${_tty}" && "${_tty}" != "?" ]] || continue
    _dev="/dev/${_tty}"
    [[ -w "${_dev}" ]] || continue
    if _retheme_osc "${_dev}"; then
      _retheme_count=$((_retheme_count + 1))
    fi
    break
  done < <(ps -o tty= --ppid "${_pid}" 2>/dev/null)
  # Enumerate real urxvt processes by exact binary name, then confirm the
  # resource name from the cmdline. A bare `pgrep -f redstone-zsh-default` also
  # matches any shell whose own command line merely mentions the string — this
  # session hit exactly that, matching three processes where one urxvt existed.
done < <(for _p in $(pgrep -x urxvt 2>/dev/null); do
           if tr '\0' ' ' < "/proc/${_p}/cmdline" 2>/dev/null \
              | grep -q -- '-name redstone-zsh-default'; then
             echo "${_p}"
           fi
         done)

if [[ "${_retheme_count}" -gt 0 ]]; then
  echo "redstone-9x-scheme-apply: re-themed ${_retheme_count} live default terminal(s)" >&2
fi

# --- GTK user CSS from template (selection + bevel colours) ---
if [[ -f "${CFG}/gtk-3.0/gtk.css.in" ]]; then
  r=$((16#${SEL_BG:1:2})); g=$((16#${SEL_BG:3:2})); b=$((16#${SEL_BG:5:2}))
  # Bevel colours: prefer scheme-provided keys (computed once by the converter,
  # same values as IceWM/Qt/Wine/FOX). Fall back to runtime GTK CSS extraction
  # only for .upstream vendored themes that have no converter-computed values.
  : "${BEVEL_FACE:=${FOX_BASE}}"
  if [[ -z "${BEVEL_HIGHLIGHT:-}" && -z "${BEVEL_SHADOW:-}" ]]; then
  _THEME_CSS="${HOME}/.themes/${GTK_THEME}/gtk-3.0/gtk.css"
  _THEME_CDE="${HOME}/.themes/${GTK_THEME}/gtk-3.0/cdecolors.css"
  BEVEL_HIGHLIGHT=""
  BEVEL_SHADOW=""
  BEVEL_DKSHADOW=""
  if [[ -f "${_THEME_CDE}" ]]; then
    # CDE family — palette 6 is the menu palette; Motif 2-colour bevel
    # uses bottomShadow as the dark border edge (no separate 3DDkShadow)
    BEVEL_HIGHLIGHT=$(grep -oP '@define-color\s+ts_color_6\s+\K#[0-9a-fA-F]{6}' "${_THEME_CDE}" | head -1)
    BEVEL_SHADOW=$(grep -oP '@define-color\s+bs_color_6\s+\K#[0-9a-fA-F]{6}' "${_THEME_CDE}" | head -1)
    BEVEL_DKSHADOW="${BEVEL_SHADOW}"
    _cde_bg=$(grep -oP '@define-color\s+bg_color_6\s+\K#[0-9a-fA-F]{6}' "${_THEME_CDE}" | head -1)
    [[ -n "${_cde_bg}" ]] && BEVEL_FACE="${_cde_bg}"
  elif [[ -f "${_THEME_CSS}" ]]; then
    # Chicago95 / bevel themes — pair box-shadow:inset with a nearby hex
    # border-top-color (±10 lines) to lock onto the button bevel block.
    # Check gtk.css first; split themes put widgets in gtk-widgets.css.
    _THEME_WIDGETS="${HOME}/.themes/${GTK_THEME}/gtk-3.0/gtk-widgets.css"
    _found_pair=false
    for _try_css in "${_THEME_CSS}" "${_THEME_WIDGETS}"; do
      [[ -f "${_try_css}" ]] || continue
      ${_found_pair} && break
      _count=0
      while IFS=: read -r _bsl _rest; do
        _count=$((_count + 1))
        (( _count > 5 )) && break
        _lo=$(( _bsl > 10 ? _bsl - 10 : 1 ))
        _nearby_hl=$(sed -n "${_lo},$((_bsl + 10))p" "${_try_css}" \
          | grep -oP 'border-top-color:\s*\K#[0-9a-fA-F]{6}' | head -1)
        if [[ -n "${_nearby_hl}" ]]; then
          BEVEL_HIGHLIGHT="${_nearby_hl}"
          _first_bs=$(sed -n "${_bsl}p" "${_try_css}")
          BEVEL_SHADOW=$(echo "${_first_bs}" | tr ',' '\n' | grep 'inset -[0-9]' \
            | grep -oP '#[0-9a-fA-F]{6}' | head -1)
          _found_pair=true
          break
        fi
      done < <(grep -n 'box-shadow:.*inset' "${_try_css}")
    done
    if [[ "${_found_pair}" != true ]]; then
      # Haiku/BeOS-style: no hex border-top-color, bevel in box-shadow only
      for _try_css in "${_THEME_CSS}" "${_THEME_WIDGETS}"; do
        [[ -f "${_try_css}" ]] || continue
        _bs_lineno=$(grep -n 'box-shadow:.*inset' "${_try_css}" | head -1 | cut -d: -f1)
        if [[ -n "${_bs_lineno}" ]]; then
          _first_bs=$(sed -n "${_bs_lineno}p" "${_try_css}")
          BEVEL_SHADOW=$(echo "${_first_bs}" | tr ',' '\n' | grep 'inset -[0-9]' \
            | grep -oP '#[0-9a-fA-F]{6}' | head -1)
          _hl_raw=$(echo "${_first_bs}" | tr ',' '\n' | grep 'inset [1-9]' \
            | grep -oiP '#[0-9a-fA-F]{6}\b|\bwhite\b' | head -1)
          [[ "${_hl_raw,,}" == "white" ]] && _hl_raw="#ffffff"
          BEVEL_HIGHLIGHT="${_hl_raw}"
          break
        fi
      done
    fi
  fi
  # Fallback for flat themes or failed extraction
  : "${BEVEL_DKSHADOW:=#000000}"
  if [[ -z "${BEVEL_HIGHLIGHT}" || -z "${BEVEL_SHADOW}" ]]; then
    _bh="${BEVEL_FACE#\#}"
    _br=$((16#${_bh:0:2})); _bg=$((16#${_bh:2:2})); _bb=$((16#${_bh:4:2}))
    [[ -z "${BEVEL_HIGHLIGHT}" ]] && BEVEL_HIGHLIGHT=$(printf '#%02x%02x%02x' \
      $((_br + (255 - _br) * 7 / 10)) $((_bg + (255 - _bg) * 7 / 10)) $((_bb + (255 - _bb) * 7 / 10)))
    [[ -z "${BEVEL_SHADOW}" ]] && BEVEL_SHADOW=$(printf '#%02x%02x%02x' \
      $((_br * 65 / 100)) $((_bg * 65 / 100)) $((_bb * 65 / 100)))
  fi
  fi  # end of runtime extraction fallback
  : "${BEVEL_DKSHADOW:=#000000}"
  _bh="${BEVEL_FACE#\#}"
  _br=$((16#${_bh:0:2})); _bg=$((16#${_bh:2:2})); _bb=$((16#${_bh:4:2}))
  _bevel_luma=$((_br * 299 + _bg * 587 + _bb * 114))
  if (( _bevel_luma >= 128000 )); then
    BEVEL_FG="#000000"
  else
    BEVEL_FG="#ffffff"
  fi
  mkdir -p "${HOME}/.config/gtk-3.0"
  sed -e "s|@SEL_BG@|${SEL_BG}|g" \
      -e "s|@SEL_FG@|${SEL_FG}|g" \
      -e "s|@SEL_RGBA@|rgba(${r}, ${g}, ${b}, 0.35)|g" \
      -e "s|@BEVEL_FACE@|${BEVEL_FACE}|g" \
      -e "s|@BEVEL_HIGHLIGHT@|${BEVEL_HIGHLIGHT}|g" \
      -e "s|@BEVEL_SHADOW@|${BEVEL_SHADOW}|g" \
      -e "s|@BEVEL_DKSHADOW@|${BEVEL_DKSHADOW}|g" \
      -e "s|@BEVEL_FG@|${BEVEL_FG}|g" \
      "${CFG}/gtk-3.0/gtk.css.in" > "${HOME}/.config/gtk-3.0/gtk.css"
fi

redstone_pcmanfm_desktop_pids() {
  local proc pid arg has_desktop proc_display="" proc_home=""
  local target_display="${DISPLAY:-}"
  local -a argv

  target_display="${target_display%.0}"
  [[ -n "${target_display}" ]] || return 0
  for proc in /proc/[0-9]*; do
    [[ -O "${proc}" && -r "${proc}/cmdline" && -r "${proc}/environ" ]] || continue
    pid="${proc##*/}"
    argv=()
    while IFS= read -r -d '' arg; do argv+=("${arg}"); done < "${proc}/cmdline"
    [[ "${#argv[@]}" -gt 0 && "${argv[0]##*/}" == "pcmanfm" ]] || continue
    # NO --desktop argv filter (live-caught 2026-08-08): pcmanfm is single-
    # instance per session — when a bare `pcmanfm` daemon exists, later
    # `pcmanfm --desktop` invocations DELEGATE to it and exit, so the desktop
    # renderer is the bare process and an argv filter never matches it. The
    # wedged daemon then survives every scheme apply, stuck on a stale theme.
    # Any owned pcmanfm on this display+home is the renderer: match them all.
    proc_display=""
    proc_home=""
    while IFS= read -r -d '' arg; do
      case "${arg}" in
        DISPLAY=*) proc_display="${arg#DISPLAY=}" ;;
        HOME=*) proc_home="${arg#HOME=}" ;;
      esac
    done < "${proc}/environ"
    proc_display="${proc_display%.0}"
    [[ "${proc_display}" == "${target_display}" && "${proc_home}" == "${HOME}" ]] || continue
    printf '%s\n' "${pid}"
  done
}

# A running PCManFM saves its in-memory desktop config while exiting. Stop the
# exact Redstone desktop renderer before editing the file so it cannot overwrite
# the new label mode during the restart.
redstone_pcmanfm_pids=()
if [[ "${BOOT}" -eq 0 ]]; then
  mapfile -t redstone_pcmanfm_pids < <(redstone_pcmanfm_desktop_pids)
  for pid in "${redstone_pcmanfm_pids[@]}"; do
    kill "${pid}" 2>/dev/null || true
  done
  for pid in "${redstone_pcmanfm_pids[@]}"; do
    for _wait in {1..20}; do
      kill -0 "${pid}" 2>/dev/null || break
      sleep 0.05
    done
  done
fi

    local key="$1" value="$2"
    if grep -q "^${key}=" "${PCMANFM_CONF}"; then
      sed -i "s|^${key}=.*|${key}=${value}|" "${PCMANFM_CONF}"

# --- Audacious Winamp skin (per-scheme) ---
# Mapped by SCHEME_ID glob rather than a key in all 104 .scheme files: two thirds
# of them are generated by the Python converters, so a per-file key would have to
# be threaded through every emitter to express what is really one rule per visual
# dynasty. This mirrors the REDSTONE_TERM_FONT case above. Any individual .scheme
# may still set AUDACIOUS_SKIN= to override its family, and AUDACIOUS_SKIN=none
# disables the layer entirely and leaves the guest's own choice alone.
#
# The named files come from both projected corpora — DotCortex' audacious Skins
# dir and the qmmp skins dir — which the launcher merges into one guest-local
# Skins directory, so all of these resolve from the same path at run time.
case "${SCHEME_ID}" in
  beos-*|haiku|icedano)                 : "${AUDACIOUS_SKIN:=BeOS.wsz}" ;;
  windows-3x)                           : "${AUDACIOUS_SKIN:=Likon__Old_Mac_OS.wsz}" ;;
  windows-95)                           : "${AUDACIOUS_SKIN:=Winamp_9x.wsz}" ;;
  windows-98|plus-*)                    : "${AUDACIOUS_SKIN:=Windows98.wsz}" ;;
  windows-2000)                         : "${AUDACIOUS_SKIN:=Windows_Style.wsz}" ;;
  windows-xp)                           : "${AUDACIOUS_SKIN:=WinXPamp.wsz}" ;;
  kde-0.1)                              : "${AUDACIOUS_SKIN:=Nostalgia_9x.wsz}" ;;
  # The dark SerenityOS variants only. serenity-catppuccin-latte is the light
  # member of that family and deliberately stays with the 9x skin below.
  serenity-basalt|serenity-contrast|serenity-cupertino|serenity-dark|\
  serenity-durrque|serenity-gruvbox-dark|serenity-nord|serenity-valve|\
  serenity-catppuccin-frappe|serenity-catppuccin-macchiato|serenity-catppuccin-mocha)
                                        : "${AUDACIOUS_SKIN:=combustion_TM.wsz}" ;;
  serenity|serenity-*)                  : "${AUDACIOUS_SKIN:=9xStyle.wsz}" ;;
  cde-*|cdep-*)                         : "${AUDACIOUS_SKIN:=Lightamp.wsz}" ;;
  *)                                    : "${AUDACIOUS_SKIN:=Winamp_9x.wsz}" ;;
esac

if [[ "${AUDACIOUS_SKIN}" != "none" ]]; then
  AUD_CFG="${HOME}/.config/audacious/config"
  AUD_SKIN="${HOME}/.local/share/audacious/Skins/${AUDACIOUS_SKIN}"
  if [[ ! -f "${AUD_SKIN}" ]]; then
    echo "redstone-9x-scheme-apply: audacious skin not projected: ${AUDACIOUS_SKIN}" >&2
  elif [[ ! -f "${AUD_CFG}" ]]; then
    echo "redstone-9x-scheme-apply: no audacious config yet; skin applies once it exists" >&2
  elif pgrep -x audacious >/dev/null 2>&1 \
       && { [[ "${BOOT}" -eq 1 ]] || [[ -z "${DISPLAY:-}" ]] || [[ "${AUDACIOUS_RESTART:-1}" == "0" ]]; }; then
    # Running, but this is not a moment to bounce it: --boot has no session to
    # relaunch into, a missing DISPLAY means no GUI to restore, and a scheme (or
    # the operator) can opt out entirely with AUDACIOUS_RESTART=0.
    echo "redstone-9x-scheme-apply: audacious is running — skin ${AUDACIOUS_SKIN} applies after it restarts" >&2
  elif pgrep -x audacious >/dev/null 2>&1; then
    # Audacious rewrites config wholesale when it exits, so the skin can only be
    # written while it is NOT running — which is why this restarts it around the
    # write rather than editing underneath it. Only ever when it was already
    # running: this never launches a player the user did not have open.
    #
    # Playback is preserved across the bounce. audtool lives beside audacious in
    # the room-gaming profile but is not always on PATH (the IceWM session has
    # the profile, a bare podman exec does not), so resolve it next to the
    # audacious binary rather than trusting PATH.
    _aud_bin="$(command -v audacious 2>/dev/null || true)"
    _aud_tool="$(command -v audtool 2>/dev/null || true)"
    if [[ -z "${_aud_tool}" && -n "${_aud_bin}" && -x "$(dirname "${_aud_bin}")/audtool" ]]; then
      _aud_tool="$(dirname "${_aud_bin}")/audtool"
    fi
    _aud_prof="${HOME}/.guix-extra-profiles/room-gaming/room-gaming"
    [[ -n "${_aud_bin}"  ]] || _aud_bin="${_aud_prof}/bin/audacious"
    [[ -n "${_aud_tool}" ]] || _aud_tool="${_aud_prof}/bin/audtool"

    # Clean shutdown, so Audacious flushes its playlist and settings first. It
    # will rewrite config with the OLD skin on the way out — that is fine and
    # expected, because the write below happens strictly after it is gone.
    if [[ -x "${_aud_tool}" ]]; then
      timeout 10 "${_aud_tool}" shutdown >/dev/null 2>&1 || true
    fi
    _aud_waited=0
    while pgrep -x audacious >/dev/null 2>&1 && [[ "${_aud_waited}" -lt 100 ]]; do
      sleep 0.1; _aud_waited=$((_aud_waited + 1))
    done
    if pgrep -x audacious >/dev/null 2>&1; then
      # Never SIGKILL: that would skip the config/playlist flush and lose the
      # queue outright. TERM still lets it save.
      pkill -TERM -x audacious 2>/dev/null || true
      _aud_waited=0
      while pgrep -x audacious >/dev/null 2>&1 && [[ "${_aud_waited}" -lt 50 ]]; do
        sleep 0.1; _aud_waited=$((_aud_waited + 1))
      done
    fi

    if pgrep -x audacious >/dev/null 2>&1; then
      echo "redstone-9x-scheme-apply: audacious would not exit; leaving skin ${AUDACIOUS_SKIN} for next start" >&2
    else
      _aud_write_skin=1
      _aud_restarting=1
    fi
  else
    _aud_write_skin=1
  fi

  if [[ "${_aud_write_skin:-0}" -eq 1 ]]; then
    # set_ini above is section-blind; audacious keys are section-scoped, so place
    # skin= specifically under [skins] rather than at the first match in the file.
    _aud_tmp="${AUD_CFG}.tmp.$$"
    awk -v val="${AUD_SKIN}" '
      BEGIN{ insect=0; done=0 }
      /^\[/ {
        if (insect && !done) { print "skin=" val; done=1 }
        insect = ($0 == "[skins]")
        print; next
      }
      insect && /^skin=/ { if (!done) { print "skin=" val; done=1 } next }
      { print }
      END{
        if (!done) {
          if (!insect) print "[skins]"
          print "skin=" val
        }
      }' "${AUD_CFG}" > "${_aud_tmp}" && mv -f "${_aud_tmp}" "${AUD_CFG}"
    rm -f "${_aud_tmp}"
  fi

  # Bring it back, if we were the one who closed it.
  if [[ "${_aud_restarting:-0}" -eq 1 ]]; then
    # Inherit this script's environment wholesale rather than rebuilding it.
    # scheme-apply runs inside the guest session on a menu click, so DISPLAY,
    # DBUS_SESSION_BUS_ADDRESS, XDG_CONFIG_HOME and the audio variables are
    # already correct here. Reconstructing them by hand is how a test harness in
    # this session launched a player bound to the HOST's config (an inherited
    # XDG_CONFIG_HOME=~/.config) and then, with env -i, one that could not open
    # its output plugin at all. Only the Qt theming vars are added, matching the
    # menu entry.
    #
    # No playback restore is attempted. Audacious reloads its own playlists, but
    # audtool's control verbs (playlist-jump, playback-play, playback-seek) were
    # measured returning exit 0 with no effect in this session, so issuing them
    # cannot be verified and, run against a not-yet-loaded playlist, actively

** Smooth title-gradient renderer

IceWM's =Gradients== theme key scales listed pixmaps instead of tiling them — so a rendered 1024px-wide gradient becomes a genuinely SMOOTH titlebar, ending the banded-ramp era. Used by the Serenity importer and the Windows 98 builder.

#+BEGIN_SRC python :tangle linux/.local/bin/redstone-9x-title-gradient :shebang "#!/usr/bin/env python3" :tangle-mode (identity #o755)
"""redstone-9x-title-gradient <theme-dir> <activeDark> <activeLight> <inactiveDark> <inactiveLight> [height]
Render smooth horizontal-gradient titleAT.png/titleIT.png into an IceWM theme
and ensure Gradients= declares them (scaled, not tiled)."""
import sys, os
from PIL import Image

theme, ad, al, idk, il = sys.argv[1:6]
height = int(sys.argv[6]) if len(sys.argv) > 6 else 20

def hx(h):
    h = h.lstrip('#')
    return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def render(dark, light, name):
    # 2px colour-stop image in XPM format. IceWM 4.0 registers gradient slots
    # by EXACT filename ("titleAT.xpm" — wpixres.cc GradientResource): a .png
    # can never enter the gradient path and silently tiles instead. XPM stops
    # interpolate smoothly across the full segment width at any window size.
    stem = name.rsplit('.', 1)[0]
    var = stem.replace('-', '_')
    lines = [f'/* XPM */',
             f'static char * {var}_xpm[] = {{',
             f'"2 {height} 2 1",',
             f'"a\tc {dark}",',
             f'"b\tc {light}",']
    lines += [f'"ab",'] * (height - 1) + [f'"ab"}};']
    with open(os.path.join(theme, stem + '.xpm'), 'w') as f:
        f.write('\n'.join(lines) + '\n')
    # remove any stale png twin from earlier eras
    png = os.path.join(theme, stem + '.png')
    if os.path.exists(png):
        os.remove(png)

render(ad, al, 'titleAT.png')
render(idk, il, 'titleIT.png')
render(ad, al, 'titleAB.png')
render(idk, il, 'titleIB.png')

# Caption buttons carry BAKED title-colour margins from the flat-title era.
# The ice2k technique (and the answer to "how does the XP theme do it?"):
# buttons sit at the bar's RIGHT end where the gradient has reached its
# light endpoint — so their margins are painted EXACTLY that end colour and
# blend seamlessly. (Transparency was wrong: IceWM composites buttons on
# their own fill, so cleared pixels rendered garbage.)
AD, AL, ID, IL = hx(ad), hx(al), hx(idk), hx(il)
CLEAR = {(0,0,128), (0,0,130), (0x84,0x35,0x1A)}
# Caption buttons sit at the bar's RIGHT (light) end; the sysmenu/menuButton
# sits at the LEFT (dark) end — each margin gets its own gradient endpoint.
# Base themes ship some buttons as .xpm (solid navy menuButtonA in the 95
# base) — those are read, baked, rewritten as .png, and the .xpm removed.
# Margins are POSITIONAL, not chromatic: the 95 base's inactive buttons use
# #808080 both as their outer margins AND as bevel shadow inside the glyph
# (Golden Era demo 2026-07-19: grey boxes around inactive captions on a sage
# gradient). A colour-global replace would kill the bevels, so margins are
# found by flood-fill from the pixmap edges — only edge-connected pixels of
# a clearable colour bake to the gradient endpoint; enclosed bevel pixels of
# the same colour survive.
from collections import deque
def bake_margins(im, endc, clearset):
    px = im.load(); W, H = im.size
    # Also clear whatever OPAQUE colour actually occupies the outer margin.
    # Dark-active themes (Creatures, Mystery) desaturate their dark active
    # titlebar into a dark grey inactive caption bg (Creatures #383838) that no
    # static allowlist can predict, so the flat-title-era allowlist skipped it
    # and left dark boxes around the caption buttons on the light inactive grey
    # gradient. The corner pixel is always background; enclosed bevels/glyphs of
    # the same colour survive via flood-fill connectivity, and if the corner is
    # already the endpoint colour the bake is a harmless no-op.
    cs = set(clearset)
    c0 = px[0, 0]
    if c0[3] != 0:
        cs.add(c0[:3])
    def clearable(x, y):
        r, g, b, a2 = px[x, y]
        return a2 == 0 or (r, g, b) in cs
    q = deque()
    q.extend((x, y) for x in range(W) for y in (0, H - 1))
    q.extend((x, y) for y in range(H) for x in (0, W - 1))
    seen, ch = set(), False
    while q:
        x, y = q.popleft()
        if (x, y) in seen or not clearable(x, y):
            continue
        seen.add((x, y))
        px[x, y] = (*endc, 255); ch = True
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < W and 0 <= ny < H and (nx, ny) not in seen:
                q.append((nx, ny))
    return ch

for stem, ends in BAKE:

* NeXTSTEP Palette Data

Phase 1 of the Redstone NeXTSTEP campaign extracts the source palettes before
any IceWM payload is authored.  OneStepBack contributes its six explicit GTK
colour roles; QTStep contributes dominant colours measured from its Xfwm4 title
and border pixmaps.  The extractor is intentionally read-only with respect to
the source assets and emits JSON so the result can be reviewed before it is
copied into the canonical data block below.

#+BEGIN_SRC python :tangle linux/.local/bin/redstone-9x-nextstep-palette-extract :shebang "#!/usr/bin/env python3" :tangle-mode (identity #o755)
"""Extract the Redstone NeXTSTEP campaign's source palette table.

The input families are checked-in DotCortex assets, not live guest state:
OneStepBack GTK CSS supplies six named colour roles, while QTStep Xfwm4 XPMs
provide dominant active/inactive title, border, and accent colours.  The
default output is stable, sorted JSON suitable for review and inclusion in the
canonical ``sanctuary-redstone-9x-schemes.org`` data block.
"""

from __future__ import annotations

import argparse
import collections
import json
import re
from pathlib import Path


ONE_STEP_ROLES = (
    "white_color",
    "lighter_color",
    "base_color",
    "darker_color",
    "black_color",
    "scale_color",
)
CSS_COLOR = re.compile(r"^@define-color\s+([A-Za-z0-9_-]+)\s+([^;]+);", re.MULTILINE)
HEX = re.compile(r"^#[0-9A-Fa-f]{6}$")
XPM_HEADER = re.compile(r'^\s*"(\d+)\s+(\d+)\s+(\d+)\s+(\d+)"')
XPM_COLOR = re.compile(r'^\s*"(.*?)"(?:,)?\s*$')


def slug(name: str) -> str:
    return re.sub(r"[^a-z0-9]+", "-", name.lower()).strip("-")


def resolve_css(value: str, values: dict[str, str], trail: tuple[str, ...] = ()) -> str:
    value = value.strip()
    if HEX.fullmatch(value):
        return value.lower()
    if value.startswith("@"):
        key = value[1:]
        if key in trail:
            raise ValueError(f"cyclic GTK colour reference: {' -> '.join(trail + (key,))}")
        if key not in values:
            raise ValueError(f"unresolved GTK colour reference: @{key}")
        return resolve_css(values[key], values, trail + (key,))
    raise ValueError(f"non-literal GTK colour expression: {value}")


def parse_one_step(path: Path) -> dict[str, str]:
    values = {name: value for name, value in CSS_COLOR.findall(path.read_text(encoding="utf-8"))}
    missing = [name for name in ONE_STEP_ROLES if name not in values]
    if missing:
        raise ValueError(f"{path}: missing GTK roles: {', '.join(missing)}")
    return {name: resolve_css(values[name], values) for name in ONE_STEP_ROLES}


def parse_xpm(path: Path) -> collections.Counter[str]:
    lines = path.read_text(encoding="latin-1").splitlines()
    header_index = next((i for i, line in enumerate(lines) if XPM_HEADER.match(line)), None)
    if header_index is None:
        raise ValueError(f"{path}: missing XPM header")
    match = XPM_HEADER.match(lines[header_index])
    assert match is not None
    _, _, color_count, chars_per_pixel = (int(part) for part in match.groups())
    if chars_per_pixel != 1:
        raise ValueError(f"{path}: unsupported chars-per-pixel {chars_per_pixel}")

    palette: dict[str, str | None] = {}
    for line in lines[header_index + 1 : header_index + 1 + color_count]:
        match = XPM_COLOR.match(line)
        if not match:
            raise ValueError(f"{path}: malformed XPM colour row: {line}")
        row = match.group(1)
        symbol = row[0]
        color_match = re.search(r"\bc\s+([^\s]+)", row)
        if not color_match:
            raise ValueError(f"{path}: XPM colour row has no c field: {line}")
        color = color_match.group(1)
        palette[symbol] = None if color.lower() == "none" else color.lower()

    pixels = lines[header_index + 1 + color_count :]
    counts: collections.Counter[str] = collections.Counter()
    for line in pixels:
        match = XPM_COLOR.match(line)
        if not match:
            continue
        for symbol in match.group(1):
            color = palette.get(symbol)
            if color and HEX.fullmatch(color):
                counts[color] += 1
    if not counts:
        raise ValueError(f"{path}: no literal pixel colours found")
    return counts


def dominant(path: Path, excluded: set[str] | None = None, accent: bool = False) -> str:
    counts = parse_xpm(path)
    excluded = excluded or set()
    ranked = counts.most_common()
    if accent:
        for color, _ in ranked:
            if color in excluded:
                continue
            red, green, blue = (int(color[index : index + 2], 16) for index in (1, 3, 5))
            if max(red, green, blue) - min(red, green, blue) >= 24:
                return color
    for color, _ in ranked:
        if color not in excluded:
            return color
    return ranked[0][0]


def extract(repo: Path) -> dict[str, dict[str, dict[str, str]]]:
    themes = repo / "linux/.themes"
    one_step: dict[str, dict[str, str]] = {}
    for path in sorted(themes.glob("OneStepBack*/gtk-3.0/gtk.css")):
        one_step[slug(path.parent.parent.name.removeprefix("OneStepBack")) or "base"] = parse_one_step(path)
    if len(one_step) != 7:
        raise ValueError(f"expected 7 OneStepBack palettes, found {len(one_step)}")

    qt_step: dict[str, dict[str, str]] = {}
    for directory in sorted(themes.glob("QTStep*19p")):
        xfwm = directory / "xfwm4"
        active = dominant(xfwm / "title-1-active.xpm")
        inactive = dominant(xfwm / "title-1-inactive.xpm", {active})
        border = dominant(xfwm / "left-active.xpm", {active, inactive})
        accent = dominant(xfwm / "maximize-prelight.xpm", {active, inactive, border}, accent=True)
        qt_step[slug(directory.name.removesuffix("19p"))] = {
            "active_title": active,
            "inactive_title": inactive,
            "border": border,
            "accent": accent,
        }
    if len(qt_step) != 20:
        raise ValueError(f"expected 20 QTStep palettes, found {len(qt_step)}")
    return {"one_step_back": one_step, "qt_step": qt_step}


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--repo-root", default=str(Path.home() / "DotCortex"))
    args = parser.parse_args()
    data = extract(Path(args.repo_root).expanduser().resolve())
    print(json.dumps(data, indent=2, sort_keys=True))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
