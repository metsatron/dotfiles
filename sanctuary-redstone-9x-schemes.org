#+TITLE: Redstone 9X — Desktop Schemes
#+AUTHOR: Mètsàtron

Full-layer theme switching for the Redstone 9X sanctuary. Split out of =sanctuary-redstone-9x-desktop.org= on 2026-07-19 (module budget) — the scheme declarations, the apply/graft/host-gtk helpers, and the SerenityOS asset importer live here; the menu entries, IceWM startup hook, and GTK/qt6ct base configs they act on remain in the desktop module.

* Desktop Schemes — full-layer theme switching

A *Desktop Scheme* swaps every appearance layer at once: IceWM theme, GTK2/GTK3 theme, icon theme, cursor theme, fonts, desktop background, selection colours, Qt palette, and sound scheme. Before this existed (2026-07-19 audit) the Windows 95 look was smeared across nine uncoordinated mechanisms — a session-frozen =GTK_THEME= export, five absolute Chicago95 paths in the menu, a launcher-time icon graft, projected GTK/Qt files, and a dead =gtk-cursor-theme-name=Win95= reference. A scheme is one declarative file; =redstone-9x-scheme-apply= is the single mover.

Mechanism per layer:
- *IceWM*: writes =~/.icewm/theme= and restarts the WM. The curated Win2k IceWM themes remain reachable as "window borders only" variants that do not change the rest of the scheme.
- *GTK (new apps)*: rewrites =settings.ini= / =.gtkrc-2.0=. The session-wide =GTK_THEME= export is gone — it overrides both settings.ini and XSETTINGS, which would make switching impossible. Host-spawned browsers get their =GTK_THEME= from =redstone-9x-host-gtk=, which reads the *active* scheme at click time.
- *GTK (running apps)*: =xsettingsd= (desktop-common) is started by the IceWM startup hook; scheme-apply rewrites its config and SIGHUPs it, so already-running GTK3 apps restyle live.
- *Icons*: IceWM does not resolve XDG icon-theme names (a name it can't find silently drops the whole menu button), so the launcher grafts a curated set into =~/.icewm/icons/= — the graft is now scheme-aware via =redstone-9x-icons-graft=, sourcing from the scheme's icon theme with Chicago95 fallback.
- *Sounds*: =~/.local/share/sounds/sanctuary= becomes a symlink to =~/.local/share/sounds/schemes/<scheme>/= (the flat dir from the first sound landing migrates automatically).
- *Persistence*: the choice lands in =~/.config/redstone-9x/scheme=; the launcher re-asserts the active scheme after every projection pass (=--boot= mode, file effects only), so projection no longer resets appearance to Windows 95.

** CDE dynasty schemes

The nIceCDE family (Stéphane Lassalvy, LGPL-3, based on Alexander Voigt's FMotif IceWM theme) recreates the Common Desktop Environment's 1990s-2000s HP-UX/Solaris workstation look. Five native IceWM themes are already vendored at =linux/.icewm/themes/nIceCDE.{Default,Green,Mustard,Sandy,Crimson}/= with their own tiled CDE backdrop patterns under =backgrounds/*.xpm=. Unlike the Windows dynasty these themes carry no flat =ColorActiveTitleBar= key — the titlebar is painted from a pixmap (=titleAM.xpm=), so titlebar/backdrop tones below were sampled from the actual pixmaps (Pillow dominant-colour pass over =titleAM.xpm= and each theme's named backdrop), not invented; menu/button/selection tones came straight from each theme's =Color*= keys.

GTK theme is the plain =cdetheme= (not =cdetheme1.3=/=cdetheme1.4=, which ship only a =cdepanel= PyInstaller build with no =gtk-3.0= dir at all; not =cdetheme-solaris=, whose =gtk-3.0/= is byte-for-byte the same widget set as =cdetheme='s — verified by directory diff, so the plain name is the natural pick with no functional loss). Qt goes through Kvantum instead of qt6ct's built-in Windows style (=QT_STYLE="kvantum"=) — CDE's Motif look has no equivalent in Qt6's stock styles, but Kvantum's =Commonality= family (pulled from T480, itself CDE-derived) does. =Commonality='s neutral tan base (=window.color=#c6b3a9=) suits Green/Mustard/Sandy; =commonalitygris= (grey base =#56585a=) was chosen for Default over the tan default because Default's own palette is already warm brown/orange (Paver backdrop, =#eda870= accent) and the grey base keeps widget chrome from fighting the backdrop; =commonalitysienna= (terracotta base =#c37b6a=, brick =highlight.color=#6d443c=) was chosen for Crimson because its magenta/red accent (=#b24d7a=/=#b54a7b=) sits on the same warm-red wheel as sienna's brick highlight — confirmed by reading each variant's =.kvconfig= =window.color=/=highlight.color= keys, not guessed from the name.

** Icon graft — scheme-aware

Copies a curated name list into IceWM's private =icons/= dir, size-suffixed the way IceWM wants (=<name>_<size>x<size>.png=), sourcing each name from the scheme's icon theme first and Chicago95 second (both use the =<category>/<size>/<name>.png= grammar). Runs host-side from the launcher (guest paths as args) and in-guest from scheme-apply.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-icons-graft :shebang "#!/bin/bash" :tangle-mode (identity #o755)
# redstone-9x-icons-graft <icons-root> <dest-dir> <icon-theme>
# Graft the curated Redstone icon set into an IceWM icons dir from the given
# XDG-layout icon theme (Chicago95 directory grammar: <category>/<size>/<name>.png),
# falling back to Chicago95 per name+size. IceWM cannot resolve XDG icon-theme
# names itself — a missing name silently drops the menu button — so this graft
# is the only bridge between icon themes and IceWM-drawn UI.
#
# THE GRAFT ONLY COVERS ICEWM. Desktop icons (pcmanfm ~/Desktop) resolve via
# real GTK icon-theme lookup, which follows the scheme theme's index.theme
# Inherits= chain and never sees this graft or its Chicago95 fallback. Every
# installed guest scheme icon theme (Win98SE, LinXP, SE98 in guest ~/.icons)
# must therefore declare "Inherits=Chicago95,..." or desktop-only names (games,
# briefcase, inbox) silently render blank/modern (sealed 2026-07-19 after the
# 98 desktop shipped with blank game icons twice).
set -uo pipefail

# Roots may be colon-separated: XDG icon dirs AND legacy ~/.icons both count
# (SE98/LinXP live in ~/.icons — found 2026-07-19).
ICONS_ROOT="${1:?icons roots required (colon-separated)}"
DEST="${2:?dest dir required (e.g. \$HOME/.icewm/icons)}"
THEME="${3:-Chicago95}"

NAMES="winamp ultimate-doom quake diablo hellfire theme-hospital duke-nukem-3d
red-alert command-conquer half-life blue-shift opposing-force zsnes snes9x
mupen64plus ms-dos-prompt retroarch msn inbox my_briefcase internet-web-browser
help-browser lxfind vlc
seamonkey palemoon redstone-system smplayer redstone-control-panel
system-file-manager emacs obsidian user-home system-run archive-manager
preferences-desktop-theme gnome-applications libreoffice-startcenter gimp
inkscape com.visualstudio.code postscript-viewer audio-card video-display
folder accessories-text-editor firefox_2 utilities-terminal
control-center2 system-shut-down preferences-system preferences-desktop
system-search edit-paste accessories-character-map applications-system
text-editor reload web-browser user-desktop text-x-generic image-x-generic
audio-x-generic video-x-generic application-pdf package-x-generic unknown
applications-utilities applications-development applications-games
applications-graphics applications-internet applications-multimedia
applications-office wine applications-painting eom corsix-th abiword gnumeric
libreoffice-writer libreoffice-calc libreoffice-impress libreoffice-draw
libreoffice-base libreoffice-math"
SIZES="16 22 24 32 48"
CATEGORIES="apps places actions devices mimes mimetypes status categories"

# Per-name theme pins (Mètsàtron's standing picks): VLC always wears his
# BeOS-r5 art — VLC is not Media-Player-Classic-like. quake/zsnes are pinned
# to Chicago95 because Win98SE ships its own art for both names that reads
# worse than the Windows-95 set (confirmed by contact-sheet comparison
# 2026-07-19: Win98SE's quake.png is a flat dark crescent with no logotype,
# Chicago95's is the branded rune-sigil box art; Win98SE's zsnes.png is an
# unbranded grey console silhouette, Chicago95's is the recognizable ZSNES
# multicolor logo) — every other game name in NAMES has no Win98SE art at
# all, so it already falls through to Chicago95 without needing a pin.
override_theme() {
  case "$1" in
    vlc) echo "BeOS-r5-Icons" ;;
    quake|zsnes) echo "Chicago95" ;;
    *) echo "" ;;
  esac
}

mkdir -p "${DEST}"
for name in ${NAMES}; do
  for size in ${SIZES}; do
    src=""
    _pin="$(override_theme "${name}")"
    for theme in ${_pin} "${THEME}" Chicago95; do
      for root in ${ICONS_ROOT//:/ }; do
        for cat in ${CATEGORIES}; do
          cand="${root}/${theme}/${cat}/${size}/${name}.png"
          [ -f "${cand}" ] && { src="${cand}"; break 3; }
          # Sized-dir grammar (e.g. Irixium: <theme>/<S>x<S>/<cat>/<name>.png,
          # DIFFERENT from Chicago95's <theme>/<cat>/<size>/<name>.png).
          cand="${root}/${theme}/${size}x${size}/${cat}/${name}.png"
          [ -f "${cand}" ] && { src="${cand}"; break 3; }
        done
      done
    done
    [ -n "${src}" ] && cp -f "${src}" "${DEST}/${name}_${size}x${size}.png"
  done
done
exit 0
#+END_SRC

** Scheme apply

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-scheme-apply :shebang "#!/bin/bash" :tangle-mode (identity #o755)
# redstone-9x-scheme-apply [--boot] <scheme-id>
# Swap every appearance layer to the named Desktop Scheme.
# --boot: file effects only (no WM restart, no daemon HUPs, no sounds) —
#         called by the launcher after projection, host-side with
#         HOME=<guest-home>, to re-assert the active scheme.
# Full mode (from the Desktop Schemes menu, in-guest): also restarts IceWM,
# HUPs xsettingsd, reconfigures pcmanfm, and plays the notify sound.
set -uo pipefail

BOOT=0
if [[ "${1:-}" == "--boot" ]]; then BOOT=1; shift; fi
SCHEME_ID="${1:?usage: redstone-9x-scheme-apply [--boot] <scheme-id>}"

CFG="${HOME}/.config/redstone-9x"
SCHEME_FILE="${CFG}/schemes/${SCHEME_ID}.scheme"
if [[ ! -f "${SCHEME_FILE}" ]]; then
  echo "scheme not found: ${SCHEME_FILE}" >&2
  ls "${CFG}/schemes/" 2>/dev/null >&2
  exit 1
fi
# shellcheck disable=SC1090
. "${SCHEME_FILE}"

: "${ICEWM_THEME:?}" "${GTK_THEME:?}" "${ICON_THEME:?}" "${CURSOR_THEME:?}"
: "${CURSOR_SIZE:=24}" "${GTK_FONT:=Sans 8}" "${DESKTOP_BG:=#008080}"
: "${SEL_BG:=#000080}" "${SEL_FG:=#ffffff}" "${QT6CT_COLORS:=win95.conf}"
: "${SOUND_SCHEME:=${SCHEME_ID}}" "${QT_STYLE:=Windows}"

# --- IceWM theme (the file the curated switcher always used) ---
mkdir -p "${HOME}/.icewm"
printf 'Theme="%s"\n' "${ICEWM_THEME}" > "${HOME}/.icewm/theme"

# --- IceWM taskbar-layout overrides (managed prefoverride block) ---
# Themes can only set colours; show/hide + placement toggles are
# preferences-level, and prefoverride outranks everything. The block is
# marked so the Focus menu's own prefoverride writes are never touched.
PREFO="${HOME}/.icewm/prefoverride"
touch "${PREFO}"
sed -i '/^# BEGIN redstone-scheme/,/^# END redstone-scheme/d' "${PREFO}"
if [[ -n "${ICEWM_PREFS:-}" ]]; then
  {
    echo "# BEGIN redstone-scheme (managed by redstone-9x-scheme-apply — do not edit)"
    IFS=';' read -ra _kvs <<< "${ICEWM_PREFS}"
    for _kv in "${_kvs[@]}"; do [[ -n "${_kv}" ]] && echo "${_kv}"; done
    echo "# END redstone-scheme"
  } >> "${PREFO}"
fi

# --- FOX toolkit registry (every FOX app: xfe, adie, PathFinder, ice2k) ---
if [[ -n "${FOX_BASE:-}" ]]; then
  mkdir -p "${HOME}/.foxrc"
  cat > "${HOME}/.foxrc/Desktop" <<FOXEOF
# Written by redstone-9x-scheme-apply (Desktop Scheme: ${SCHEME_ID}).
[SETTINGS]
basecolor=${FOX_BASE}
forecolor=${FOX_FG:-#000000}
backcolor=${FOX_BG:-#ffffff}
textcolor=${FOX_FG:-#000000}
selbackcolor=${FOX_SEL_BG:-#000080}
selforecolor=${FOX_SEL_FG:-#ffffff}
selmenubackcolor=${FOX_MENU_BG:-${FOX_SEL_BG:-#000080}}
selmenutextcolor=${FOX_MENU_FG:-${FOX_SEL_FG:-#ffffff}}
tipbackcolor=#ffffe1
tipforecolor=#000000
normalfont="Sans,80"
FOXEOF
fi

# --- GTK3 settings.ini + GTK2 rc (newly launched apps) ---
set_ini() { # file key value  (replace or append; tolerate quoted gtk2 style)
  local file="$1" key="$2" val="$3"
  if grep -q "^${key}=" "${file}" 2>/dev/null; then
    sed -i "s|^${key}=.*|${key}=${val}|" "${file}"
  else
    printf '%s=%s\n' "${key}" "${val}" >> "${file}"
  fi
}
GTK3="${HOME}/.config/gtk-3.0/settings.ini"
if [[ -f "${GTK3}" ]]; then
  set_ini "${GTK3}" gtk-theme-name "${GTK_THEME}"
  set_ini "${GTK3}" gtk-icon-theme-name "${ICON_THEME}"
  set_ini "${GTK3}" gtk-font-name "${GTK_FONT}"
  set_ini "${GTK3}" gtk-cursor-theme-name "${CURSOR_THEME}"
  set_ini "${GTK3}" gtk-cursor-theme-size "${CURSOR_SIZE}"
fi
GTK2="${HOME}/.gtkrc-2.0"
if [[ -f "${GTK2}" ]]; then
  set_ini "${GTK2}" gtk-theme-name "\"${GTK_THEME}\""
  set_ini "${GTK2}" gtk-icon-theme-name "\"${ICON_THEME}\""
  set_ini "${GTK2}" gtk-font-name "\"${GTK_FONT}\""
  set_ini "${GTK2}" gtk-cursor-theme-name "\"${CURSOR_THEME}\""
  set_ini "${GTK2}" gtk-cursor-theme-size "${CURSOR_SIZE}"
  set_ini "${GTK2}" gtk-button-images 0
  set_ini "${GTK2}" gtk-menu-images 0
fi

# --- GTK user CSS from template (selection colours) ---
if [[ -f "${CFG}/gtk-3.0/gtk.css.in" ]]; then
  r=$((16#${SEL_BG:1:2})); g=$((16#${SEL_BG:3:2})); b=$((16#${SEL_BG:5:2}))
  mkdir -p "${HOME}/.config/gtk-3.0"
  sed -e "s|@SEL_BG@|${SEL_BG}|g" \
      -e "s|@SEL_FG@|${SEL_FG}|g" \

# --- Qt via qt6ct ---
QT6CT="${HOME}/.config/qt6ct/qt6ct.conf"
if [[ -f "${QT6CT}" ]]; then
  sed -i -e "s|^color_scheme_path=.*|color_scheme_path=${HOME}/.config/qt6ct/colors/${QT6CT_COLORS}|" \

# --- Kvantum (only meaningful when QT_STYLE=kvantum; harmless otherwise) ---
if [[ -n "${KVANTUM_THEME:-}" ]]; then

# --- Wine classic colours (the Wine desktop follows the scheme too) ---
WINEREG="${HOME}/.config/redstone-9x/wine/${WINE_COLORS:-${SCHEME_ID}.reg}"

  # stall the scheme switch.
  ( wine regedit /S "${WINEREG}" >/dev/null 2>&1 & ) || true
fi

# --- Cursor fallback (libXcursor default when env is absent; also repairs
#     LXAppearance drive-by overwrites of this file) ---
mkdir -p "${HOME}/.icons/default"
printf '[Icon Theme]\nName=Default\nComment=Redstone scheme cursor fallback\nInherits=%s\n' \
  "${CURSOR_THEME}" > "${HOME}/.icons/default/index.theme"

# --- XSETTINGS (live restyle of running GTK3 apps) ---
mkdir -p "${HOME}/.config/xsettingsd"

# --- Desktop background (pcmanfm owns the desktop) ---
PCMANFM_CONF="${HOME}/.config/pcmanfm/default/desktop-items-0.conf"
if [[ -f "${PCMANFM_CONF}" ]]; then
  if [[ -n "${WALLPAPER:-}" && -f "${WALLPAPER}" ]]; then
    sed -i -e "s|^wallpaper_mode=.*|wallpaper_mode=${WALLPAPER_MODE:-stretch}|" \
           -e "s|^wallpaper=.*|wallpaper=${WALLPAPER}|" "${PCMANFM_CONF}"
    grep -q '^wallpaper=' "${PCMANFM_CONF}" || sed -i "/^wallpaper_mode=/a wallpaper=${WALLPAPER}" "${PCMANFM_CONF}"
  else
    # pcmanfm's real key is desktop_bg; the launcher's write-once seed used
    # wallpaper_bg_color and pcmanfm rewrote it (found by scratch test
    # 2026-07-19) — handle both so pristine and evolved confs both switch.
    sed -i -e "s|^wallpaper_mode=.*|wallpaper_mode=color|" \
           -e "s|^wallpaper_bg_color=.*|wallpaper_bg_color=${DESKTOP_BG}|" \
           -e "s|^desktop_bg=.*|desktop_bg=${DESKTOP_BG}|" \
           -e "s|^desktop_fg=.*|desktop_fg=${DESKTOP_FG:-#ffffff}|" "${PCMANFM_CONF}"
  fi
fi

# --- IceWM menu/toolbar icons regrafted from this scheme's icon theme ---
if command -v redstone-9x-icons-graft >/dev/null 2>&1; then
  redstone-9x-icons-graft "${HOME}/.local/share/icons:${HOME}/.icons" "${HOME}/.icewm/icons" "${ICON_THEME}"

** Smooth title-gradient renderer

IceWM's =Gradients== theme key scales listed pixmaps instead of tiling them — so a rendered 1024px-wide gradient becomes a genuinely SMOOTH titlebar, ending the banded-ramp era. Used by the Serenity importer and the Windows 98 builder.

#+BEGIN_SRC python :tangle linux/.local/bin/redstone-9x-title-gradient :shebang "#!/usr/bin/env python3" :tangle-mode (identity #o755)
"""redstone-9x-title-gradient <theme-dir> <activeDark> <activeLight> <inactiveDark> <inactiveLight> [height]
Render smooth horizontal-gradient titleAT.png/titleIT.png into an IceWM theme
and ensure Gradients= declares them (scaled, not tiled)."""
import sys, os
from PIL import Image

theme, ad, al, idk, il = sys.argv[1:6]
height = int(sys.argv[6]) if len(sys.argv) > 6 else 20

def hx(h):
    h = h.lstrip('#')
    return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def render(dark, light, name):
    # 2px colour-stop image in XPM format. IceWM 4.0 registers gradient slots
    # by EXACT filename ("titleAT.xpm" — wpixres.cc GradientResource): a .png
    # can never enter the gradient path and silently tiles instead. XPM stops
    # interpolate smoothly across the full segment width at any window size.
    stem = name.rsplit('.', 1)[0]
    var = stem.replace('-', '_')
    lines = [f'/* XPM */',
             f'static char * {var}_xpm[] = {{',
             f'"2 {height} 2 1",',
             f'"a\tc {dark}",',
             f'"b\tc {light}",']
    lines += [f'"ab",'] * (height - 1) + [f'"ab"}};']
    with open(os.path.join(theme, stem + '.xpm'), 'w') as f:
        f.write('\n'.join(lines) + '\n')
    # remove any stale png twin from earlier eras
    png = os.path.join(theme, stem + '.png')
    if os.path.exists(png):
        os.remove(png)

render(ad, al, 'titleAT.png')
render(idk, il, 'titleIT.png')
render(ad, al, 'titleAB.png')
render(idk, il, 'titleIB.png')

# Caption buttons carry BAKED title-colour margins from the flat-title era.
# The ice2k technique (and the answer to "how does the XP theme do it?"):
# buttons sit at the bar's RIGHT end where the gradient has reached its
# light endpoint — so their margins are painted EXACTLY that end colour and
# blend seamlessly. (Transparency was wrong: IceWM composites buttons on
# their own fill, so cleared pixels rendered garbage.)
AD, AL, ID, IL = hx(ad), hx(al), hx(idk), hx(il)
CLEAR = {(0,0,128), (0,0,130), (0x84,0x35,0x1A)}
# Caption buttons sit at the bar's RIGHT (light) end; the sysmenu/menuButton
# sits at the LEFT (dark) end — each margin gets its own gradient endpoint.
# Base themes ship some buttons as .xpm (solid navy menuButtonA in the 95
# base) — those are read, baked, rewritten as .png, and the .xpm removed.
# Margins are POSITIONAL, not chromatic: the 95 base's inactive buttons use
# #808080 both as their outer margins AND as bevel shadow inside the glyph
# (Golden Era demo 2026-07-19: grey boxes around inactive captions on a sage
# gradient). A colour-global replace would kill the bevels, so margins are
# found by flood-fill from the pixmap edges — only edge-connected pixels of
# a clearable colour bake to the gradient endpoint; enclosed bevel pixels of
# the same colour survive.
from collections import deque
def bake_margins(im, endc, clearset):
    px = im.load(); W, H = im.size
    def clearable(x, y):
        r, g, b, a2 = px[x, y]
        return a2 == 0 or (r, g, b) in clearset
    q = deque()
    q.extend((x, y) for x in range(W) for y in (0, H - 1))
    q.extend((x, y) for y in range(H) for x in (0, W - 1))
    seen, ch = set(), False
    while q:
        x, y = q.popleft()
        if (x, y) in seen or not clearable(x, y):
            continue
        seen.add((x, y))
        px[x, y] = (*endc, 255); ch = True
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < W and 0 <= ny < H and (nx, ny) not in seen:
                q.append((nx, ny))
    return ch

BAKE = ([(s, {'A': (AL, CLEAR), 'I': (IL, CLEAR | {(0x80,0x80,0x80)})}) for s in
         ('close', 'minimize', 'maximize', 'restore', 'hide', 'rollup')]
        + [('menuButton', {'A': (AD, CLEAR | {(0x80,0x80,0x80)}),
                           'I': (ID, CLEAR | {(0x80,0x80,0x80)})})])
# GLYPH_FG (set by the converter for dark faces): caption glyph strokes are
# pure black in the base art and invisible on dark chrome. Only pure black —
# bevels are white/#808080/#404040 in the 95 base, so this touches exactly
# the X / _ / [] strokes. menuButton has no glyph and is excluded.
GLYPH = os.environ.get('GLYPH_FG', '')
GL = hx(GLYPH) if GLYPH else None
for stem, ends in BAKE:
    for st, (endc, clearset) in ends.items():
        png = os.path.join(theme, f'{stem}{st}.png')
        xpm = os.path.join(theme, f'{stem}{st}.xpm')
        bp = png if os.path.isfile(png) else xpm
        if not os.path.isfile(bp):
            continue
        im = Image.open(bp).convert('RGBA')
        ch = bake_margins(im, endc, clearset)
        if GL and stem != 'menuButton':
            px = im.load()
            for y in range(im.height):
                for x in range(im.width):
                    if px[x, y][:3] == (0, 0, 0):
                        px[x, y] = (*GL, 255); ch = True
        if ch or bp == xpm:
            im.save(png)
            if os.path.isfile(xpm):
                os.remove(xpm)

# The INVERTED START FLAG (Mètsàtron's revelation, 2026-07-19): on dark
# themes the start button's black art (text, flag outline, trail) inverts to
# the theme fg — but POSITIONALLY: edge-connected black is the bevel's
# bottom/right shadow and must stay dark; only enclosed black inverts.
if GL:
    sp = os.path.join(theme, 'taskbar', 'start.png')
    if os.path.isfile(sp):
        im = Image.open(sp).convert('RGBA')
        px = im.load(); W2, H2 = im.size
        seen2, q2 = set(), deque()
        q2.extend((x, y) for x in range(W2) for y in (0, H2 - 1))
        q2.extend((x, y) for y in range(H2) for x in (0, W2 - 1))
        while q2:
            x, y = q2.popleft()
            if (x, y) in seen2 or px[x, y][:3] != (0, 0, 0):
                continue
            seen2.add((x, y))
            for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
                nx, ny = x + dx, y + dy
                if 0 <= nx < W2 and 0 <= ny < H2:
                    q2.append((nx, ny))
        n2 = 0
        for y in range(H2):
            for x in range(W2):
                if px[x, y][:3] == (0, 0, 0) and (x, y) not in seen2:
                    px[x, y] = (*GL, 255); n2 += 1
        if n2:
            im.save(sp)
            print(f"inverted start flag: {n2} px -> {GLYPH} (bevel {len(seen2)} px kept)")
th = os.path.join(theme, 'default.theme')
t = open(th, encoding='latin-1').read()
if 'Gradients=' not in t:
    t += '\nGradients="titleAT.xpm titleIT.xpm titleAB.xpm titleIB.xpm"\n'
    open(th, 'w', encoding='latin-1').write(t)
print(f"smooth gradients rendered into {theme} (h={height})")

** CDE palette batch converter — raided .dp palettes onto nIceCDE.Default

37 genuine CDE =.dp= palette files (raided source, cross-referenced against the hand-made =nIceCDE.Crimson= to crack the set semantics) become full Redstone 9X layers: an IceWM theme (=CDE-<Name>=, pixmaps recoloured — nIceCDE titlebars/frames are PIXMAP-painted, there is no flat colour key doing that work), a GTK theme (=CDE-<Name>=, cloned from =cdetheme= and recoloured), a tiled desktop backdrop rendered from a raided XBM pattern, a qt6ct palette, a Wine =.reg=, and a scheme file (=cdep-<slug>=, deliberately distinct from the hand-made =cde-*= prefix to avoid collision).

Set semantics (cracked 2026-07-20 by cross-referencing =Crimson.dp='s 8 colour sets against =nIceCDE.Crimson='s actual pixmap/=default.theme= colours): set1 = active titlebar/frame family, set2 = widget face + inactive titlebar/frame family, set4 = text/base fill, set8 = workspace/desktop background. Sets 3, 5, 6, 7 are secondary Motif widget groups CDE never wired into this IceWM/GTK pairing and are left untouched.

Pixmap recolour uses per-file luminance-transfer, not a fixed-anchor hue/saturation pixel classifier: =nIceCDE.Default='s own ACTIVE pixmaps (=title{A,I}*=, =frame{A,I}*=, =dframe{A,I}*=, button glyphs) already carry the family split in their filenames — the trailing =A=/=I= token — and critically the INACTIVE ramp is achromatic grey (=#999999=, zero saturation), which no hue-based classifier can recover a family from. Each xpm's own light/base/dark tones are sorted by luminance, the middle tone becomes that file's local reference, and every tone (including the reference itself) is re-expressed as a blend fraction toward white (highlights) or black (shadows) applied to the target anchor (set1 for =A= files, set2 for =I= files, =menusel.xpm=, =menusep.xpm= by direct inspection). A naive multiplicative luminance ratio was tried first and rejected at the ground-truth gate below — it clamps/blows out highlight channels and drifts hue at the extremes; the blend-fraction form reproduced the hand-made =nIceCDE.Crimson= highlight/shadow pairs almost exactly.

GTK recolouring reuses a second, genuinely hue/saturation-based classifier (=classify_family=) for the =cdetheme= assets, which DO mix both families' anti-aliased blends within single css/rc literals and PNG icons with no filename cue: hue distance to the two known base anchors (=#eda870= title, =#c6b2a8= face — cdetheme's own =cde_style_1=/=cde_style_5= Motif blocks, generated for the vendored =Broica.dp= by upstream's own =MotifColors.py=) gated to a ±22° band, saturation below 0.06 passes through as neutral (borders, greys, unrelated secondary-group teals/mauves genuinely fall outside the band and are correctly left alone).

Kvantum theme is =commonalitygris= across the whole palette fleet (decree 2026-07-20: the grey base never fights any palette's chrome; the earlier set2-hue rule that picked =commonalitysienna=/=Commonality= by warmth is superseded).

def hx(c):
    return '#%02x%02x%02x' % tuple(max(0, min(255, round(v))) for v in c)

def unhex(h):
    h = h.lstrip('#')
    return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def lum(c):
    return 0.299 * c[0] + 0.587 * c[1] + 0.114 * c[2]

def hsv(c):
    r, g, b = (v / 255.0 for v in c)
    h, s, v = colorsys.rgb_to_hsv(r, g, b)
    return h * 360.0, s, v

def contrast(bar_rgb):
    return (0, 0, 0) if lum(bar_rgb) >= 128 else (255, 255, 255)

def blend_white(c, f):
    return tuple(x + (255 - x) * f for x in c)

def blend_black(c, f):
    return tuple(x * (1 - f) for x in c)

def parse_dp(path):
    sets = []
    with open(path, encoding='latin-1') as f:
        for line in f:
            line = line.strip()
            if not line.startswith('#'):
                continue
            h = line.lstrip('#')
            groups = [h[i:i+4] for i in (0, 4, 8)]
            rgb = tuple(int(g, 16) >> 8 for g in groups)
            sets.append(rgb)
    if len(sets) != 8:
        raise ValueError(f"{path}: expected 8 sets, got {len(sets)}")
    return sets

def scale_to(rgb, target, ref):
    """Reproduce this pixel's tonal position relative to its file's own
    reference tone (blend toward white for highlights, toward black for
    shadows) on the new target anchor -- not a multiplicative luminance
    ratio, which clamps/blows out highlights and drifts hue at extremes
    (rejected at the mandatory ground-truth gate, 2026-07-20)."""
    lp, lr = lum(rgb), lum(ref)
    if abs(lp - lr) < 1e-6:
        return tuple(round(c) for c in target)
    if lp > lr:
        frac = (lp - lr) / max(1e-6, 255 - lr)
        out = blend_white(target, frac)
    else:
        frac = (lr - lp) / max(1e-6, lr)
        out = blend_black(target, frac)
    return tuple(max(0, min(255, round(c))) for c in out)

def classify_family(rgb, base1, base2, hue_band=22.0, sat_neutral=0.06):
    h, s, v = hsv(rgb)
    if s < sat_neutral:
        return None
    h1, _, _ = hsv(base1)
    h2, _, _ = hsv(base2)
    def hd(a, b):
        d = abs(a - b) % 360
        return min(d, 360 - d)
    d1, d2 = hd(h, h1), hd(h, h2)
    if min(d1, d2) > hue_band:
        return None
    return 1 if d1 <= d2 else 2

def render_backdrop(bm_path, out_png, set8):
    from PIL import Image
    w, h, bits = parse_xbm(bm_path)
    fg = tuple(round(c * 0.72) for c in set8)
    img = Image.new('RGB', (w, h), set8)
    px = img.load()
    row_bytes = (w + 7) // 8
    for y in range(h):
        for xb in range(row_bytes):
            idx = y * row_bytes + xb
            if idx >= len(bits):
                continue
            byte = bits[idx]
            for bit in range(8):
                x = xb * 8 + bit
                if x >= w:
                    continue
                if (byte >> bit) & 1:
                    px[x, y] = fg
    os.makedirs(os.path.dirname(out_png), exist_ok=True)
    img.save(out_png)

            t = re.sub(r'#[0-9A-Fa-f]{6}', lambda m: fam_map.get(m.group(0).lower(), m.group(0)), t)
            if t != orig:
                open(p, 'w', encoding='latin-1').write(t)
                n += 1
    return n

def recolor_gtk_pngs(root, set1, set2):
    from PIL import Image
    base1, base2 = unhex('#eda870'), unhex('#c6b2a8')
    n = 0
    for dp, dirs, fs in os.walk(root):
        dirs[:] = [d for d in dirs if d not in ('bak', 'src', '.git')]
        for fn in fs:
            if not fn.lower().endswith('.png'):
                continue
            p = os.path.join(dp, fn)
            try:
                im = Image.open(p).convert('RGBA')
            except Exception:
                continue
            colors = im.getcolors(maxcolors=1_000_000)
            if not colors:
                continue
            cmap, changed = {}, False
            for _, (r, g, b, a) in colors:
                fam = classify_family((r, g, b), base1, base2)
                if fam is None:
                    continue
                target, ref = (set1, base1) if fam == 1 else (set2, base2)
                cmap[(r, g, b)] = (*scale_to((r, g, b), target, ref), a)
                changed = True
            if not changed:
                continue
            px = im.load()
            for y in range(im.height):
                for x in range(im.width):
                    c = px[x, y]
                    m = cmap.get((c[0], c[1], c[2]))
                    if m:
                        px[x, y] = m
            im.save(p)
            n += 1
    return n

** SerenityOS asset importer

Repo tool (host-side, not projected): manufactures the SerenityOS scheme's assets *into the DotCortex source tree* from a SerenityOS checkout (BSD-2-Clause — unlike the Win95 media, these are redistributable and repo-first). The generated trees are committed as plain tracked payload, exactly like Irixium; this script is their canonical source together with upstream. Idempotent — rerun after an upstream refresh.

Products:
- =linux/.local/share/icons/Serenity95/= — icon theme, =Inherits=Chicago95=: only Serenity's own shell/filetype/app icons are present (mapped to XDG names, 16/32 native + 22/24/48 nearest-neighbour resamples for IceWM's graft sizes); inheritance fills every other name from Chicago95, which is what keeps the theme small and non-brittle.
- =linux/.icewm/themes/Serenity/= — the Windows-95 IceWM theme recoloured to =Default.ini=: flat =#6e2209= active titlebar (upstream renders a gradient to =#f4ca9e= — a titlebar-pixmap polish item), Serenity's *light* menu selection (=#d2c0b6= with black text — a real personality difference from Win95's navy/white), warm =#d4d0c8= chrome across colours and pixmaps.
- =linux/.themes/Serenity95/= — the Windows-95 GTK2/3/4 theme with the same colour map over CSS/rc text and all pixmaps (GTK menu hover becomes sienna rather than Serenity's light tan — pixmap surgery can't distinguish menu from selection assets; noted as polish).
- =linux/.config/redstone-9x/fonts/SerenitySans-Regular.ttf= and =wallpapers/serenity-sunset-retro.png=.

def emit(imgs, cat, name):
    # imgs: {16: Image|None, 32: Image|None}; nearest-neighbour resample for
    # the in-between/large sizes IceWM's graft wants (pixel-art rule).
    global count
    base32 = imgs.get(32) or (imgs.get(16).resize((32, 32), Image.NEAREST) if imgs.get(16) else None)
    base16 = imgs.get(16) or (imgs.get(32).resize((16, 16), Image.NEAREST) if imgs.get(32) else None)
    if base32 is None and base16 is None:
        return
    for size in SIZES:
        if size == 16:
            img = base16
        elif size == 32:
            img = base32
        else:
            src = base32 if base32 is not None else base16
            img = src.resize((size, size), Image.NEAREST)
        d = os.path.join(out, cat, str(size))
        os.makedirs(d, exist_ok=True)
        img.save(os.path.join(d, name + ".png"))
        count += 1

import sys, os
from PIL import Image
COLORMAP = {
    (0xC0, 0xC0, 0xC0): (0xD4, 0xD0, 0xC8),
    # Taskbar/toolbar fill: the Windows-95 theme uses a THIRD grey (#c3c3c3,
    # +3 over chrome) in taskbarbg.xpm/toolbuttonbg.xpm — found live 2026-07-19
    # when the taskbar stayed cold grey. Keep the same +3 offset, warmed.
    (0xC3, 0xC3, 0xC3): (0xD7, 0xD3, 0xCB),
    (0xDF, 0xDF, 0xDF): (0xE8, 0xE4, 0xDC),
    (0xE0, 0xE0, 0xE0): (0xE8, 0xE4, 0xDC),
    (0x00, 0x00, 0x80): (0x84, 0x35, 0x1A),
    (0x00, 0x80, 0x80): (0x50, 0x50, 0x50),
}
n = 0
for root in sys.argv[1:]:
    for dirpath, _, files in os.walk(root):
        for fn in files:
            if not fn.lower().endswith((".png", ".xpm")):
                continue
            if fn.lower().endswith(".xpm"):
                # xpm is text: colour-table substitution
                p = os.path.join(dirpath, fn)
                t = open(p, encoding="latin-1").read()
                for (r, g, b), (R, G, B) in COLORMAP.items():
                    t = t.replace(f"#{r:02x}{g:02x}{b:02x}", f"#{R:02x}{G:02x}{B:02x}")
                    t = t.replace(f"#{r:02X}{g:02X}{b:02X}", f"#{R:02X}{G:02X}{B:02X}")
                open(p, "w", encoding="latin-1").write(t)
                n += 1
                continue
            p = os.path.join(dirpath, fn)
            img = Image.open(p).convert("RGBA")
            px = img.load()
            changed = False
            for y in range(img.height):
                for x in range(img.width):
                    r, g, b, a = px[x, y]
                    m = COLORMAP.get((r, g, b))
                    if m:
                        px[x, y] = (*m, a)
                        changed = True
            if changed:
                img.save(p)
                n += 1
print(f"recoloured {n} pixmaps")
PYEOF
