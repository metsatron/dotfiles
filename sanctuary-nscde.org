* Purpose

=sanctuary-nscde= hosts *NsCDE* — Hegel3DReloaded's "Not so Common Desktop Environment", a faithful CDE recreation built as an extensive FVWM configuration plus FvwmScript GUI programs, Korn Shell scripts, Python tools, and Motif-styled GTK themes. Upstream: https://github.com/NsCDE/NsCDE. Where =sanctuary-cde= preserves the genuine Motif/ToolTalk CDE 2.5.3 codebase, NsCDE is the modern-continuation answer to the same aesthetic: CDE's front panel, workspace manager, and color schemes reimplemented on a maintained window manager, comfortable with modern GTK/Qt applications. It promotes the =sanctuary-nscde= line reserved in =guests.org='s "Modern X11 continuation sanctuaries" block.

Like every sanctuary it rides the one-store-many-rooms Guix substrate from =sanctuary-distrobox.org=: base image =sanctuary-base:guix=, host =/gnu/store= read-only, a dedicated =sanctuary-nscde= Guix profile providing FVWM3 and the runtime/toolchain, and NsCDE itself compiled from source inside the container. Xephyr display is *=:96=* (=:90= qtile, =:91= gnustep, =:92= cde, =:93= redstone-9x, =:94= godzilla-xs and retropie, =:95= mide).

* Application catalogue

NsCDE is the modern, usable CDE-period room; =sanctuary-cde= remains the
authentic Open CDE room for the tightly-coupled =dt*= suite (such as =dtfile=,
=dtpad=, =dtmail=, =dtcm=, =dticon=, and =dtterm=). NsCDE therefore owns its
own applications in the =sanctuary-nscde= Guix profile rather than borrowing
host binaries or transplanting the CDE runtime.

The profile contains three catalogue layers: NsCDE's front-panel tools and
modern daily applications; period-style accessories (paint, editor,
calculator, archive, document, image, file-manager, and office roles); and a
full Games category spanning classic X11/CDE-period titles, KDE board/card/
puzzle/arcade games, and larger period-style games. The profile also includes
=libkmahjongg= and =libkdegames= because their data trees are split from the
corresponding game binaries in Guix.

NsCDE's Application Manager remains the canonical catalogue surface. It opens
the guest XDG application tree through =pcmanfm menu://applications/=, so the
expanded profile is visible by category without replacing the user's
hand-maintained Quick Menu. Every launch must resolve from the guest profile,
the private session bus, and the NsCDE Xephyr display; a missing package must
never fall through to a host application.

* Qt toolkit commonality

The Qt layer follows the mature Redstone 9X pattern: =qt5ct= and =qt6ct= own
the per-generation platform configuration, while =Kvantum= supplies the
CDE-shaped widget engine for both generations. The current Guix =kvantum= 1.1.5
package is Qt6-only, so the NsCDE manifest defines a matching =kvantum-qt5=
variant from the same upstream release with =ENABLE_QT5=ON= and Qt5 inputs.
That keeps the Qt5 plugin inside the Guix profile instead of mixing a host Qt5
plugin with Guix Qt5 libraries. The light =Commonality= theme is the
initial NsCDE companion: Redstone's =commonalitygris= remains the dark-scheme
fleet's choice, but NsCDE's default Broica palette needs the light donor's
bevels and neutral chrome. The theme is projected read-only from the
DotCortex asset into the guest; the small qt5ct/qt6ct defaults and palette are
room-owned files.

Qt5 is the room default because NsCDE's ColorMgr and PyQt5 tools use it. Known
Qt6 catalogue applications receive a narrow wrapper that switches to qt6ct
and the Qt6 plugin/QML paths. This keeps both generations themed without
asking a Qt5 process to load a Qt6 platform plugin (or vice versa).

* The ksh93 problem

NsCDE hard-requires the AT&T original Korn Shell 93 — =configure.ac= aborts without a =ksh93=/=ksh= binary (=AC_PATH_PROGS([KSH],[ksh93 ksh],[no])=), upstream explicitly rejects pdksh/mksh/oksh as drop-ins, and every NsCDE script's shebang is baked to the configure-time ksh path (=#!@KSH@=). Guix has no ksh93 (only the mksh/oksh/loksh clones), so the build script first compiles *ksh93u+m* — the community-maintained AT&T ksh93 fork at https://github.com/ksh93/ksh — into =~/.local/share/nscde-deps/bin/ksh= inside the guest home. The guest home persists across container recreation, so the baked shebang path stays valid for the lifetime of the install. Everything lands in the guest home (=~/.local/share/NsCDE= for the desktop, mirroring CDE's =~/.local/share/cde= convention), so unlike =sanctuary-mide= no bind volume or preflight arm is needed: =distrobox-sanctuaries-create= uses plain =create_common=.

* Source build: sanctuary-nscde-build

Host-side build driver following the =sanctuary-cde-build= / =sanctuary-mide-build= pattern: an inner script heredoc executed through =sanctuary-exec= inside the container. Build order is ksh93u+m v1.0.10 (its own =bin/package make= build system), then NsCDE from pinned git master — release 2.3 (2023-06) predates FVWM3 1.1.x and Guix ships only =fvwm3=, so master (2.4-dev) with its FVWM3 fixes is the correct source. NsCDE's =configure= is checked in upstream (no autoreconf needed); with the prefix under the guest home every install path — sysconfdir, xsessions — stays inside the prefix. Each stage is sentinel-guarded and the script is safe to re-run; a re-run after success is a fast no-op.

#+BEGIN_SRC bash :tangle linux/.local/bin/sanctuary-nscde-build :shebang "#!/usr/bin/env bash"
# Build ksh93u+m + NsCDE from source inside sanctuary-nscde.
# Run once from the host: sanctuary-nscde-build
# Sources: https://github.com/ksh93/ksh  https://github.com/NsCDE/NsCDE
set -euo pipefail

usage() {
  cat <<EOF
sanctuary-nscde-build - build ksh93u+m + NsCDE inside sanctuary-nscde

Usage: sanctuary-nscde-build
       sanctuary-nscde-build -h | --help

No arguments. Clones, compiles, and installs ksh93u+m (v1.0.10, NsCDE's
hard ksh93 dependency missing from Guix) into ~/.local/share/nscde-deps
and NsCDE (pinned git master) into ~/.local/share/NsCDE, both inside the
persistent guest home. Idempotent: completed stages are skipped via
sentinel files.
EOF
}

if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
  usage
  exit 0
fi

if (( $# > 0 )); then
  usage >&2
  exit 1
fi

KSH_TAG="v1.0.10"
# NsCDE master pinned 2026-07-05 (2.4-dev; post-2.3 FVWM3 1.x fixes)
NSCDE_COMMIT="cbad197534dd357a15856f08140f16cacd87803b"
SANCTUARY="sanctuary-nscde"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"

# Heredoc builds the inner script — outer-shell vars (KSH_TAG, NSCDE_COMMIT,
# GUIX_PROFILES) expand at heredoc time; inner-shell vars are deferred via \$.
INNER_SCRIPT=$(cat <<INNER_EOF
set -eo pipefail

PREFIX=\${HOME}/.local/share/NsCDE
DEPS=\${HOME}/.local/share/nscde-deps
SRC=\${HOME}/.local/share/nscde-src

# Pre-declare vars the Guix profile scripts append to — they run under set -u
# semantics in some layers and must never hit an unbound variable.
export PKG_CONFIG_PATH="\${PKG_CONFIG_PATH:-}"
export LD_LIBRARY_PATH="\${LD_LIBRARY_PATH:-}"

GUIX_PROFILE=${GUIX_PROFILES}/desktop-common/desktop-common
. \${GUIX_PROFILE}/etc/profile
GUIX_PROFILE=${GUIX_PROFILES}/sanctuary-nscde/sanctuary-nscde
. \${GUIX_PROFILE}/etc/profile
export CURL_CA_BUNDLE=\${GIT_SSL_CAINFO}

mkdir -p "\${SRC}" "\${DEPS}/bin"
cd "\${SRC}"

# ── Stage 1: ksh93u+m — AT&T ksh93, hard NsCDE dependency ────────────────────
if [ ! -f "\${DEPS}/.sentinel-ksh-${KSH_TAG}" ]; then
  echo "Building ksh93u+m ${KSH_TAG}..."
  if [ ! -d ksh ]; then
    git clone --depth 1 --branch ${KSH_TAG} https://github.com/ksh93/ksh.git
  fi
  cd "\${SRC}/ksh"
  # Pin the compiler: package(1) aborts if the detected CC differs from the one
  # recorded in an existing arch tree, so never let PATH order decide it. And if
  # a finished, tested binary already exists (interrupted install), skip the
  # compile instead of re-invoking package make against a possibly different CC.
  export CC=gcc
  if ! ls arch/*/bin/ksh >/dev/null 2>&1; then
    ./bin/package make
  fi
  KSH_BIN=\$(ls "\${SRC}"/ksh/arch/*/bin/ksh | head -1)
  if [ -z "\${KSH_BIN}" ] || [ ! -x "\${KSH_BIN}" ]; then
    echo "ksh93u+m build produced no arch/*/bin/ksh binary" >&2
    exit 1
  fi
  install -m 0755 "\${KSH_BIN}" "\${DEPS}/bin/ksh"
  "\${DEPS}/bin/ksh" -c 'echo "ksh93 OK: \${.sh.version}"'
  touch "\${DEPS}/.sentinel-ksh-${KSH_TAG}"
  cd "\${SRC}"
else
  echo "ksh93u+m ${KSH_TAG} already installed (sentinel present)"
fi

# ksh must be visible to NsCDE's configure (AC_PATH_PROGS ksh93 ksh) so the
# @KSH@ shebang bakes to this persistent guest-home path.
export PATH=\${DEPS}/bin:\${PATH}

# ── Stage 2: NsCDE (pinned master) ───────────────────────────────────────────
if [ ! -f "\${PREFIX}/.sentinel-nscde-${NSCDE_COMMIT}" ]; then
  echo "Building NsCDE @ ${NSCDE_COMMIT}..."
  if [ ! -d NsCDE ]; then
    git clone https://github.com/NsCDE/NsCDE.git
  fi
  cd "\${SRC}/NsCDE"
  git fetch --depth 1 origin ${NSCDE_COMMIT} 2>/dev/null || git fetch origin
  git checkout ${NSCDE_COMMIT}
  # Neutralize git-checkout timestamp skew: the checked-in autotools outputs
  # are current, but checkout gives every file the same mtime, so make tries
  # maintainer-mode regeneration — which demands the exact aclocal-1.16
  # upstream used (Error 127 under Guix's newer automake). Touch the outputs
  # newer than their sources so the regeneration rules never fire.
  touch aclocal.m4
  find . -name Makefile.in -exec touch {} +
  touch configure
  ./configure --prefix="\${PREFIX}"
  make
  make install
  touch "\${PREFIX}/.sentinel-nscde-${NSCDE_COMMIT}"
else
  echo "NsCDE ${NSCDE_COMMIT} already installed (sentinel present)"
fi

# ── Re-runnable post-install fixups (run even when stage sentinels skip) ────
# Quiet egrep/fgrep: NsCDE's ksh scripts call egrep pervasively, and GNU grep
# 3.8+ prints an obsolescence warning per call, flooding the session log.
# Shim the names in nscde-deps/bin (PATH-front for build and launcher).
printf '#!/bin/sh\nexec grep -E "\$@"\n' > "\${DEPS}/bin/egrep"
printf '#!/bin/sh\nexec grep -F "\$@"\n' > "\${DEPS}/bin/fgrep"
chmod 0755 "\${DEPS}/bin/egrep" "\${DEPS}/bin/fgrep"

# get_logical_screens chokes on comment lines in Backdrops files: the second
# field becomes e.g. "Author:" and \$((o2 - 31)) aborts with a parse warning.
# Guard the read loop against comment/blank lines (idempotent).
GLS="\${PREFIX}/libexec/NsCDE/get_logical_screens"
if [ -f "\${GLS}" ] && ! grep -q 'DotCortex: skip comments' "\${GLS}"; then
  sed -i '/while read o1 o2 o3 o4 o5 o6/{n;s|do|do\n         case "\$o1" in ""\|"#"*) continue ;; esac # DotCortex: skip comments|;}' "\${GLS}"
fi

# NsCDE's Motif GTK2/GTK3 theme is GENERATED (themegen, needs PyQt5) into
# ~/.themes/NsCDE — the first-run wizard skips it silently when PyQt is
# missing, leaving GTK apps (pcmanfm, gimp) on raw stock defaults while the
# GTK configs already name theme "NsCDE". Generate the default Broica/8
# palette theme when absent; never regenerate over an existing one (the
# user may have chosen another palette via the Color Style Manager).
if [ ! -d "\${HOME}/.themes/NsCDE" ]; then
  echo "Generating NsCDE Motif GTK theme (Broica/8)..."
  NSCDE_ROOT=\${PREFIX} NSCDE_LIBDIR=\${PREFIX}/lib/NsCDE \
  NSCDE_DATADIR=\${PREFIX}/share/NsCDE NSCDE_TOOLSDIR=\${PREFIX}/libexec/NsCDE \
  FVWM_USERDIR=\${HOME}/.NsCDE QT_QPA_PLATFORM=offscreen \
    "\${PREFIX}/libexec/NsCDE/themegen" Broica 8 gtk2 gtk3 | grep -v '^/' || true
fi

# Tool-registry pins (audit 2026-07-31). NsCDE resolves its InfoStore tool
# slots per start via appfinder over app-catalog candidate lists; two need
# explicit pins in the user NsCDE.conf:
#  - mailreader: we ship icedove (Debian-rebranded Thunderbird) — the catalog
#    only knows "thunderbird", so the Mail applet resolves to NOAPP.
#  - browser: pin the Diet Netscape wrapper by path so the fix reaches an
#    already-running session on a mere FVWM restart (its PATH predates the
#    launcher's ~/.local/bin fix and env does not change on restart).
NCONF="\${HOME}/.NsCDE/NsCDE.conf"
if [ -f "\${NCONF}" ] && ! grep -q '^InfoStoreAdd mailreader ' "\${NCONF}"; then
  printf '\n# DotCortex: icedove is rebranded thunderbird; appfinder cannot know\nInfoStoreAdd mailreader icedove\n' >> "\${NCONF}"
fi
if [ -f "\${NCONF}" ] && ! grep -q '^InfoStoreAdd browser ' "\${NCONF}"; then
  # Absolute path, expanded at write time: f_FindApp guards each slot with
  # "Test (x ...)" which does NOT shell-expand — a literal \${HOME} fails the
  # test and appfinder silently overwrites the pin every FVWM start.
  printf '\n# DotCortex: Diet Netscape chrome wrapper, not the raw profile firefox\nInfoStoreAdd browser %s/.local/bin/firefox\n' "\${HOME}" >> "\${NCONF}"
fi

# Calendar: upstream ships f_Calendar deliberately unset (click on the front
# panel date → "Default action is not set" dialog). Wire it to icedove's
# built-in calendar — same shape as upstream's thunderbird example in
# Functions.fvwmlocal. Guarded: never touch a user-modified definition.
FLOCAL="\${HOME}/.NsCDE/Functions.fvwmlocal"
if [ -f "\${FLOCAL}" ] && ! grep -q 'DotCortex: f_Calendar' "\${FLOCAL}"; then
  cat >> "\${FLOCAL}" <<'CALEOF'

# DotCortex: f_Calendar — front-panel calendar opens icedove's calendar
DestroyFunc f_Calendar
AddToFunc f_Calendar
+ I None (*cedove*) Exec exec icedove -calendar
+ I All (*cedove*, !Iconic) WarpToWindow 50 50
CALEOF
fi

if [ -x "\${PREFIX}/bin/nscde" ]; then
  echo "NsCDE installed to \${PREFIX}"
  echo "Session starter: \${PREFIX}/bin/nscde (ksh: \${DEPS}/bin/ksh)"
  echo "Launch with: sanctuary-nscde-launch"
else
  echo "Build finished but \${PREFIX}/bin/nscde is missing — inspect the NsCDE stage." >&2
  exit 1
fi
INNER_EOF
)
sanctuary-exec "${SANCTUARY}" sh -c "${INNER_SCRIPT}"
#+END_SRC

* Launcher: sanctuary-nscde-launch

Same shape as =sanctuary-mide-launch=: dedicated Xephyr display =:96=, stale-session teardown, clipboard bridge, trash shield, then the session inside the container via =sanctuary-exec=. The session entry is NsCDE's own =<prefix>/bin/nscde= wrapper (a ksh93 script that sets =NSCDE_ROOT= and execs FVWM with the NsCDE configuration) — never a display manager. FVWM3 comes from the =sanctuary-nscde= Guix profile; =nscde-deps/bin= is prepended so every =#!…/ksh= script resolves. If the desktop has not been built yet the launcher falls back to a bare xterm with instructions rather than dying silently.

#+BEGIN_SRC bash :tangle linux/.local/bin/sanctuary-nscde-launch :shebang "#!/usr/bin/env bash"
# Launch sanctuary-nscde: Xephyr :96 + NsCDE (FVWM CDE recreation) inside the Guix container.
set -euo pipefail

if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
  cat <<EOF
sanctuary-nscde-launch - launch sanctuary-nscde (Xephyr :96 + NsCDE, FVWM CDE sanctuary)

Usage: sanctuary-nscde-launch

No arguments. Requires a completed sanctuary-nscde-build (session starter
~/.local/share/NsCDE/bin/nscde inside the guest home).
Normally invoked via: sanctuary-enter sanctuary-nscde
EOF
  exit 0
fi

DISPLAY_NUM=":96"
HOST_DISPLAY="${DISPLAY}"
SANCTUARY="sanctuary-nscde"
GUIX_PROFILES="${HOME}/.guix-extra-profiles"

sanctuary-teardown-stale-session "${SANCTUARY}" "${DISPLAY_NUM}"

# Multi-head law: -fullscreen alone spans ALL monitors (bounding box of every
# output); sanctuary-xephyr-geometry restricts to one RandR output on
# multi-head hosts (override with SANCTUARY_XEPHYR_OUTPUT).
mapfile -t XEPHYR_GEOMETRY < <(sanctuary-xephyr-geometry)
Xephyr "${DISPLAY_NUM}" "${XEPHYR_GEOMETRY[@]}" -br -ac -glamor -no-host-grab &
XEPHYR_PID=$!
trap "kill ${XEPHYR_PID} 2>/dev/null || true" EXIT

timeout 10 sh -c "until DISPLAY=${DISPLAY_NUM} xdpyinfo >/dev/null 2>&1; do sleep 0.1; done" \
  || { echo "Xephyr ${DISPLAY_NUM} did not become ready"; kill "${XEPHYR_PID}"; exit 1; }

sanctuary-xephyr-place "${DISPLAY_NUM}" "${HOST_DISPLAY}" "${SANCTUARY}"

# Colemak-NEIO law: the nested X server comes up on stock us(qwerty). Apply
# the host layout and guard it (fleet pattern from sanctuary-godzilla-xs-launch:
# in-room tools can reset the map, so a 2s watcher re-applies on drift).
# /usr/bin/setxkbmap: host X utility by absolute path (sanctuary-gotchas).
_nscde_apply_colemak() {
  DISPLAY="${DISPLAY_NUM}" /usr/bin/setxkbmap -layout us -variant colemak -option terminate:ctrl_alt_bksp
}
_nscde_apply_colemak
(
  while kill -0 "${XEPHYR_PID}" 2>/dev/null; do
    _kb="$(DISPLAY="${DISPLAY_NUM}" /usr/bin/setxkbmap -query 2>/dev/null || true)"
    grep -qx 'variant:[[:space:]]*colemak' <<<"${_kb}" || _nscde_apply_colemak 2>/dev/null || true
    sleep 2
  done
) &
KEYMAP_GUARD_PID=$!

sanctuary-clip-bridge "${HOST_DISPLAY}" "${DISPLAY_NUM}" &
CLIP_BRIDGE_PID=$!
trap "kill ${XEPHYR_PID} ${CLIP_BRIDGE_PID} ${KEYMAP_GUARD_PID} 2>/dev/null || true" EXIT

# ── Shield trash:/// from host fleet NFS mounts (see sanctuary-trash-shield) ──
sanctuary-trash-shield "${SANCTUARY}" "${HOME}"

# Host session bus, projected as a FILE for runtime consumers (fleet pattern
# from sanctuary-godzilla-xs-launch): the session below runs under its own
# dbus-run-session bus, so anything that genuinely needs the HOST bus reads
# it from here. Refreshed every launch — the address changes per host login.
GUEST_HOME="${HOME}/.local/share/dotcortex/guests/${SANCTUARY}/home"
mkdir -p "${GUEST_HOME}/.config/sanctuary"
printf '%s\n' "${DBUS_SESSION_BUS_ADDRESS:-}" > "${GUEST_HOME}/.config/sanctuary/host-session-bus"

# Small projection helpers for room-owned, token-free defaults.  The guest
# home is bind-mounted at the same absolute host path, so read-only theme
# assets can be linked while mutable toolkit defaults are copied into place.
project_file() {
  local src="$1" dst="$2"
  [[ -f "${src}" ]] || { echo "${SANCTUARY}: missing projected file: ${src}" >&2; return 1; }
  mkdir -p "$(dirname "${dst}")"
  cp "${src}" "${dst}"
}
project_link() {
  local src="$1" dst="$2"
  [[ -d "${src}" ]] || { echo "${SANCTUARY}: missing projected directory: ${src}" >&2; return 1; }
  if [[ -e "${dst}" && ! -L "${dst}" ]]; then
    echo "${SANCTUARY}: refusing to replace non-symlink projected path: ${dst}" >&2
    return 1
  fi
  mkdir -p "$(dirname "${dst}")"
  ln -sfnT "${src}" "${dst}"
}

# Qt5/Qt6 + Kvantum commonality: the visual contract is the same one Redstone

project_file "${NSCDE_QT_ROOT}/qt6ct/qt6ct.conf" "${GUEST_HOME}/.config/qt6ct/qt6ct.conf"
project_file "${NSCDE_QT_ROOT}/qt/commonality.conf" "${GUEST_HOME}/.config/qt5ct/colors/commonality.conf"
project_file "${NSCDE_QT_ROOT}/qt/commonality.conf" "${GUEST_HOME}/.config/qt6ct/colors/commonality.conf"
sed -i "s|@GUEST_QT5CT_COLORS@|${GUEST_HOME}/.config/qt5ct/colors/commonality.conf|g" "${GUEST_HOME}/.config/qt5ct/qt5ct.conf"
sed -i "s|@GUEST_QT6CT_COLORS@|${GUEST_HOME}/.config/qt6ct/colors/commonality.conf|g" "${GUEST_HOME}/.config/qt6ct/qt6ct.conf"

# not provide a gtk-4.0 directory.  CDE-Broica is the matching static theme
# for NsCDE's current Broica palette (#999999 face, #eda870 selection).
mkdir -p "${GUEST_HOME}/.config/gtk-4.0" "${GUEST_HOME}/.local/share/themes"

  "${GUEST_HOME}/.local/share/themes/CDE-Broica"
project_file "${NSCDE_QT_ROOT}/gtk4/settings.ini" \
  "${GUEST_HOME}/.config/gtk-4.0/settings.ini"

if [[ ! -f "${KVANTUM_CONFIG}" ]] || grep -Eq '^theme[[:space:]]*=[[:space:]]*NsCDE[[:space:]]*$' "${KVANTUM_CONFIG}"; then

[General]

# A rootless Xephyr room cannot provide a trustworthy PAM unlock boundary:
# xscreensaver-auth cannot be setuid root and the container has no
# /etc/pam.d/xscreensaver.  Keep the saver/blanking behavior, but disable its
# password lock and leave actual session security to the host display lock.
# This is an intentional room policy, so repair an upstream/default True on
# every launch while preserving any already-disabled setting.
NSCDE_XSCREENSAVER_CONFIG="${GUEST_HOME}/.xscreensaver"
if [[ -f "${NSCDE_XSCREENSAVER_CONFIG}" ]]; then
  if grep -Eq '^[[:space:]]*lock:[[:space:]]*True([[:space:]]*)$' "${NSCDE_XSCREENSAVER_CONFIG}"; then
    sed -E -i 's/^([[:space:]]*lock:[[:space:]]*)True([[:space:]]*)$/\1False\2/' "${NSCDE_XSCREENSAVER_CONFIG}"
  elif ! grep -Eq '^[[:space:]]*lock:' "${NSCDE_XSCREENSAVER_CONFIG}"; then
    printf 'lock:\t\tFalse\n' >> "${NSCDE_XSCREENSAVER_CONFIG}"
  fi
else
  printf '%s\n' '# NsCDE rootless-room policy: host owns session locking.' > "${NSCDE_XSCREENSAVER_CONFIG}"
  printf 'lock:\t\tFalse\n' >> "${NSCDE_XSCREENSAVER_CONFIG}"
fi

# Application Manager invokes most desktop entries by name.  Keep Qt5 as the
# room default, then shadow every known Qt6 member with a tiny profile-pinned
# wrapper so both QPA generations get their own platformtheme plugin.  The
# wrappers are regenerated each launch and contain no mutable app state.
mkdir -p "${GUEST_HOME}/.local/bin"
make_qt_wrapper() {
  local name="$1" qt="$2"
  local wrapper="${GUEST_HOME}/.local/bin/${name}"
  cat > "${wrapper}" <<EOF
#!/bin/sh
export QT_QPA_PLATFORMTHEME=qt${qt}ct
export QT_PLUGIN_PATH="${NSCDE_QT_PROFILE}/lib/qt${qt}/plugins"
EOF
  if [[ "${qt}" == 6 ]]; then
    cat >> "${wrapper}" <<EOF
export QT_STYLE_OVERRIDE=kvantum
export QML_IMPORT_PATH="${NSCDE_QT_PROFILE}/lib/qt6/qml"
export QML2_IMPORT_PATH="${NSCDE_QT_PROFILE}/lib/qt6/qml"
EOF
  else
    printf '%s\n' 'export QT_STYLE_OVERRIDE=kvantum' >> "${wrapper}"
  fi
  printf 'exec %q "$@"\n' "${NSCDE_QT_PROFILE}/bin/${name}" >> "${wrapper}"
  chmod 0755 "${wrapper}"
}
make_qt_wrapper qt5ct 5
make_qt_wrapper qt6ct 6
QT6_APPS=(
  gcompris-qt ktuberling kmahjongg kshisen kpat kreversi bovo kfourinline
  ksquares knights kigo kajongg lskat katomic klines kmines picmi kblocks
  kbounce kbreakout
)
for _qt6_app in "${QT6_APPS[@]}"; do
  make_qt_wrapper "${_qt6_app}" 6
done

# Guix desktop files use absolute store paths in Exec=, so PATH shadowing does
# not reach the wrappers above.  Project user-owned copies of the affected
# entries and rewrite only the executable token to the Qt6 wrapper.  This is
# generated at launch, stays outside the public profile, and lets the
# Application Manager keep using the package-provided names/categories/icons.
QT6_DESKTOP_DIR="${GUEST_HOME}/.local/share/applications"
mkdir -p "${QT6_DESKTOP_DIR}"
for _qt6_app in qt6ct "${QT6_APPS[@]}"; do
  while IFS= read -r _desktop; do
    [[ -f "${_desktop}" ]] || continue
    if grep -Eq "^Exec=[^[:space:]]*/bin/${_qt6_app}([[:space:]]|$)" "${_desktop}"; then
      _desktop_copy="${QT6_DESKTOP_DIR}/$(basename "${_desktop}")"
      _desktop_tmp="$(mktemp "${QT6_DESKTOP_DIR}/.qt6-desktop.XXXXXX")"
      cp "${_desktop}" "${_desktop_tmp}"
      sed -E -i \
        "s#^Exec=[^[:space:]]*/bin/${_qt6_app}([[:space:]]|$)#Exec=${GUEST_HOME}/.local/bin/${_qt6_app}\1#" \
        "${_desktop_tmp}"
      chmod 0644 "${_desktop_tmp}"
      mv -f "${_desktop_tmp}" "${_desktop_copy}"
    fi
  done < <(find -L "${NSCDE_QT_PROFILE}/share/applications" -maxdepth 1 -type f -name '*.desktop' -print)
done

# Diet Netscape Firefox chrome (fleet pattern from sanctuary-godzilla-xs-launch):
# seed the themed wrapper into the guest home's ~/.local/bin so an in-room
# "firefox" resolves to it — the raw Guix profile binary is the unbranded
# ("Nightly") build with a virgin profile. The inner session PATH below puts
# ~/.local/bin ahead of the profile bins to make this stick.
if [[ -f "${HOME}/DotCortex/linux/.local/bin/firefox" ]]; then
  mkdir -p "${GUEST_HOME}/.local/bin"
  ln -sfnT "${HOME}/DotCortex/linux/.local/bin/firefox" "${GUEST_HOME}/.local/bin/firefox"
fi

# NsCDE hardcodes "xrdb -cpp /usr/bin/cpp" throughout (bin/nscde, ColorMgr,
# Functions.fvwmconf); the Guix container has no /usr/bin/cpp. Project the
# profile's cpp there via container root (uid 0 = host user in rootless
# Podman user ns — same pattern as sanctuary-cde-launch's fixups). Idempotent;
# the container layer is disposable so this re-runs every launch.
podman start "${SANCTUARY}" 2>/dev/null || true
podman exec --user 0 "${SANCTUARY}" ln -sf \
  "${GUIX_PROFILES}/sanctuary-nscde/sanctuary-nscde/bin/cpp" /usr/bin/cpp 2>/dev/null || true
# fvwm-menu-desktop (used by NsCDE's Application Manager) follows the
# conventional absolute XDG menu path.  The Guix profile owns the real menu
# tree, so project just that directory into the disposable container layer;
# this keeps menu discovery inside the guest without copying mutable state.
podman exec --user 0 "${SANCTUARY}" sh -c \
  "mkdir -p /etc/xdg && ln -sfn \\
    '${GUIX_PROFILES}/sanctuary-nscde/sanctuary-nscde/etc/xdg/menus' \\
    /etc/xdg/menus" 2>/dev/null || true
# Qt/KDE applications need the standard D-Bus machine identity.  The base
# image intentionally has no mutable system identity, so expose the host
# identity through the container's /run/host mount in the same narrow form as
# the Flatpak runner; this is only a disposable runtime projection.
podman exec --user 0 "${SANCTUARY}" sh -c \
  "if [ ! -e /var/lib/dbus/machine-id ] && [ -r /run/host/var/lib/dbus/machine-id ]; then \\
     mkdir -p /var/lib/dbus && ln -sfn /run/host/var/lib/dbus/machine-id /var/lib/dbus/machine-id; \\
   fi; \\
   if [ ! -e /etc/machine-id ] && [ -r /var/lib/dbus/machine-id ]; then \\
     ln -sfn /var/lib/dbus/machine-id /etc/machine-id; \\
   fi" 2>/dev/null || true

echo "${SANCTUARY}: Xephyr ${DISPLAY_NUM} ready — sourcing Guix profiles and starting NsCDE…"
DISPLAY="${DISPLAY_NUM}" sanctuary-exec "${SANCTUARY}" sh -c "
  GUIX_PROFILE=${GUIX_PROFILES}/desktop-common/desktop-common
  . \${GUIX_PROFILE}/etc/profile
  GUIX_PROFILE=${GUIX_PROFILES}/sanctuary-nscde/sanctuary-nscde
  . \${GUIX_PROFILE}/etc/profile
  # Guest ~/.local/bin FIRST (godzilla pattern): the Diet Netscape firefox
  # wrapper must shadow the raw profile firefox for NsCDE's appfinder.
  export PATH=\${HOME}/.local/bin:\${HOME}/.local/share/NsCDE/bin:\${HOME}/.local/share/nscde-deps/bin:\${PATH}
  # Qt5 is the NsCDE-native default; the generated Qt6 wrappers above replace
  # it only for known KF6/QML applications. Both use the profile's native
  # Kvantum plugin and the same Commonality theme.
  export QT_QPA_PLATFORMTHEME=qt5ct
  export QT_PLUGIN_PATH=${GUIX_PROFILES}/sanctuary-nscde/sanctuary-nscde/lib/qt5/plugins
  export QT_STYLE_OVERRIDE=kvantum
  export SHELL=\$(command -v bash 2>/dev/null || echo /bin/bash)
  # Suppress the at-spi2 accessibility bridge: each GTK app launched inside
  # dbus-run-session otherwise spawns its own at-spi2 bus daemon (fleet
  # lesson from sanctuary-godzilla-xs: 1 unreaped inotify instance each,
  # saturates max_user_instances=128).
  export NO_AT_BRIDGE=1
  # Private session bus (fleet pattern): without it the HOST bus address
  # leaks in and single-instance apps (GIMP, Firefox, LibreOffice) rendezvous
  # with the host's running instances instead of opening in the room.
  if [ -x \${HOME}/.local/share/NsCDE/bin/nscde ]; then
    exec dbus-run-session -- \${HOME}/.local/share/NsCDE/bin/nscde
  fi
  echo 'nscde not found — run sanctuary-nscde-build first.' >&2
  exec dbus-run-session -- xterm -title 'sanctuary-nscde: run sanctuary-nscde-build first'
"

kill "${XEPHYR_PID}" 2>/dev/null || true
