* Why

Honey's Hermes (Aura's runtime) was a hand-built venv plus hand-applied local patches in =~/.hermes/hermes-agent=. A Hermes upgrade wipes those patches, so every upgrade had to be re-derived by hand. This module makes the install reproducible: the pinned sources, the interpreter, the extras, the carried packages and the ordered patch set are files in this repo, and one script builds the staged trees from them. Written 2026-11-06 for the Hermes 0.20.5 to target upgrade (Tiago's requirement: "built to DotCortex, durable and reproducible").

PUBLIC AND NON-SECRET ONLY. Nothing here reads or stores auth files, tokens, =.env=, =config.yaml=, the state databases, logs or clinical material. Those stay in =~/.hermes= and are only ever copied as opaque files by the backup script, into a root-only directory outside this repo.

Everything tangles into =deploy/honey-hermes/= (not an overlay directory: it is never stowed). Nothing is deployed by tangling. Deployment is the explicit, gated procedure below.

* Pinned spec

=build-spec.env= is the single pin file. The agent and WebUI sources are local commits on kikin (the agent commit is not on public GitHub), so the pin is the commit plus a tree digest that =hermes-stage= re-checks after =git archive=: the build aborts if the bytes differ. The production Python is 3.14.7: the target =uv.lock= supports only python >= 3.14 (a 3.11 build was tried and refused by uv), so the pre-upgrade 3.11 venv cannot be reproduced. Voice was proven on it (Piper Amy synthesis then faster-whisper base transcription, exact match).

* Stage: build from the spec

=hermes-stage= runs as =gille=. It fetches both pinned trees from kikin, verifies the digests, makes a baseline commit, applies the ordered patches, then builds the venv at its FINAL path inside a private mount namespace (=hermes-stage-venv=, root via sudo) so the live tree is never touched. It uses the target's own PM builder against the target =uv.lock=, then installs the carried pins and import-checks the gateway, voice, Telegram, Google, pdf and uvloop. It is idempotent: a stage whose recorded spec digest matches is left alone; otherwise =REBUILD=1= moves the old stage aside.

#+BEGIN_SRC bash :tangle deploy/honey-hermes/hermes-stage :tangle-mode (identity #o755)
#!/bin/bash
# hermes-stage: build the staged Hermes + WebUI trees for Honey from build-spec.env. Run as gille (not root).
# Idempotent: a stage whose recorded spec digest matches is left alone; otherwise REBUILD=1 moves it aside first.
set -euo pipefail
D=$(cd "$(dirname "$0")" && pwd); . "$D/build-spec.env"
: "${HH:=/home/gille/.hermes}" "${WS:=/home/gille/src}" "${CACHE:=/var/tmp/hermes-stage-cache}" "${BH:=/tmp/hermes-stage-home}"
SA=$HH/hermes-agent.staged; SW=$WS/hermes-webui.staged
die(){ echo "ABORT: $*" >&2; exit 1; }
[ "$(id -u)" != 0 ] || die "run as the gille user; root is used only through sudo for the mount namespace"
tree_digest(){ ( cd "$1" && find . -type f -not -path './.git/*' -not -path './venv/*' -print0 | sort -z | xargs -0 sha256sum | sha256sum | cut -c1-64 ); }
spec_digest(){ ( cd "$D" && cat build-spec.env carried-pins.txt $(for p in $PATCHES_AGENT $PATCHES_WEBUI; do echo patches/$p; done) | sha256sum | cut -c1-64 ); }
fetch(){ # host repo commit expect dest
  mkdir -p "$5"; ssh "$1" "git -C $2 archive --format=tar $3" | tar -x -C "$5"
  got=$(tree_digest "$5"); [ "$got" = "$4" ] || die "archive tree digest mismatch for $3: $got != $4"; }

* Deploy: backup, swap, rollback

The order is fixed and gated; nothing here is run by tangling.

1. =backup-phaseA.sh= (hot, root): code, venv, WebUI, OpenRC scripts, the original =hermes= launcher, revisions, diffs and freeze into =/var/lib/hermes-upgrade/backups/=. It contains no config, auth, state or logs.
2. Drain the gateway with =gateway.drain_control.write_drain_request= (the function behind =POST /api/gateway/drain=; the dashboard server is not running on Honey), poll =gateway_state.json= for =draining= and =active_agents= 0, then =rc-service hermes-webui stop= and =rc-service hermes-gateway stop= without SIGKILL escalation. Never =hermes gateway restart=, never a second gateway.
3. =phaseB-backup.sh= (requires both services stopped) snapshots the opaque Hermes home state as root-only.
4. =go-live.sh= swaps by rename; the old trees are kept as =*.pre-upgrade=. Then clear the drain marker with =gateway.drain_control.clear_drain_request= from the new tree.
5. =hermes-launchers= (root, before any start): rewrites the =hermes= launcher and adds =HERMES_DISABLE_LAZY_INSTALLS=1= to both OpenRC scripts (see the next section).
6. Start gateway, then WebUI, through OpenRC, and run the acceptance checks.
7. =rollback.sh [--restore-state]= renames the trees back (requires services stopped), restores the original launcher and OpenRC scripts from phase A, and optionally restores the phase B snapshot.

* Why launch-time sync is disabled

The target's =hermes_bootstrap= runs a "source-update completion" at launch whenever PM has no recorded venv facts for the tree: it syncs dependencies, builds node, the TUI and the web UI, refreshes the store under =~/.hermes/installs/<hash>=, then relaunches into a store interpreter. A venv built by =hermes-stage= has no PM facts, so on 2026-11-06 the first WebUI start ran that whole tail and the relaunch broke its imports (=No module named api=). The in-tree venv was not altered, but a sync could also prune the carried clinical pins and voice extras. =HERMES_DISABLE_LAZY_INSTALLS=1= makes every launch skip it. It also stops the target rewriting =~/.local/bin/hermes=. Lazy installs are off by design here: every needed extra is pinned in the spec. Also: the stage script runs =ln= and =sed= on the venv as gille, because the target refuses to update a tree whose =venv/bin/python= is root-owned.

#!/bin/bash
# Root. Run after go-live.sh and BEFORE starting services. Idempotent.
# The target's hermes_bootstrap does a launch-time source-update completion (dependency sync, node/TUI/web build, relaunch into a

# the WebUI imports on 2026-11-06. HERMES_DISABLE_LAZY_INSTALLS=1 makes every launch skip that step, so nothing can re-resolve or
