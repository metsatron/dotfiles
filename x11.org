* AppMenu registrar bootstrap
#+BEGIN_SRC sh :tangle linux/.xsessionrc.d/30-appmenu-registrar.sh :shebang "#!/usr/bin/env sh"
# Start the registrar inside the real X session so exported menus and the
# panel plugin meet on the same session bus.
#
# IMPORTANT: this runs at Xsession step 40 (xsessionrc), before D-Bus is
# created at step 75 (dbus-launch). Without a live session bus the registrar
# cannot connect and silently exits. The boot autostart (appmenu-boot.desktop)
# handles the common case; this snippet is a belt-and-suspenders fallback for
# display managers that start D-Bus before running Xsession (e.g. systemd/GDM).
[ -n "${DBUS_SESSION_BUS_ADDRESS:-}" ] || return 0

registrar_has_owner() {
  command -v gdbus >/dev/null 2>&1 || return 1
  gdbus call --session \
    --dest org.freedesktop.DBus \
    --object-path /org/freedesktop/DBus \
    --method org.freedesktop.DBus.NameHasOwner \
    com.canonical.AppMenu.Registrar 2>/dev/null | grep -q '(true,'
}

APPMENU_REGISTRAR=
if ! registrar_has_owner; then
  pkill -x appmenu-registr >/dev/null 2>&1 || true
  pkill -x appmenu-registrar >/dev/null 2>&1 || true

  if command -v appmenu-registrar >/dev/null 2>&1; then
    APPMENU_REGISTRAR="$(command -v appmenu-registrar)"
  elif [ -x /usr/libexec/vala-panel/appmenu-registrar ]; then
    APPMENU_REGISTRAR=/usr/libexec/vala-panel/appmenu-registrar
  fi

  if [ -n "${APPMENU_REGISTRAR}" ]; then
    # `-r` only references an existing primary instance; it cannot start one.
    # Start the primary as the D-Bus service file does, then hold it with `-r`
    # so it does not auto-quit after ~10 s idle.
    nohup "$APPMENU_REGISTRAR" --gapplication-service >/dev/null 2>&1 &
    for _i in 1 2 3 4 5 6; do
      sleep 0.5
      registrar_has_owner && break
    done
    # Foreground, bounded: `-r` returns in milliseconds once a primary owns the
    # name, and its hold is what stops the registrar idle-quitting after ~10 s.
    if registrar_has_owner; then
      timeout 5 "$APPMENU_REGISTRAR" -r >/dev/null 2>&1 || true
    fi
  fi
fi

unset APPMENU_REGISTRAR
#+END_SRC

* GTK4/libadwaita color-scheme (portal Settings)
GTK4 apps built on libadwaita (GNOME Calculator, and similarly-modernized GNOME apps) no longer read XFCE's XSettings theme name at all -- they hardcode Adwaita and only switch light/dark by asking =xdg-desktop-portal='s Settings interface for =org.freedesktop.appearance color-scheme=. =xdg-desktop-portal-gtk= answers that query straight from the GNOME gsettings key =org.gnome.desktop.interface color-scheme=, which nothing on an XFCE session ever sets. Confirmed live via =dbus-monitor= (2026-07-10): the portal call returned =uint32 0= (no-preference), so libadwaita apps rendered light Adwaita regardless of the dark XFCE theme.

This tracks the XFCE XSettings theme name so libadwaita apps follow whatever =/Net/ThemeName= is currently set to, rather than hardcoding a value independent of theme switches.

#+BEGIN_SRC sh :tangle linux/.xsessionrc.d/35-gtk-color-scheme.sh :shebang "#!/usr/bin/env sh"
command -v gsettings >/dev/null 2>&1 || return 0

THEME_NAME=""
if command -v xfconf-query >/dev/null 2>&1; then
  THEME_NAME="$(xfconf-query -c xsettings -p /Net/ThemeName 2>/dev/null)"
fi

case "${THEME_NAME}" in
  *[Dd]ark*) SCHEME=prefer-dark ;;
  *)         SCHEME=default ;;
esac

gsettings set org.gnome.desktop.interface color-scheme "${SCHEME}" 2>/dev/null || true
#+END_SRC

* darkman — color-scheme portal backend (works around xdg-desktop-portal-gtk 1.15.3)
Live investigation (2026-07-10) confirmed the dconf/gsettings side of the previous fix is entirely correct -- =gsettings get org.gnome.desktop.interface color-scheme= reports =prefer-dark=, no gschema override or dconf lock exists, and =gsettings-desktop-schemas= is current (48.0-1). Yet =gdbus call --session --dest org.freedesktop.impl.portal.desktop.gtk ... Settings.Read org.freedesktop.appearance color-scheme= kept returning =uint32 0= even across a full daemon restart. Devuan excalibur only carries =xdg-desktop-portal-gtk 1.15.3-1=, sitting in a known regression window (other users reported needing to pin/downgrade for reliable color-scheme reads). No newer/older version is available without adding another apt suite.

=darkman= (packaged in Guix, no Debian/Devuan apt package exists) runs its own =org.freedesktop.impl.portal.desktop.darkman= D-Bus service implementing the Settings portal interface directly from its own internal light/dark state -- it does not depend on =xdg-desktop-portal-gtk= at all, sidestepping the bug entirely. =portals.conf= tells the frontend dispatcher to route the =Settings= interface specifically to darkman; every other portal interface (file chooser, screenshot, etc.) is untouched and still served by =xdg-desktop-portal-gtk= as before.

Automatic sunrise/sunset transitions require a configured location (=lat=/=lng= or geoclue); leaving both unset (the default, no =config.yaml= needed) disables automatic transitions entirely, and darkman just holds whatever mode was last set -- it persists the mode to a cache file and restores it on restart, so =darkman set dark= only needs to be run once, ever, after first install.

* Session PATH: ~/.local/bin
=xfce4-session= launches XDG autostart entries with the PATH it inherits from Xsession. That PATH never contained =~/.local/bin=, so every autostart entry naming a stowed helper by bare command name died at login with =Failed to execute child process ... (No such file or directory)= -- =appmenu-boot-setup= (the global-menu registrar bootstrap), =clipmenud-start=, =xfce-sanctuary-shortcuts=, =plank=, =twistpatch=. The failure is silent unless you read =~/.xsession-errors=, and the usual symptom is "the fix works when I run it by hand but never survives a reboot" -- because an interactive shell *does* have =~/.local/bin= on PATH.

Numbered =40= so it runs *after* =20-guix-core-profile.sh=. Guix prepends its profile, so prepending here afterwards leaves =~/.local/bin= ahead of Guix -- the ordering =guix.org= already relies on for the =python3= shim that keeps =#!/usr/bin/env python3= off Guix's tkinter-less interpreter. Nine names now resolve to =~/.local/bin= for GUI-launched processes (=python3=, =pip3=, =node=, =npm=, =npx=, =corepack=, =f2py=, =isympy=, =numpy-config=); all nine already resolved that way in interactive shells, so this makes the session agree with the shell rather than diverge from it.

#+BEGIN_SRC sh :tangle linux/.xsessionrc.d/40-local-bin.sh :shebang "#!/usr/bin/env sh"
# Put ~/.local/bin on the session PATH so XDG autostart entries can name stowed
# helpers by bare command name. Idempotent: re-sourcing must not duplicate.
case ":${PATH}:" in
  *":$HOME/.local/bin:"*) ;;
  *) PATH="$HOME/.local/bin:$PATH" ;;
esac
export PATH
#+END_SRC

* KWin X11 compositing on XLibre — modesetting smear, fixed by KWIN_OPENGL_INTERFACE=egl (not the DDX)
XLibre's =modesetting= DDX corrupts KWin OpenGL compositing on this machine: stale framebuffer content smears across Plasma panels and menus, popups render as garbage, and icons freeze in stale positions (worst while hovering the task manager). Upstream family: X11Libre/xserver#1924 ("Corrupted windows when hovering task manager in KDE"); filed against the Intel DDX as xlibre-artix/xlibre-video-intel#2.

Bisected live 2026-07-04, one variable at a time with everything else held constant (XLibre 25.2.0, Mesa 25.0.7 =iris=, KWin/Plasma 6.3.6): with KWin GL compositing ON the =modesetting= DDX smears, while =xf86-video-intel= (SNA) renders completely clean. So the fault is modesetting-DDX-specific — its Present/damage/flip path under KWin's compositor — not KWin window management and not xf86-video-intel. This corrects the earlier "purely KWin's GL compositing path" conclusion. Escalations that did NOT fix it on modesetting: =KWIN_USE_BUFFER_AGE=0= (reduced, never cleared the smear) and modesetting =Option "TearFree" "false"= (no effect).

SUPERSEDED 2026-07-09. The =xf86-video-intel= DDX never fixed the smear — it made the smear *impossible* by silently disabling hardware GL, and software rendering cannot exhibit a hardware Present/damage bug. =intel_drv.so= requests the classic =i965= DRI driver, which Mesa 25 removed (only the gallium =iris=/=crocus= survive), so =/var/log/Xorg.0.log= shows =(EE) AIGLX error: unable to load driver i965= followed by =(II) GLX: Initialized DRISWRAST GL provider for screen 0=. The whole X session consequently ran on llvmpipe: =glxinfo= reported =renderer: llvmpipe= and =Accelerated: no=, kitty burned ~400% CPU across eight =llvmpipe-N= software-rasteriser threads drawing the terminal, and kwin_x11 measured 192.8% — together five of eight threads on an i5-8350U. The GPU was healthy throughout: an offscreen EGL probe on the render node returns =Mesa Intel(R) UHD Graphics 620 (KBL GT2)=, OpenGL 4.6. Neither escape hatch works while this DDX is loaded — symlinking =i965_dri.so -> libdril_dri.so= fails because =libdril_dri.so= exports no =__driDriverGetExtensions_i965=, and EGL-on-X11 falls back to llvmpipe as well.

RESOLVED 2026-07-09, verified on the live session. Disabled the machine-local =/etc/X11/xorg.conf.d/20-intel-ddx.conf= (renamed to =.disabled=; a SYSTEM file, not stowable — stow targets =$HOME= only, see the T480 SystemCodex ledger) so the builtin =modesetting= DDX takes over, and set =KWIN_OPENGL_INTERFACE=egl= in the Plasma env. After =sudo service sddm restart=, =/var/log/Xorg.0.log= reads =(II) glamor: DRI3 X acceleration enabled on Mesa Intel(R) UHD Graphics 620 (KBL GT2)= and =(II) GLX: Initialized glamor GL provider for screen 0= (was =DRISWRAST=), =glxinfo= reports =renderer: Mesa Intel(R) UHD Graphics 620= with =Accelerated: yes=, and the smear is gone. So the real fix is EGL, not the DDX: the corruption lives in KWin's GLX/AIGLX Present path, and bypassing it at the GL interface keeps hardware acceleration instead of trading it away. Measured before → after: kwin_x11 192.8% → 0.2%, kitty 311–411% (eight =llvmpipe-N= software-rasteriser threads) → 1.8%, load average 11–12 → ~2.2.

=KWIN_USE_BUFFER_AGE=0= is dropped: it forced full-screen repaints costing ~1.9 cores and, under software rendering, was mitigating a bug that could not occur. Recovery if the smear ever returns: restore =20-intel-ddx.conf= and =sudo service sddm restart= (clean but software-rendered), or stay on modesetting and set =kwinrc [Compositing] Enabled=false= to keep hardware GL without GL compositing. Gotcha: =service sddm restart= does not reliably reap the old session — an orphaned =plasmashell= survived it and span at 98% CPU on a dead X connection, holding a zombie kitty child; after any restart, check for pre-restart PIDs (=ps -o etimes=) and =SIGTERM= the strays. T480-only: this is the machine running XLibre + SonicDE; x230/t480s keep their working Xorg compositors.

* T480s DeskFlow Moonlight guard
#+BEGIN_SRC bash :tangle t480s/.local/bin/deskflow-moonlight-guard :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
set -euo pipefail

INTERVAL="${DESKFLOW_MOONLIGHT_GUARD_INTERVAL:-0.25}"
RESUME_MISSES="${DESKFLOW_MOONLIGHT_GUARD_RESUME_MISSES:-8}"
LOG_FILE="${DESKFLOW_MOONLIGHT_GUARD_LOG:-$HOME/.cache/deskflow-moonlight-guard.log}"
STATE="resumed"
MISSES=0

usage() {
  cat <<'EOF'
deskflow-moonlight-guard

Pauses DeskFlow while Moonlight is the active X11 foreground window.
Requires several consecutive non-Moonlight samples before resuming, because
Moonlight can briefly expose blank or root-ish active-window data while it owns
the input grab.

Commands:
  --once      Print whether Moonlight is the active window, then exit
  --debug     Print active-window and DeskFlow detection details, then exit
  --resume    Resume any stopped DeskFlow process and exit
  --help      Show this help

Emergency resume:
  deskflow-moonlight-guard --resume
  pkill -CONT -x deskflow
  pkill -CONT -x deskflow-core
  pkill -CONT -x deskflow-server
EOF
}

log() {
  mkdir -p "$(dirname "$LOG_FILE")"
  printf '%s %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$*" >>"$LOG_FILE"
}

require_x11() {
  [ -n "${DISPLAY:-}" ] || return 1

  case "${XDG_SESSION_TYPE:-x11}" in
    x11|"") return 0 ;;
    *) return 1 ;;
  esac
}

deskflow_pids() {
  {
    pgrep -u "$USER" -x deskflow || true
    pgrep -u "$USER" -x .deskflow-real || true
    pgrep -u "$USER" -x deskflow-core || true
    pgrep -u "$USER" -x deskflow-server || true
    pgrep -u "$USER" -f '(^|[ /])deskflow($| )' || true
  } | sort -u
}

active_window_details() {
  local wid class title pid args

  if ! require_x11; then
    printf 'x11=unavailable DISPLAY=%s XDG_SESSION_TYPE=%s\n' "${DISPLAY:-}" "${XDG_SESSION_TYPE:-}"
    return 1
  fi

  if ! command -v xdotool >/dev/null 2>&1; then
    printf 'xdotool=missing\n'
    return 1
  fi

  wid="$(xdotool getactivewindow 2>/dev/null || true)"
  if [ -z "$wid" ]; then
    printf 'active_window=unavailable DISPLAY=%s\n' "${DISPLAY:-}"
    return 1
  fi

  class="$(xdotool getwindowclassname "$wid" 2>/dev/null || true)"
  title="$(xdotool getwindowname "$wid" 2>/dev/null || true)"
  pid="$(xdotool getwindowpid "$wid" 2>/dev/null || true)"
  args=""
  if [ -n "$pid" ]; then
    args="$(ps -p "$pid" -o args= 2>/dev/null || true)"
  fi

  printf 'wid=%s\nclass=%s\ntitle=%s\npid=%s\nargs=%s\n' "$wid" "$class" "$title" "$pid" "$args"
}

moonlight_active() {
  local wid class title pid args

  require_x11 || return 1
  command -v xdotool >/dev/null 2>&1 || return 1

  wid="$(xdotool getactivewindow 2>/dev/null || true)"
  [ -n "$wid" ] || return 1

  class="$(xdotool getwindowclassname "$wid" 2>/dev/null || true)"
  title="$(xdotool getwindowname "$wid" 2>/dev/null || true)"
  pid="$(xdotool getwindowpid "$wid" 2>/dev/null || true)"

  args=""
  if [ -n "$pid" ]; then
    args="$(ps -p "$pid" -o args= 2>/dev/null || true)"
  fi

  printf '%s\n%s\n%s\n' "$class" "$title" "$args" \
    | grep -Eiq 'moonlight|com\.moonlight_stream\.Moonlight'
}

pause_deskflow() {
  local pids

  pids="$(deskflow_pids)"
  [ -n "$pids" ] || return 0

  echo "$pids" | xargs -r kill -STOP
  STATE="paused"
  log "paused DeskFlow pids: $(echo "$pids" | tr '\n' ' ')"
}

resume_deskflow() {
  local pids

  pids="$(deskflow_pids)"
  [ -n "$pids" ] || return 0

  echo "$pids" | xargs -r kill -CONT
  STATE="resumed"
  log "resumed DeskFlow pids: $(echo "$pids" | tr '\n' ' ')"
}

case "${1-}" in
  --once)
    if moonlight_active; then
      echo "moonlight-active"
    else
      echo "moonlight-inactive"
    fi
    exit 0
    ;;
  --debug)
    active_window_details || true
    printf 'deskflow_pids=%s\n' "$(deskflow_pids | tr '\n' ' ')"
    if moonlight_active; then
      echo "moonlight-active"
    else
      echo "moonlight-inactive"
    fi
    exit 0
    ;;
  --resume)
    resume_deskflow
    exit 0
    ;;
  --help|-h)
    usage
    exit 0
    ;;
  "")
    ;;
  *)
    usage >&2
    exit 2
    ;;
esac

if ! require_x11; then
  log "X11 DISPLAY not available; exiting DISPLAY=${DISPLAY:-} XDG_SESSION_TYPE=${XDG_SESSION_TYPE:-}"
  exit 0
fi

if ! command -v xdotool >/dev/null 2>&1; then
  log "xdotool not found; exiting"
  exit 0
fi

trap resume_deskflow EXIT
trap 'resume_deskflow; exit 0' INT TERM

log "started DISPLAY=${DISPLAY:-} XDG_SESSION_TYPE=${XDG_SESSION_TYPE:-} interval=$INTERVAL resume_misses=$RESUME_MISSES"

while true; do
  if moonlight_active; then
    MISSES=0
    [ "$STATE" = "paused" ] || pause_deskflow
  else
    if [ "$STATE" = "paused" ]; then
      MISSES=$((MISSES + 1))
      if [ "$MISSES" -ge "$RESUME_MISSES" ]; then
        resume_deskflow
        MISSES=0
      fi
    else
      MISSES=0
    fi
  fi

  sleep "$INTERVAL"
done
#+END_SRC

* T480 Deskflow enter command

Releases all stuck modifier keys when Deskflow focus enters the T480.

Standard =xdotool keyup= only targets the primary keycode per keysym. On T480,
Super_L and Hyper_L have secondary keycodes (206/207) from extra xmodmap entries
that Deskflow can leave stuck. This script:
1. Releases common modifier keysyms via xdotool
2. Finds and releases any stuck keys in the XTEST virtual keyboard via XTestFakeKeyEvent

#+BEGIN_SRC bash :tangle linux/.local/bin/xfce-appmenu-configure :shebang "#!/usr/bin/env bash"
set -euo pipefail

if ! command -v xfconf-query >/dev/null 2>&1; then

set_bool() {
  local path="$1" value="$2"
  if xfconf-query -c xsettings -p "$path" >/dev/null 2>&1; then
    xfconf-query -c xsettings -p "$path" -t bool -s "$value"
  else
    xfconf-query -c xsettings -p "$path" -n -t bool -s "$value"
  fi
}

set_string() {
  local path="$1" value="$2"
  if xfconf-query -c xsettings -p "$path" >/dev/null 2>&1; then
    xfconf-query -c xsettings -p "$path" -t string -s "$value"
  else
    xfconf-query -c xsettings -p "$path" -n -t string -s "$value"
  fi
}

resolve_registrar() {
  if command -v appmenu-registrar >/dev/null 2>&1; then
    command -v appmenu-registrar
  elif [ -x /usr/libexec/vala-panel/appmenu-registrar ]; then
    printf '%s\n' /usr/libexec/vala-panel/appmenu-registrar
  else
    return 1
  fi
}

set_bool /Gtk/ShellShowsMenubar true
set_bool /Gtk/ShellShowsAppmenu true

gtk_modules="$(xfconf-query -c xsettings -p /Gtk/Modules 2>/dev/null || true)"
case ":${gtk_modules}:" in
  *:appmenu-gtk-module:*) ;;
  *) gtk_modules="${gtk_modules:+$gtk_modules:}appmenu-gtk-module" ;;
esac
set_string /Gtk/Modules "$gtk_modules"

# A D-Bus Ping is NOT a passive probe. `com.canonical.AppMenu.Registrar.service`
# makes the name activatable, so pinging it STARTS a registrar and returns
# success -- then that summoned instance idle-quits ~10 s later because nothing
# holds a reference. Every heal therefore "found a healthy registrar", changed
# nothing, and watched the menu die seconds after the operator looked away.
# Proven on T480s 2026-07-10: ping -> 1 proc at t=0/t=4, 0 procs at t=13.
# `name_has_owner` asks the BUS about ownership instead, and never activates.
name_has_owner() {
  command -v gdbus >/dev/null 2>&1 || return 1
  gdbus call --session \
    --dest org.freedesktop.DBus \
    --object-path /org/freedesktop/DBus \
    --method org.freedesktop.DBus.NameHasOwner \
    com.canonical.AppMenu.Registrar 2>/dev/null | grep -q '(true,'
}

registrar_bin="$(resolve_registrar || true)"

if [[ -n "$registrar_bin" ]]; then
  if ! name_has_owner; then
    # Start the PRIMARY the way the D-Bus service file does. `-r` alone can never
    # start one: per --help it only "references a registrar", and with no primary
    # it blocks forever without claiming the bus name (the old bug on this line).
    pkill -x appmenu-registr >/dev/null 2>&1 || true
    pkill -x appmenu-registrar >/dev/null 2>&1 || true
    nohup "$registrar_bin" --gapplication-service >/dev/null 2>&1 &
    for _i in 1 2 3 4 5 6; do sleep 0.5; name_has_owner && break; done
  fi

  # ALWAYS place a hold, even on a registrar that already owns the name: an
  # activated-but-unreferenced instance is indistinguishable from a held one,
  # and its refcount is zero, so it is ~10 s from death. `-r` only increments a
  # reference -- it NEVER bounces the running registrar, so the menu export of
  # every open window survives (killing/replacing it orphans them permanently,
  # which is what made past heals destroy the global menu).
  # Foreground + `timeout`, because backgrounding drops the reference when this
  # script exits, and a bare `-r` with no primary would block forever.
  if name_has_owner; then
    timeout 5 "$registrar_bin" -r >/dev/null 2>&1 || true
  fi
fi

printf 'Gtk/ShellShowsMenubar=%s\n' "$(xfconf-query -c xsettings -p /Gtk/ShellShowsMenubar 2>/dev/null || echo unset)"
printf 'Gtk/ShellShowsAppmenu=%s\n' "$(xfconf-query -c xsettings -p /Gtk/ShellShowsAppmenu 2>/dev/null || echo unset)"
printf 'Gtk/Modules=%s\n' "$(xfconf-query -c xsettings -p /Gtk/Modules 2>/dev/null || echo unset)"
pgrep -af '[a]ppmenu-registrar' || true

* AppMenu boot autostart (XFCE)
Fixes the D-Bus timing race where =30-appmenu-registrar.sh= runs at Xsession
step 40 before the session bus exists (step 75).  Runs once per session from
XDG autostart; if the registrar is already live it exits immediately.

#+BEGIN_SRC bash :tangle linux/.local/bin/appmenu-boot-setup :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
# appmenu-boot-setup — start registrar and restart panel after session login.
# The xsessionrc.d snippet (30-appmenu-registrar.sh) runs before D-Bus exists,
# so the registrar never joins the session bus on SLiM/Devuan.  We fix it here
# where D-Bus is guaranteed live (XDG autostart runs post-session-init).
set -euo pipefail

registrar_has_owner() {
  command -v gdbus >/dev/null 2>&1 || return 1
  gdbus call --session \
    --dest org.freedesktop.DBus \
    --object-path /org/freedesktop/DBus \
    --method org.freedesktop.DBus.NameHasOwner \
    com.canonical.AppMenu.Registrar 2>/dev/null | grep -q '(true,'
}

# Already on D-Bus — registrar started correctly (e.g. on a systemd/GDM box).
registrar_has_owner && exit 0

# Resolve registrar binary.
APPMENU_REGISTRAR=
if command -v appmenu-registrar >/dev/null 2>&1; then
  APPMENU_REGISTRAR="$(command -v appmenu-registrar)"
elif [ -x /usr/libexec/vala-panel/appmenu-registrar ]; then
  APPMENU_REGISTRAR=/usr/libexec/vala-panel/appmenu-registrar
else
  exit 0
fi

# `pkill -x` matches against /proc/<pid>/comm, which the kernel truncates to 15
# characters -- "appmenu-registrar" is 17, so the full name NEVER matches and the
# stale-registrar sweep silently no-ops. Match the truncated comm as well.
pkill -x appmenu-registr >/dev/null 2>&1 || true
pkill -x appmenu-registrar >/dev/null 2>&1 || true

# `-r` alone can NEVER start a registrar. Per `--help` it means "Reference a
# registrar", i.e. bump the hold count of an already-running primary instance.
# With no primary it blocks without ever claiming the bus name. Start the
# primary the same way the D-Bus service file does, with --gapplication-service.
nohup "$APPMENU_REGISTRAR" --gapplication-service >/dev/null 2>&1 &

# Wait up to 3 s for the registrar to claim its D-Bus name.
for _i in 1 2 3 4 5 6; do
  sleep 0.5
  registrar_has_owner && break
done

# Sync xsettings (idempotent).
if command -v xfce-appmenu-configure >/dev/null 2>&1; then
  xfce-appmenu-configure >/dev/null 2>&1 || true
fi

# Reconnect the panel's appmenu plugin to the now-live registrar. Use the
# panel's own --restart: `pkill` relies on xfce4-session respawning the panel,
# which it does not reliably do, and a killed panel simply stays dead.
xfce4-panel --restart >/dev/null 2>&1 || true
sleep 2

# ORDER MATTERS. A registrar with no references auto-quits ~10 s after its last
# activity, taking every exported menu with it. `-r` adds a hold that prevents
# that: it increments a persistent count and returns in ~15 ms.
#
# It must run *after* the panel restart. Measured on T480s: holding first, then
# restarting the panel, leaves the registrar dead ~10 s later -- the outgoing
# panel's appmenu plugin unreferences the registrar as it exits, cancelling the
# hold. Holding last survives indefinitely.
#
# Foreground, because backgrounding means the reference never lands if this
# script exits first. Bounded by `timeout` because with no primary instance
# running, `-r` blocks forever instead of failing.
hold_registrar() {
  registrar_has_owner || return 1
  timeout 5 "$APPMENU_REGISTRAR" -r >/dev/null 2>&1 || true
  sleep 11
  registrar_has_owner
}

if ! hold_registrar; then
  # Registrar lost its name anyway; bring it back and hold it once more.
  nohup "$APPMENU_REGISTRAR" --gapplication-service >/dev/null 2>&1 &
  for _i in 1 2 3 4 5 6; do
    sleep 0.5
    registrar_has_owner && break
  done
  registrar_has_owner && timeout 5 "$APPMENU_REGISTRAR" -r >/dev/null 2>&1 || true
fi
#+END_SRC

* Virtual Habitat — XFCE workspace shortcuts (T480s)

Keeps workspace switching on the *stock XFCE defaults* — =Ctrl+F1..F4= — each landing on its
dedicated sanctuary desktop. Run once after stow; idempotent.
Also binds the Rofi launcher suite: =Super+space= (drun), =Super+x= (action menu),
=Super+b= (emoji), =Super+z= (clipboard), and relocates the old appfinder launcher
from =Super+space= to =Alt+space= (removing the unused xfwm4 popup-menu binding there).

Workspace switching used to be remapped to =Super+1/2/3/4= here. It is back on the defaults
deliberately: =Ctrl+FN= matches SonicDE on the other machine, so one set of workspace keys now
holds across the fleet. Nothing about the =Super+N= mapping was wrong in itself — it just had
no reason to exist, and it cost six debugging sessions.

*XFWM4 binds exactly one key per action.* The XFCE defaults bind =<Primary>F1..F12= to
=workspace_1..12_key=. Binding =<Super>N= to the same =workspace_N_key= action does not add a
second accelerator — the two properties compete for one slot, and the winner is chosen by
xfconf's *hash enumeration order*, not by XML order or by which was written last. So a
rebinding must *displace*, never merely add; declaring both silently disables one of them.

That was the entire =Super+4= bug. =<Primary>F4= won the =workspace_4_key= slot on every fresh
xfwm4 startup, so =Super+4= was never grabbed at all (verified with =XGrabKey=: the keycode sat
*free*, nobody held it). =Super+1/2/3= happened to win their slots, which made the failure look
key-specific and sent several fixes chasing PATH, regrab races, and workspace counts. Rewriting
=<Super>4= at runtime flips the slot until the next login — which is exactly why the shortcut
"worked when run by hand" and died on every reboot. The same collision had silently killed
=Ctrl+F1/F2/F3= the whole time, despite this file long claiming they were preserved.

So the script still asserts each workspace binding *exclusively*: it removes every other
property bound to =workspace_N_key= before setting the one we want. Now that the wanted key is
the default, this mostly just clears the stale =<Super>N= entries — but it is kept because it is
the only thing standing between this config and a silent re-collision.

#+BEGIN_SRC bash :tangle t480s/.local/bin/xfce-sanctuary-shortcuts :shebang "#!/usr/bin/env bash"
# Workspace switching on the XFCE defaults: Ctrl+F1/F2/F3/F4 → workspace 1/2/3/4 (T480s XFCE).
# Layout: Desktop 1 = normal, Desktop 2/3/4 = sanctuaries (qtile/gnustep/cde).
# Bindings are exclusive, not additive: xfwm4 binds one key per action (see x11.org).
set -euo pipefail

CHANNEL=xfce4-keyboard-shortcuts

if ! command -v xfconf-query >/dev/null 2>&1; then
  echo "xfconf-query not found; XFCE keyboard shortcuts cannot be configured" >&2
  exit 1
fi

# xfwm4 keeps exactly ONE key per action. Two properties carrying the same value (e.g.
# <Primary>F4 and <Super>4 both = workspace_4_key) compete for that single slot, and xfconf's
# hash enumeration order decides the winner on each fresh xfwm4 startup. Drop every rival so
# the binding we want is the only claimant — this is what makes the shortcut survive reboot.
# `local` expands every argument before it assigns any of them, so a later assignment may not
# reference an earlier one on the same line — declare separately or ${n} reads as unbound.
clear_rivals() {
  local n="$1"
  local keep="/xfwm4/custom/<Primary>F${n}"
  local action="workspace_${n}_key"
  local p
  while read -r p; do
    [ -n "${p}" ] || continue
    # `[ x = y ] && continue` returns non-zero when the test fails, which trips `set -e`.
    if [ "${p}" = "${keep}" ]; then continue; fi
    xfconf-query -c "${CHANNEL}" -p "${p}" -r 2>/dev/null || true
    echo "  removed rival: ${p} → ${action}"
  done < <(xfconf-query -c "${CHANNEL}" -l -v 2>/dev/null \
             | awk -v act="${action}" '$1 ~ "^/xfwm4/custom/" && $2 == act { print $1 }')
}

set_shortcut() {
  local n="$1"
  local p="/xfwm4/custom/<Primary>F${n}"
  local action="workspace_${n}_key"
  clear_rivals "${n}"
  if xfconf-query -c "${CHANNEL}" -p "${p}" >/dev/null 2>&1; then
    xfconf-query -c "${CHANNEL}" -p "${p}" -t string -s "${action}"
  else
    xfconf-query -c "${CHANNEL}" -p "${p}" -n -t string -s "${action}"
  fi
  echo "  set: ${p} → ${action}"
}

# Clean up stale entries from previous wrong schemas (xfwm4 channel)
for k in 1 2 3 4; do
  xfconf-query -c xfwm4 -p "/custom/<Super>${k}" -r 2>/dev/null || true
  xfconf-query -c xfwm4 -p "/general/workspace_${k}_key" -r 2>/dev/null || true
done

echo "Configuring Virtual Habitat workspace shortcuts…"
set_shortcut 1
set_shortcut 2
set_shortcut 3
set_shortcut 4
if [ -x "$HOME/.local/bin/kitty" ]; then

else

fi
if [ -x "$HOME/.local/bin/whisper-hotkey" ]; then

if [ -x "$HOME/.local/bin/pclip-toggle" ]; then

* Pclip Toggle (cancel-on-repress)
=Super+v= now goes through this wrapper instead of calling =pclip= directly
(it was previously only live xfconf state — =/commands/custom/<Super>v= set
by hand, never in source — now durable like =Super+c=). First press speaks
the clipboard as before; a second press while it's still talking kills it
instead of queuing/overlapping a second reading — a cancel button. A
notification also fires on first press announcing which voice is about to
speak (e.g. "Speaking with Lessac…"), resolved from the same Speech
Dispatcher =piper.conf= that =pclip default= itself reads.

=pclip='s =--stream= mode is a shell pipeline (Piper piped into
=ffplay=/=aplay=/=paplay=/=pw-play=), so a plain =kill= on the wrapper's own
PID wouldn't reach the actual audio-playing process. The wrapper launches
=pclip= under =setsid= so it becomes its own process-group leader, and
cancels by signaling the whole group (=kill -TERM -PGID=) — that reaches
Piper and the player together. State (the running PGID) lives under
=~/.local/state/pclip-toggle/=, cleared automatically once playback finishes
on its own, matching the same alive-PID-check discipline as =whisper-hotkey=.

#+BEGIN_SRC bash :tangle linux/.local/bin/pclip-toggle :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
set -euo pipefail

export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"

STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/pclip-toggle"
PID_FILE="$STATE_DIR/pgid"
PCLIP="$HOME/HelmCortex/FORGE/VoxForge/bin/pclip"
PVOX="$HOME/HelmCortex/FORGE/VoxForge/bin/pvox"

mkdir -p "$STATE_DIR"

is_speaking() {
  # setsid makes the leader's PGID equal its own PID, so kill -0 -PGID
  # probes the whole group via its leader.
  [ -f "$PID_FILE" ] && kill -0 "-$(cat "$PID_FILE")" 2>/dev/null
}

# Resolve the voice `pclip default` is about to speak with, for the
# heads-up notification below. Same conf file and precedence as pclip's
# own "default" resolution (piper.conf's --model first, `pvox sd-show`
# fallback), so the announced name always matches what actually plays.
# Reads a local file instead of shelling out to pvox on the fast path —
# pclip's own header notes chasing hotkey latency down from conda's
# ~2-3s, an extra ~0.35s pvox subprocess here would cut back into that.
resolve_voice_label() {
  local conf model
  conf="$HOME/.config/speech-dispatcher/modules/piper.conf"
  model=""
  if [ -f "$conf" ]; then
    model="$(grep -oE -- '--model[[:space:]][^[:space:]]+' "$conf" | awk '{print $2}' | tail -n1)"
  fi
  if [ -z "$model" ] && [ -x "$PVOX" ]; then
    model="$("$PVOX" sd-show 2>/dev/null | sed -n 's/.*model  : //p')"
  fi
  [ -z "$model" ] && return
  basename "$model" .onnx | awk -F- '{print $2}' | tr '_' ' ' | sed 's/\b\(.\)/\u\1/g'
}

if is_speaking; then
  pgid="$(cat "$PID_FILE")"
  kill -TERM "-$pgid" 2>/dev/null || true
  rm -f "$PID_FILE"
  notify-send "pclip" "Cancelled." || true
else
  rm -f "$PID_FILE"
  voice_label="$(resolve_voice_label)"
  notify-send "pclip" "Speaking with ${voice_label:-default voice}…" || true
  setsid "$PCLIP" default --stream >/dev/null 2>&1 &
  pid=$!
  echo "$pid" > "$PID_FILE"
  disown

  # Clear the PID file once playback finishes naturally (not cancelled).
  # Polling rather than `wait` — after disown this isn't reliably a
  # waitable child of this short-lived invocation.
  (
    while kill -0 "$pid" 2>/dev/null; do sleep 0.3; done
    [ -f "$PID_FILE" ] && [ "$(cat "$PID_FILE" 2>/dev/null)" = "$pid" ] && rm -f "$PID_FILE"
  ) &
  disown
fi
#+END_SRC

* Whisper Hotkey
=Super+c= toggles mic capture (XFCE custom command binding above, mirroring
=Super+v='s live pclip binding — a direct =/commands/custom/<Super>X=
xfconf command, no =.desktop= launcher involved; that's a KDE/kglobalaccel
convention and doesn't apply on this XFCE machine). First press starts
recording via =parecord=, second press stops it, transcribes via
=whisper-transcribe --model small= (low-latency tier, not the default
=large=), copies the transcript to the clipboard, and pastes it into
whatever window currently has focus via =xdotool key ctrl+v=. State
(recording PID + the in-progress wav) lives under
=~/.local/state/whisper-hotkey/= so a crashed/killed recording never
leaves a stale lock — the toggle always checks the PID is actually alive
before trusting it.

Known limitation: =ctrl+v= is the paste binding for GUI apps generally;
some terminal emulators require =ctrl+shift+v= instead. Not handled
per-app — retarget the =xdotool key= line if this bites in a specific app.

#+BEGIN_SRC bash :tangle linux/.local/bin/whisper-hotkey :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
set -euo pipefail

# xfwm4 key-binding execution context doesn't reliably inherit XDG_RUNTIME_DIR
# (same gotcha already worked around in pclip's own <Super>v binding) — without
# it, parecord/pactl can't find the PulseAudio socket and fail silently.
export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"

STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/whisper-hotkey"
PID_FILE="$STATE_DIR/record.pid"
WAV_FILE="$STATE_DIR/capture.wav"
OUT_FILE="$STATE_DIR/transcript.md"
WHISPER_TRANSCRIBE="$HOME/HelmCortex/FORGE/bin/whisper-transcribe"

mkdir -p "$STATE_DIR"

is_recording() {
  [ -f "$PID_FILE" ] && kill -0 "$(cat "$PID_FILE")" 2>/dev/null
}

if is_recording; then
  # Stop: signal parecord to finalize the wav, then transcribe and paste.
  pid="$(cat "$PID_FILE")"
  kill -INT "$pid" 2>/dev/null || true
  for _ in $(seq 1 20); do
    kill -0 "$pid" 2>/dev/null || break
    sleep 0.1
  done
  rm -f "$PID_FILE"

  if [ ! -s "$WAV_FILE" ]; then
    notify-send "Whisper Hotkey" "No audio captured — nothing to transcribe." || true
    exit 0
  fi

  notify-send "Whisper Hotkey" "Transcribing…" || true

  if [ ! -x "$WHISPER_TRANSCRIBE" ]; then
    notify-send "Whisper Hotkey" "whisper-transcribe not found: $WHISPER_TRANSCRIBE" || true
    exit 1
  fi

  # Write to a file rather than parsing stdout: whisper-cli echoes the
  # transcript to its own inherited stdout with no trailing newline right
  # before whisper-transcribe's own "---" frontmatter delimiter, producing
  # a glued line like " Thank you.---" that line-based parsing can't see
  # as a delimiter — the frontmatter file path never touches that stream,
  # since it's built straight from the already-read transcript text in
  # Python (found 2026-07-07, "transcription came back empty" bug).
  "$WHISPER_TRANSCRIBE" --model small --out "$OUT_FILE" "$WAV_FILE" >/dev/null 2>&1 || true

  if [ ! -s "$OUT_FILE" ]; then
    notify-send "Whisper Hotkey" "whisper-transcribe produced no output file." || true
    rm -f "$WAV_FILE"
    exit 0
  fi

  # Strip the YAML frontmatter (everything up to and including the second
  # "---" line plus the blank line after it) — paste the transcript only.
  transcript="$(awk 'BEGIN{d=0} /^---$/{d++; next} d>=2' "$OUT_FILE")"
  transcript="$(printf '%s' "$transcript" | sed -e '1{/^$/d}')"
  rm -f "$OUT_FILE"

  if [ -z "$transcript" ]; then
    notify-send "Whisper Hotkey" "Transcription came back empty." || true
    rm -f "$WAV_FILE"
    exit 0
  fi

  printf '%s' "$transcript" | xclip -selection clipboard
  xdotool key --clearmodifiers ctrl+v
  preview="$(printf '%s' "$transcript" | head -c 120)"
  notify-send "Whisper Hotkey" "Pasted: ${preview}" || true
  rm -f "$WAV_FILE"
else
  # Start: background parecord, remember its PID.
  rm -f "$WAV_FILE"
  parecord --channels=1 "$WAV_FILE" >/dev/null 2>&1 &
  echo $! > "$PID_FILE"
  disown
  notify-send "Whisper Hotkey" "Recording… press Super+c again to stop and paste." || true
fi
#+END_SRC

* SDDM theme (T480)
Setup script for the sddmsel login theme on T480.
Works on both OpenMandriva (rpm/dnf) and Vendefoul Wolf/Devuan (dpkg/apt).
Installs to =/usr/share/sddm/themes/sel-shaders/= and writes the SDDM config drop-in.
Run once after =tangle-one x11.org && STOW_PKGS="all linux t480" make safe-stow=.

#+BEGIN_SRC bash :tangle t480/.local/bin/sddm-theme-setup :mkdirp yes :shebang "#!/usr/bin/env bash"
set -euo pipefail

THEME_NAME="sel-shaders"
THEME_DEST="/usr/share/sddm/themes/${THEME_NAME}"
SDDM_CONF="/etc/sddm.conf.d/10-theme.conf"
REPO_URL="https://github.com/leonardochappuis/sddmsel"
CLONE_DIR="$(mktemp -d)"

die() { printf 'sddm-theme-setup: %s\n' "$*" >&2; exit 1; }

echo "[1/4] Qt6 dependencies..."
NEED=()
if command -v rpm &>/dev/null && command -v dnf &>/dev/null; then
  # OpenMandriva / RPM-based
  rpm -q lib64Qt6Multimedia  &>/dev/null || NEED+=(lib64Qt6Multimedia)
  rpm -q lib64Qt6Core5Compat &>/dev/null || NEED+=(lib64Qt6Core5Compat)
  rpm -q lib64Qt6Svg         &>/dev/null || NEED+=(lib64Qt6Svg)
  [ ${#NEED[@]} -eq 0 ] || sudo dnf install -y "${NEED[@]}"
else
  # Debian/Devuan/apt-based (Vendefoul Wolf)
  dpkg -l libqt6multimedia6  &>/dev/null || NEED+=(libqt6multimedia6)
  dpkg -l libqt6core5compat6 &>/dev/null || NEED+=(libqt6core5compat6)
  dpkg -l libqt6svg6         &>/dev/null || NEED+=(libqt6svg6)
  [ ${#NEED[@]} -eq 0 ] || sudo apt-get install -y "${NEED[@]}"
fi

echo "[2/4] Cloning sddmsel..."
git clone --depth=1 "$REPO_URL" "$CLONE_DIR"
[ -d "${CLONE_DIR}/${THEME_NAME}" ] || die "theme variant '${THEME_NAME}' not found in repo"

echo "[3/4] Installing theme to ${THEME_DEST}..."
sudo install -d -m 755 "$THEME_DEST"
sudo cp -r "${CLONE_DIR}/${THEME_NAME}/." "$THEME_DEST/"
rm -rf "$CLONE_DIR"

echo "[4/5] Writing SDDM config..."
sudo install -d -m 755 /etc/sddm.conf.d
sudo tee "$SDDM_CONF" > /dev/null <<EOF
[Theme]
Current=${THEME_NAME}
EOF

echo "[5/6] Patching Xsetup for ALSA volume at login..."
XSETUP="/usr/share/sddm/scripts/Xsetup"
ALSA_MARKER="# sddmsel: ALSA init"
if ! grep -qF "$ALSA_MARKER" "$XSETUP" 2>/dev/null; then
  sudo tee -a "$XSETUP" > /dev/null <<'XEOF'
# sddmsel: ALSA init — ensure audible levels before login screen renders
amixer -c 0 set Master 100% unmute 2>/dev/null || true
amixer -c 0 set Speaker 100% unmute 2>/dev/null || true
amixer -c 0 set PCM 100% 2>/dev/null || true
XEOF
fi
sudo mkdir -p /var/lib/alsa && sudo alsactl store 2>/dev/null || true

echo "[6/7] Granting sddm user ALSA access (Qt6 multimedia fallback)..."
# Qt6 tries PipeWire first; without a session PipeWire it must fall back to
# ALSA — but only if the sddm user is in the audio group.
if ! id sddm | grep -q '(audio)'; then
  sudo usermod -aG audio sddm
fi

echo "[7/8] Configuring ALSA default device for sddm (bypass PulseAudio plugin)..."
# On systems where ALSA 'default' routes through PulseAudio/PipeWire, the
# sddm user has no audio session at login time and Qt6 falls silent. Route
# default directly to hardware for this user only.
SDDM_HOME="$(getent passwd sddm | cut -d: -f6)"
if [ -n "$SDDM_HOME" ] && ! grep -qF 'type plug' "${SDDM_HOME}/.asoundrc" 2>/dev/null; then
  sudo tee "${SDDM_HOME}/.asoundrc" > /dev/null <<'AEOF'
pcm.!default {
  type plug
  slave.pcm "hw:0,0"
}
ctl.!default {
  type hw
  card 0
}
AEOF
  sudo chown sddm:sddm "${SDDM_HOME}/.asoundrc"
fi

echo "[8/8] Overriding PipeWire systemd condition for sddm greeter..."
# Qt6 multimedia uses PipeWire as its sole audio backend. pipewire.service has
# ConditionUser=!@system which blocks it for system users (uid < 1000) like
# sddm. PipeWire socket activation exists but the service never starts.
# Override to remove the condition so socket activation works for sddm.
# Only applies on systemd systems — sysv-init (Devuan) skips this step.
if command -v systemctl &>/dev/null; then
  SDDM_HOME="$(getent passwd sddm | cut -d: -f6)"
  PW_OVERRIDE_DIR="${SDDM_HOME}/.config/systemd/user/pipewire.service.d"
  sudo -u sddm mkdir -p "$PW_OVERRIDE_DIR"
  if ! grep -q 'ConditionUser=' "${PW_OVERRIDE_DIR}/override.conf" 2>/dev/null; then
    sudo tee "${PW_OVERRIDE_DIR}/override.conf" > /dev/null <<'PEOF'
[Unit]
ConditionUser=
PEOF
    sudo chown -R sddm:sddm "${SDDM_HOME}/.config/systemd"
  fi
else
  echo "  (skipped — sysv-init detected, no systemd user units)"
fi

echo
echo "=== SDDM theme ‘${THEME_NAME}’ installed ==="
echo "Test with: sddm-greeter-qt6 --test-mode --theme ${THEME_DEST}"
#+END_SRC

** Rofi Launch Wrapper

This wrapper composes `XDG_DATA_DIRS` before calling `rofi-core` so `drun` can still see user, system, and Flatpak desktop entries even when the Guix profile environment would otherwise narrow discovery too aggressively.

#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-launch :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
# Source the Guix core profile FIRST (before set -u): it puts rofi on PATH and its
# own reference to an unset GIO_EXTRA_MODULES would abort under nounset. This is why
# we call bare `rofi` here rather than rofi-core (which sources under its own set -u
# and dies in a session that never exported GIO_EXTRA_MODULES — the Super+space bug).
P="$HOME/.guix-extra-profiles/core/core"; [ -r "$P/etc/profile" ] && . "$P/etc/profile"
set -euo pipefail
compose() { case ":${XDG_DATA_DIRS:-}:" in *":$1:"*) ;; *) XDG_DATA_DIRS="${XDG_DATA_DIRS:+$XDG_DATA_DIRS:}$1";; esac; }
compose "$HOME/.local/share"; compose /usr/local/share; compose /usr/share
compose "$HOME/.local/share/flatpak/exports/share"; compose /var/lib/flatpak/exports/share
export XDG_DATA_DIRS
exec rofi -show drun "$@"
#+END_SRC

** Run Dialog

Binds =Super+r= to Rofi's built-in =run= modi — bare =$PATH= executables, as distinct from =Super+space='s =drun=, which lists =.desktop= entries. Same source-before-=set -u= pattern as the other wrappers.

=Super+r= is not a free key: XFCE ships it as a *default* shortcut at =/commands/default/<Super>r= bound to =xfce4-appfinder -c= (the appfinder's collapsed run dialog). A =/commands/custom/= entry on the same key takes precedence over the default, so the sanctuary shortcut script simply writes the custom entry and the XFCE default is shadowed without needing removal.

Because this wrapper does not compose =XDG_DATA_DIRS= (=run= scans =$PATH=, not desktop entries), executables live wherever the Guix core profile puts them.

** Custom Action Menu

This menu provides a plain-text control panel for common desktop actions, duplicates the Sanctuary workspace jumps already available on Ctrl+F2/F3/F4 for discoverability, and routes power/session commands through `xfce4-session-logout` where possible so accidental one-keystroke shutdowns are avoided even though some backend behavior on Devuan remains best-effort and refinable later.

Unlike the other wrappers this one calls =rofi-core= (from =guix.org=) rather than bare =rofi=, because it needs the profile on PATH for =wmctrl= and the =xfce4-*= helpers too. That wrapper used to run =set -euo pipefail= *before* sourcing the Guix profile, and the profile dereferences an unset =GIO_EXTRA_MODULES=, so under =nounset= it aborted with =unbound variable= before ever reaching rofi — which is exactly why =Super+x= did nothing while the source-first wrappers worked. =rofi-core= now sources the profile first, so this menu opens.

#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-actions :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
set -euo pipefail
ROFI="$HOME/.local/bin/rofi-core"
declare -A ACT=(
  ["Lock screen"]="xflock4"
  ["Screenshot"]="xfce4-screenshooter"
  ["Display settings"]="xfce4-display-settings"
  ["Task manager"]="xfce4-taskmanager"
  ["App finder"]="xfce4-appfinder"
  ["Emoji picker"]="$HOME/.local/bin/rofi-emoji-menu"
  ["Clipboard history"]="$HOME/.local/bin/clipmenu-rofi"
  ["Sanctuary: Qtile (WS2)"]="wmctrl -s 1"
  ["Sanctuary: GNUstep (WS3)"]="wmctrl -s 2"
  ["Sanctuary: CDE (WS4)"]="wmctrl -s 3"
  ["Suspend"]="xfce4-session-logout --suspend"
  ["Power / session…"]="xfce4-session-logout"
)
ORDER=("Lock screen" "Screenshot" "Display settings" "Task manager" "App finder" "Emoji picker" "Clipboard history" "Sanctuary: Qtile (WS2)" "Sanctuary: GNUstep (WS3)" "Sanctuary: CDE (WS4)" "Suspend" "Power / session…")
choice="$(printf '%s\n' "${ORDER[@]}" | "$ROFI" -dmenu -i -p actions)"
[ -n "${choice:-}" ] || exit 0
cmd="${ACT[$choice]:-}"
[ -n "$cmd" ] || exit 0
setsid -f sh -c "$cmd" >/dev/null 2>&1 || eval "$cmd" &
#+END_SRC

** Clipmenu Daemon Autostart

This autostart entry ensures the clipboard history daemon is present in graphical sessions so the Rofi clipboard picker has data to show. It launches =clipmenud-start= by bare name, which self-sources the Guix core profile before starting the daemon.

A correction, recorded because it cost a debugging session: an earlier revision of this prose asserted that the bare name "resolves from =~/.local/bin= on the session PATH". That was false. =xfce4-session= launches XDG autostart entries with the PATH inherited from Xsession, which never contained =~/.local/bin= — so this entry died silently at every login and the clipboard was permanently empty, while running =clipmenud-start= by hand always worked (an interactive shell *does* have =~/.local/bin= on PATH). The lesson generalises: where a name resolves in your shell says nothing about where it resolves for a GUI-launched process.

There are two independent fixes and both are kept. One layer down, =x11.org='s =.xsessionrc.d/40-local-bin.sh= puts =~/.local/bin= on the session PATH for every autostart entry (=clipmenud-start=, =xfce-sanctuary-shortcuts=, =appmenu-boot-setup=, =plank=, =twistpatch= — all were affected, all silently). Here, the =Exec== names the script by absolute path so it does not consult PATH at all.

Belt and braces is deliberate. The PATH snippet only takes effect if =~/.xsessionrc= is sourced, which is a property of the display manager, not of this repo; a login path that skips it must not silently disable the clipboard again. An autostart entry should not depend on PATH to find a file whose location it already knows.

#+BEGIN_SRC conf :tangle linux/.config/autostart/clipmenud.desktop :tangle-mode (identity #o644) :comments no
[Desktop Entry]
Type=Application
Name=clipmenud
Comment=Clipboard history daemon for rofi clipboard picker
Exec=sh -c 'exec "$HOME/.local/bin/clipmenud-start"'
Terminal=false
X-GNOME-Autostart-enabled=true
#+END_SRC
