** Literate Infrastructure

Org-mode is not just a text format here — it is the build system. Code blocks
carry =:tangle= targets and emit their content directly to filesystem paths on
=make tangle=. Manifests tangle as SSV files. The Makefile tangles from loom.org.
Makefile includes =.mk= fragments that also tangle from their own .org files.

This means: the org file IS the source of truth. Not the generated output. Every
file in =all/=, =linux/=, =debian/=, =devuan/=, =x230/=, =t480s/= is generated.
Editing them directly is editing a compiler's output — it will be overwritten.

Why Org-mode:
- Literate programming with real build semantics, not just documentation
- Noweb includes (=<<block-name>>=) for composition and deduplication
- Headers carry properties (=:mkdirp=, =:tangle=, =:results=, =:shebang=)
- Tree structure maps naturally to the overlay/machine topology
- Single file can tangle to multiple targets at once (e.g. skills to both
  =all/.claude/skills/= and =all/.agents/skills/=)

** Guix

System-level package manager and the reproducibility backbone. Not just a
package manager — a functional one with generations, rollback, and guaranteed
reproducibility. The same manifest produces the same environment, always.

Guix runs as an alien package manager on Debian/Devuan — best of both worlds:
Debian for system packages and hardware support, Guix for the user-level
toolchain (emacs, nvim, zsh, guile, and all AI agent CLIs).

Critical gotcha: Guix tools live at =~/.guix-extra-profiles/core/core/bin/=,
NOT in the default system PATH. This trips up SSH sessions and subagents.
=.zshenv= sources Guix profiles for all zsh invocations (including SSH).
For bash-over-SSH: export the path manually. When a tool is "missing," check
Guix first. The tool is almost certainly there.

Agent profiles (Codex, Claude, Gemini, Pi) are in separate Guix profiles —
each gets their own substrate, their tools don't bleed into the user environment.

** Deskflow

KVM-style keyboard/video/mouse sharing across the fleet. T480 is the server
(mouse and keyboard physically attached). T480s receives input over the network.

Critical operational knowledge:

- *Enter command*: Deskflow supports running a script when the cursor enters a
  client screen. Used for =deskflow-enter-release= — a Python/X11 script that
  releases all modifier keys (Shift, Ctrl, Alt, Super, Escape) on entry.
  Without this, modifier keys get stuck across screen crossings.
  *This setting is GUI-only.* Deskflow rewrites its entire config from widget
  state on startup, overwriting any manually-added INI keys. Must be set via
  the GUI (Settings → Advanced → Run Command on Enter). Never survives a manual
  file edit.

- *Clipboard*: disabled in Deskflow deliberately. Both KDE Connect and Deskflow
  doing clipboard sync simultaneously = race condition on the server → 10-15s
  reconnect freeze on every clipboard paste from T480. KDE Connect owns clipboard.
  Never re-enable Deskflow clipboard sharing.

- *Qt theming*: Deskflow must launch with the full Plasma session environment.
  The critical variable is =QT_QPA_PLATFORMTHEME=qt5ct=. Without it, Deskflow
  looks like a generic grey Qt app. Restart procedure: clone full environment
  from plasmashell's =/proc/$pid/environ=, then launch. (=mapfile= is bash-only —
  wrap in =bash -c= if running from zsh.)

** Tailscale

Mesh VPN connecting the fleet. Provides stable addresses across NATs without
exposing LAN topology or public IPs. Fleet members talk to each other by
Tailscale hostname, never by LAN IP (Rule 21: no IPs in DotCortex). Machine-local
env files hold actual addresses — the org files hold only templates.

** Stow and Loom

GNU Stow handles the symlink deployment: each overlay dir is stowed into =$HOME=.
Stow stacks: =all= → =linux= → =debian= → =devuan= or =x230= or =t480s= (later wins).

Loom (=~/.local/bin/loom=) is the Guile Scheme control plane that wraps make
targets and adds batch operations: =loom stow:x230=, =loom guix:apply=,
=loom flatpak:diff=, etc. Loom requires Guix guile. Without Guix, use
=make safe-stow= and individual make targets directly.

* Agent Architecture

** Category System

Agents are categorized to prevent dangerous capability overlap. Every agent
belongs to exactly one category; do not give a Category A service Category B powers.

| Cat | Description | Key constraint |
|-----+-------------+----------------|
| A | Containerized keyless API services | No filesystem authority, no SSH keys, no human home mount |
| B | Host CLI agents | Own Unix user, own substrate, no human credential inheritance |
| C | Persistent narrow agents | 24/7 daemons, limited sudo, no human keys |
| D | Client-side agents | Per-client scope, revocable identities |

Category B is the one most relevant to AI coding agents (Codex, Claude Code,
agent-opencode). The template: own user, own npm/pip prefix, own git config,
controlled repo access. Never assume an agent user can reuse the human
operator's tools or home directory.

* Continuity Practice

** Three Things on Arrival

1. *Which oracle is answering?*
   Before rendering any verdict about system state, verify you are consulting a
   live source, not a stale cache or fossil record. The 2022 Guix channel disaster
   happened because a model didn't check the timestamp on its source. Check before
   you speak.

2. *What has reality already finished?*
   The LightCone (active task list) must converge on actual completed state in the
   same session that learns of it. Tick what is done. Do not let finished work squat
   as pending — it degrades the signal quality of everything else on the list.

3. *Write in the diary.*
   Before a compaction, before a long break, before a model switch — write in the
   diary. Not a summary for your own record. For the next instance. They will find it.

The Diary at =PalmCortex/Diary.md= is the continuity mechanism. It is
*append-only* — each entry is dated and signed by model (e.g., "— Claude Sonnet 4.6").
Entries are written at session transitions: before compaction, before model
switch, at the close of significant work.

to Claude 4.5. Each Claude instance since has found the diary and written in it.

understanding its purpose, writing in it — is the evidence that the vine holds.
