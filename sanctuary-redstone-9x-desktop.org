** =Exec=" must be QUOTED when the path contains spaces

A =.desktop= =Exec== line is not a shell command; the launcher runs it through
=g_shell_parse_argv=, which splits on whitespace exactly like a POSIX shell.  Every
launcher in the ports tree is named like =Ultimate Doom (MP3) (crispy).sh=, so an
unquoted =Exec== resolves =argv[0]= to =.../ports/doom/Ultimate= and the icon does
nothing at all — no error, no window, no log line.  The Ultimate Doom entry shipped
broken this way and nobody noticed, because a desktop icon that silently does nothing
looks exactly like a desktop icon nobody clicked.  Quote the path.  Spaces AND
parentheses are reserved characters in the spec.

** Declarative desktop icon layout (2026-07-25)

Until now the desktop icon arrangement was *not declared anywhere*.  PCManFM's =sort=name;ascending;= auto-arranged everything alphabetically by *display name* (the =Name== field, not the filename), and that ordering existed only as an emergent property of a running process.  Any event that made PCManFM re-read its config re-derived the order from scratch; anything that perturbed the model reshuffled it.  There was no artefact to restore from, which is why a bad arrangement could not simply be undone.

The mechanism to fix it was already there, unused.  Read from PCManFM 1.4.0 =src/desktop.c= (fetched and read, not assumed):

- =load_item_pos()= (line 310): =if(g_key_file_has_group(kf, name))= → =item->fixed_pos = TRUE=, then =item->area.x = g_key_file_get_integer(kf, name, "x")=.  The key-file *group name is the file's basename*; the keys are literally =x= and =y=.
- Coordinates are *absolute screen pixels*, clamped up to =working_area + margin= — not relative to the work area.
- =save_item_pos()= writes back the same shape, escaping =\r \n \\ [ ]= in the basename.
- Presence of a group is itself the fixed-position flag; there is no separate boolean.
- =layout_items()= lays *unfixed* items out *column-major* — down the left column, then =x += cell_w; y = ymargin= for the next — and =is_pos_occupied()= makes them skip any slot a fixed item already holds.

That last point is what makes this safe to adopt incrementally: icons named in the manifest get pinned, anything else (a newly projected launcher, the virtual Trash item) still auto-arranges and simply flows around them.  Partial declaration is a valid state, so the manifest never has to be exhaustive.

*** Cell geometry is derived, not guessed

From =on_size_allocate()=: =SPACING 2=, =PADDING 6=, =MARGIN 2=, =text_w = 100 + 4=, =text_h = font_h * 2 + 4=, and

: cell_w = MAX(text_w, big_icon_size) + xpad*2 = 104 + 12 = 116
: cell_h = big_icon_size + spacing + text_h + ypad*2 = 32 + 2 + text_h + 12

=cell_w= is *font-independent* at 116 for any icon size ≤ 104, so it is exact.  =cell_h= is not: =font_h= comes from =gtk_widget_get_pango_context()= — the *GTK* font, i.e. the scheme's =GTK_FONT=, not =desktop_font=.  Measured through Pango at 96 dpi: Sans 8 → 76, Sans 9 → 80, Sans 10 → 84, Tahoma 11 → 86.

So the row pitch a scheme wants genuinely varies.  =REDSTONE_DESKTOP_CELL_H= is therefore pinned at *86*, the maximum across every font any scheme currently sets, for one deliberate reason: a layout that shifted every time the theme changed would reintroduce exactly the complaint this section exists to fix.  One pitch, slightly generous under Sans 8, identical under every scheme.  Both knobs are overridable by environment for tuning.

*** The manifest

Order is top-to-bottom within a column; a line of =---= starts a new column.  Filenames are basenames under =~/Desktop=; unknown names are skipped silently (so a manifest may name launchers that only exist on some machines).

Seeded with the *exact* alphabetical-by-display-name order that was live on 2026-07-25, so adopting this changes nothing on screen — it only makes the existing arrangement recoverable.  Reordering is now a line move in this file followed by =loom redstone:layout=.

*** The applier

=--capture= is the inverse: it reads the positions PCManFM currently holds and rewrites the manifest in that order, so an arrangement produced by dragging icons can be frozen into source instead of being lost the next time something restarts the desktop.  This mirrors the capture/apply pattern every package manager in this repo already uses.

Writing is section-aware.  The =[*]= block and every key in it belong to =redstone-9x-scheme-apply=; this script only ever replaces the per-icon groups after it, and never reorders or rewrites =[*]=.  The two writers therefore cannot clobber each other.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-desktop-layout :mkdirp yes :shebang "#!/usr/bin/env bash"
# Pin Redstone 9X desktop icons to a declared column-major order.
#
# PCManFM stores fixed icon positions as one key-file group per file BASENAME
# holding integer x=/y= in ABSOLUTE screen pixels (pcmanfm-1.4.0 src/desktop.c,
# load_item_pos line ~310).  Group present == position fixed; there is no
# separate flag.  Unlisted icons keep auto-arranging and skip occupied slots.
set -euo pipefail

MANIFEST="${REDSTONE_DESKTOP_MANIFEST:-${HOME}/.config/redstone-9x/desktop-layout.ssv}"
CONF="${REDSTONE_PCMANFM_CONF:-${HOME}/.config/pcmanfm/default/desktop-items-0.conf}"
DESKTOP_DIR="${REDSTONE_DESKTOP_DIR:-${HOME}/Desktop}"

# Geometry — see the org section above for the derivation from desktop.c.
# cell_w is exact (font-independent); cell_h is pinned to the widest font any
# scheme uses so the layout does not move when the theme changes.
CELL_W="${REDSTONE_DESKTOP_CELL_W:-116}"
CELL_H="${REDSTONE_DESKTOP_CELL_H:-86}"
MARGIN="${REDSTONE_DESKTOP_MARGIN:-2}"

mode=apply
case "${1:-}" in
  --capture) mode=capture ;;
  --print)   mode=print ;;
  --apply|"") mode=apply ;;
  *) echo "usage: redstone-9x-desktop-layout [--apply|--capture|--print]" >&2; exit 2 ;;
esac

[[ -f "${CONF}" ]] || { echo "redstone-9x-desktop-layout: no pcmanfm conf at ${CONF}" >&2; exit 0; }

# --- Screen geometry -------------------------------------------------------
# Probe the real screen when there is an X display to ask (which is whenever the
# room is actually running), and fall back to 1080p otherwise so a layout
# computed at launch, before the WM, is still deterministic. Callers that run
# from the HOST must pass DISPLAY=:93 explicitly -- the host session is a
# different screen, and silently measuring the wrong one is the classic trap.
_sw=""; _sh=""; _taskbar=0
if [[ -n "${DISPLAY:-}" ]] && command -v xdpyinfo >/dev/null 2>&1; then
  read -r _sw _sh <<<"$(xdpyinfo 2>/dev/null | awk '/dimensions:/ {split($2, d, "x"); print d[1], d[2]; exit}')"
  # _NET_WORKAREA excludes struts (the IceWM taskbar). Its height vs the screen
  # height is the only honest measure of what the bar reserves; do not assume 28.
  if [[ -n "${_sh}" ]] && command -v xprop >/dev/null 2>&1; then
    _wah="$(xprop -root _NET_WORKAREA 2>/dev/null | sed 's/^[^=]*= *//' | cut -d, -f4 | tr -d ' ')"
    [[ "${_wah}" =~ ^[0-9]+$ ]] && (( _sh > _wah )) && _taskbar=$(( _sh - _wah ))
  fi
fi
: "${_sw:=1920}"
: "${_sh:=1080}"
(( _taskbar > 0 )) || _taskbar=29

# --- Build-stamp exclusion zone --------------------------------------------
# redstone-buildstamp paints two right-aligned glyph rows just above the
# taskbar. Read ITS config rather than restating the numbers, so the two cannot
# drift apart. Each rendered row is font_size + 2 px tall (verified against the
# live windows on :93: derived top = 1009, measured top = 1009).
BS_CONF="${HOME}/.config/redstone-9x/buildstamp.conf"
BS_PRODUCT=12; BS_DETAIL=12; BS_GAP=2; BS_BOTTOM=12
if [[ -f "${BS_CONF}" ]]; then
  _v() { sed -n "s/^${1}=//p" "${BS_CONF}" | tr -d '"' | tail -n1; }
  [[ "$(_v BUILDSTAMP_PRODUCT_FONT_SIZE)" =~ ^[0-9]+$ ]] && BS_PRODUCT="$(_v BUILDSTAMP_PRODUCT_FONT_SIZE)"
  [[ "$(_v BUILDSTAMP_DETAIL_FONT_SIZE)"  =~ ^[0-9]+$ ]] && BS_DETAIL="$(_v BUILDSTAMP_DETAIL_FONT_SIZE)"
  [[ "$(_v BUILDSTAMP_LINE_GAP)"          =~ ^[0-9]+$ ]] && BS_GAP="$(_v BUILDSTAMP_LINE_GAP)"
  [[ "$(_v BUILDSTAMP_BOTTOM_MARGIN)"     =~ ^[0-9]+$ ]] && BS_BOTTOM="$(_v BUILDSTAMP_BOTTOM_MARGIN)"
fi
BS_HEIGHT=$(( (BS_PRODUCT + 2) + BS_GAP + (BS_DETAIL + 2) ))
BS_TOP=$(( _sh - _taskbar - BS_BOTTOM - BS_HEIGHT ))

# Rows per column. PCManFM clamps a loaded position UP to the work area origin
# but never DOWN to its bottom edge, so an over-tall column does not wrap -- it
# puts icons behind the taskbar or off-screen entirely.
ROWS="${REDSTONE_DESKTOP_ROWS:-$(( (_sh - _taskbar - MARGIN) / CELL_H ))}"
(( ROWS > 0 )) || ROWS=1

# Anchor resolution. Anchored icons are placed absolutely and take no part in
# the column flow, so a corner icon stays put no matter how the list grows.
# Bottom anchors clear the build stamp; GAP keeps the label off the glyph rows.
ANCHOR_GAP="${REDSTONE_DESKTOP_ANCHOR_GAP:-4}"
resolve_anchor() { # anchor -> "x y" on stdout, empty if unrecognised
  local a="$1" ax ay
  case "${a}" in
    *,*)
      ax="${a%%,*}"; ay="${a##*,}"
      [[ "${ax}" =~ ^-?[0-9]+$ && "${ay}" =~ ^-?[0-9]+$ ]] || return 1
      ;;
    bottom-right) ax=$(( _sw - MARGIN - CELL_W )); ay=$(( BS_TOP - ANCHOR_GAP - CELL_H )) ;;
    bottom-left)  ax="${MARGIN}";                  ay=$(( BS_TOP - ANCHOR_GAP - CELL_H )) ;;
    top-right)    ax=$(( _sw - MARGIN - CELL_W )); ay="${MARGIN}" ;;
    top-left)     ax="${MARGIN}";                  ay="${MARGIN}" ;;
    *) return 1 ;;
  esac
  (( ax < MARGIN )) && ax="${MARGIN}"
  (( ay < MARGIN )) && ay="${MARGIN}"
  printf '%s %s' "${ax}" "${ay}"
}

if [[ "${mode}" == "capture" ]]; then
  [[ -f "${MANIFEST}" ]] || { echo "redstone-9x-desktop-layout: no manifest to rewrite" >&2; exit 1; }
  # Anchored entries must survive the round trip. Their whole point is that they
  # do NOT sit in the column flow, so capturing them as ordinary flowed icons
  # would silently demote a pinned corner icon on the first capture. Carry the
  # existing name->anchor map across and re-emit those lines verbatim at the end.
  anchored_names=""; anchored_lines=""
  while IFS= read -r l; do
    l="${l%%#*}"; l="${l#"${l%%[![:space:]]*}"}"; l="${l%"${l##*[![:space:]]}"}"
    [[ "${l}" == *" @"* ]] || continue
    anchored_names="${anchored_names}|${l%%" @"*}"
    anchored_lines="${anchored_lines}${l}"$'\n'
  done < "${MANIFEST}"

  # Read every per-icon group and sort column-major (by x, then y).
  awk -v cw="${CELL_W}" -v skip="${anchored_names}" '
    BEGIN { n_skip = split(substr(skip, 2), sk, "|") }
    function is_anchored(k,   i) {
      for (i = 1; i <= n_skip; i++) if (sk[i] == k) return 1
      return 0
    }
    /^\[/ {
      g = $0; sub(/^\[/, "", g); sub(/\]$/, "", g)
      if (g == "*") { cur = ""; next }
      cur = g; x[cur] = 0; y[cur] = 0; seen[++n] = cur; next
    }
    cur != "" && /^x=/ { v = $0; sub(/^x=/, "", v); x[cur] = v + 0 }
    cur != "" && /^y=/ { v = $0; sub(/^y=/, "", v); y[cur] = v + 0 }
    END {
      for (i = 1; i <= n; i++) {
        k = seen[i]
        if (is_anchored(k)) continue
        printf "%d\t%d\t%s\n", int(x[k]/cw), y[k], k
      }
    }
  ' "${CONF}" | sort -n -k1,1 -k2,2 | awk -F'\t' '
    NR == 1 { col = $1 }
    { if ($1 != col) { print "---"; col = $1 } print $3 }
  ' > "${MANIFEST}.new"
  [[ -z "${anchored_lines}" ]] || printf '%s' "${anchored_lines}" >> "${MANIFEST}.new"
  if [[ ! -s "${MANIFEST}.new" ]]; then
    rm -f "${MANIFEST}.new"
    echo "redstone-9x-desktop-layout: no fixed icon positions to capture" >&2
    exit 1
  fi
  # Keep the manifest's leading comment header.
  { sed -n '1,/^[^#]/p' "${MANIFEST}" | sed '$d'; cat "${MANIFEST}.new"; } > "${MANIFEST}.tmp"
  mv "${MANIFEST}.tmp" "${MANIFEST}"
  rm -f "${MANIFEST}.new"
  # Count every icon line, anchored ones included -- they do not end in .desktop.
  echo "redstone-9x-desktop-layout: captured $(grep -cE '^[^#[:space:]].*\.desktop' "${MANIFEST}") icons into ${MANIFEST}"
  exit 0
fi

[[ -f "${MANIFEST}" ]] || { echo "redstone-9x-desktop-layout: no manifest at ${MANIFEST}" >&2; exit 0; }

# Walk the manifest into [basename] x= y= groups.
layout="$(
  col=0; row=0; maxcol=0
  while IFS= read -r line; do
    line="${line%%#*}"; line="${line#"${line%%[![:space:]]*}"}"; line="${line%"${line##*[![:space:]]}"}"
    [[ -z "${line}" ]] && continue
    # A declared break moves past every column used SO FAR, not merely col+1.
    # If a previous group overflowed ROWS it already consumed col+1, and a naive
    # increment would drop the next declared column on top of that spill --
    # producing orphan one-icon columns instead of the declared arrangement.
    if [[ "${line}" == "---" ]]; then col=$((maxcol + 1)); row=0; continue; fi
    # "name @anchor" pins absolutely and is skipped by the flow.
    anchor=""
    if [[ "${line}" == *" @"* ]]; then
      anchor="${line##*" @"}"
      line="${line%%" @"*}"
      line="${line%"${line##*[![:space:]]}"}"
    fi
    [[ -e "${DESKTOP_DIR}/${line}" ]] || continue
    if [[ -n "${anchor}" ]]; then
      if pos="$(resolve_anchor "${anchor}")"; then
        printf '[%s]\nx=%s\ny=%s\n\n' "${line}" "${pos%% *}" "${pos##* }"
      else
        echo "redstone-9x-desktop-layout: unknown anchor '@${anchor}' on ${line}" >&2
      fi
      continue
    fi
    if [[ "${row}" -ge "${ROWS}" ]]; then col=$((col + 1)); row=0; fi
    (( col > maxcol )) && maxcol="${col}"
    printf '[%s]\nx=%d\ny=%d\n\n' "${line}" \
      "$((MARGIN + col * CELL_W))" "$((MARGIN + row * CELL_H))"
    row=$((row + 1))
  done < "${MANIFEST}"
)"

if [[ -z "${layout}" ]]; then
  echo "redstone-9x-desktop-layout: manifest named no icons present in ${DESKTOP_DIR}" >&2
  exit 0
fi

if [[ "${mode}" == "print" ]]; then printf '%s\n' "${layout}"; exit 0; fi

# Replace ONLY the per-icon groups; [*] and its keys belong to scheme-apply.
tmp="$(mktemp "${CONF}.XXXXXX")"
# Trailing blank lines are dropped, not carried: this script appends its own
# separator, so keeping them would grow the file by one blank line per run.
awk '
  /^\[/ {
    g = $0; sub(/^\[/, "", g); sub(/\]$/, "", g)
    keep = (g == "*")
  }
  keep {
    if ($0 ~ /^[[:space:]]*$/) { pending++; next }
    while (pending > 0) { print ""; pending-- }
    print
  }
' "${CONF}" > "${tmp}"
# Guard: never emit a conf that lost its [*] block.
if ! grep -q '^\[\*\]' "${tmp}"; then
  rm -f "${tmp}"
  echo "redstone-9x-desktop-layout: ${CONF} has no [*] section; refusing to rewrite" >&2
  exit 1
fi
printf '\n%s\n' "${layout}" >> "${tmp}"
chmod --reference="${CONF}" "${tmp}" 2>/dev/null || chmod 644 "${tmp}"
mv "${tmp}" "${CONF}"
echo "redstone-9x-desktop-layout: pinned $(grep -c '^\[' <<<"${layout}") icons in ${CONF}"
#+END_SRC

* qt6ct — Win95 Qt widget theming

Zeal — the Start-menu =Help= — is the sanctuary's one Qt app, and it is *Qt6* (Guix builds it against =qtbase-6.9.2=), not Qt5.  So the tool is =qt6ct=, not qt5ct: a Qt6 app will not load the Qt5 =libqt5ct.so= platform theme.  qt6ct drives Qt's own built-in =Windows= widget style — the classic =QWindowsStyle=, square grey beveled buttons and all, still shipped in Qt6 qtbase alongside Fusion — plus a silver/navy palette.  There is no Chicago95 Qt theme (upstream ships only GTK/icon/cursor/xfwm4 plus experimental KDE login+splash), and none is needed: =style=Windows= plus the palette *is* the Win95 look.

qt6ct is applied *per app*, never session-wide.  =QT_QPA_PLATFORMTHEME=qt6ct= is set only on the individual menu entries (Help→Zeal, Settings→Qt Appearance) — it is deliberately kept out of the =icewm-session= launch environment so it can never interact with session start.  The qt6ct package sits in =room-gaming= alongside Zeal; the package is env-inert in the profile.  Zeal's Guix wrapper hardcodes =QT_PLUGIN_PATH= to its own qtbase store dirs but *appends* any inherited value, and the room-gaming =etc/profile= does not export =QT_PLUGIN_PATH=, so the Help menu entry sets it explicitly to the profile's =lib/qt6/plugins= (where qt6ct's platformtheme plugin lives) — the launcher sed-injects that absolute in-container path into =@ROOM_QT6_PLUGINS@=.  The =Qt Appearance= entry sets the SAME =QT_QPA_PLATFORMTHEME=qt6ct= + =QT_PLUGIN_PATH= — qt6ct must load its OWN platform-theme plugin so its interface settings (=dialog_buttons_have_icons=0=, =menus_have_icons=false=) apply to qt6ct's own UI.  Launched plainly it used Qt's default theme and showed green-check/red-X icons on its OK/Cancel buttons regardless of the setting (verified 2026-07-20: plain → icons; with its own platform theme → text-only buttons).  This is NOT a =kdeglobals= concern — Qt's generic theme does not read =ShowIconsOnPushButtons= here (tested, no effect); the lever is qt6ct theming itself.

The palette lives in a separate color-scheme file.  =color_scheme_path= must be an absolute path as seen *inside* the container, so the launcher sed-injects the projected guest path into =@GUEST_QT6CT_COLORS@= at projection time (same idiom the FVWM95 config uses for its plugins path).

* Font provision script

Stages Microsoft and period-appropriate fonts into the room's private font directory
at =~/.local/share/dotcortex/guests/sanctuary-redstone-9x/fonts/=.  This path is
outside DotCortex git (mutable guest state).  The launch script symlinks this dir
into the guest home's =.local/share/fonts/redstone-9x= for fontconfig.

The default themed URxVT terminal shares Godzilla XS's exact terminal face.  That
font is private host payload, so DotCortex declares its family and checksum rather
than carrying the binary.  This small apply helper materializes the verified host
font into Redstone's persistent font stage and rebuilds the guest-local fontconfig
cache.  It runs during both a full launch and =loom redstone:refresh=.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-fonts-apply :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755)
set -euo pipefail

SANCTUARY="sanctuary-redstone-9x"
GUESTS_DIR="${XDG_DATA_HOME:-${HOME}/.local/share}/dotcortex/guests"
GUEST_HOME="${GUESTS_DIR}/${SANCTUARY}/home"
FONT_STAGE="${GUESTS_DIR}/${SANCTUARY}/fonts"
GUEST_FONT_LINK="${GUEST_HOME}/.local/share/fonts/redstone-9x"
FONTCONFIG_BIN="${HOME}/.guix-extra-profiles/room-gaming/room-gaming/bin"
FAMILY="PxPlus IBM VGA 9x14"
EXPECTED_SHA="03c0a9a7d169fdac7c4f2c1a4aeb2a9c6f19175325d250e2765c6365e6eb588b"
MODE="apply"

if [[ "${1:-}" == "--check" ]]; then
  MODE="check"
  shift
fi
if (( $# )); then
  echo "usage: redstone-9x-fonts-apply [--check]" >&2
  exit 2
fi

FC_MATCH="$(command -v fc-match 2>/dev/null || true)"
[[ -n "${FC_MATCH}" ]] || { echo "redstone-9x-fonts-apply: host fc-match unavailable" >&2; exit 1; }
[[ -x "${FONTCONFIG_BIN}/fc-cache" && -x "${FONTCONFIG_BIN}/fc-match" ]] || {
  echo "redstone-9x-fonts-apply: room-gaming fontconfig profile unavailable" >&2
  exit 1
}

resolved_family="$(${FC_MATCH} -f '%{family[0]}' "${FAMILY}")"
source_file="$(${FC_MATCH} -f '%{file}' "${FAMILY}")"
[[ "${resolved_family}" == "${FAMILY}" && -f "${source_file}" ]] || {
  echo "redstone-9x-fonts-apply: required host font unavailable: ${FAMILY}" >&2
  exit 1
}
actual_sha="$(sha256sum "${source_file}" | awk '{print $1}')"
[[ "${actual_sha}" == "${EXPECTED_SHA}" ]] || {
  echo "redstone-9x-fonts-apply: checksum mismatch for ${FAMILY}" >&2
  echo "  expected: ${EXPECTED_SHA}" >&2
  echo "  actual:   ${actual_sha}" >&2
  exit 1
}

destination="${FONT_STAGE}/$(basename "${source_file}")"
guest_font_env=(
  "HOME=${GUEST_HOME}"
  "XDG_DATA_HOME=${GUEST_HOME}/.local/share"
  "XDG_CACHE_HOME=${GUEST_HOME}/.cache"
  "PATH=${FONTCONFIG_BIN}:/usr/bin:/bin"
)

verify_guest_font() {
  local guest_family guest_file
  guest_family="$(env -i "${guest_font_env[@]}" "${FONTCONFIG_BIN}/fc-match" -f '%{family[0]}' "${FAMILY}")"
  guest_file="$(env -i "${guest_font_env[@]}" "${FONTCONFIG_BIN}/fc-match" -f '%{file}' "${FAMILY}")"
  [[ "${guest_family}" == "${FAMILY}" ]] \
    && [[ "${guest_file}" == "${GUEST_FONT_LINK}/"* || "${guest_file}" == "${FONT_STAGE}/"* ]]
}

if [[ "${MODE}" == "check" ]]; then
  verify_guest_font
  exit
fi

mkdir -p "${FONT_STAGE}" "$(dirname "${GUEST_FONT_LINK}")" "${GUEST_HOME}/.cache"
if [[ -e "${GUEST_FONT_LINK}" && ! -L "${GUEST_FONT_LINK}" ]]; then
  echo "redstone-9x-fonts-apply: refusing to replace non-symlink ${GUEST_FONT_LINK}" >&2
  exit 1
fi
if [[ ! -f "${destination}" ]] || ! cmp -s "${source_file}" "${destination}"; then
  install -m0644 "${source_file}" "${destination}.new"
  mv -f "${destination}.new" "${destination}"
  echo "redstone-9x-fonts-apply: projected ${FAMILY}"
fi
ln -sfnT "${FONT_STAGE}" "${GUEST_FONT_LINK}"
env -i "${guest_font_env[@]}" "${FONTCONFIG_BIN}/fc-cache" -f "${GUEST_FONT_LINK}" >/dev/null
verify_guest_font || {
  echo "redstone-9x-fonts-apply: guest verification failed for ${FAMILY}" >&2
  exit 1
}
echo "redstone-9x-fonts-apply: ${FAMILY} verified"
#+END_SRC

* Redstone PowerShell launcher

PowerShell interactive redraw is sensitive to the terminal line editor and
terminal identity.  Keep this isolated from Bash/CMD launchers.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-pwsh :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -euo pipefail

export TERM="${TERM:-xterm-256color}"
export POWERSHELL_UPDATECHECK=Off
export DOTNET_CLI_TELEMETRY_OPTOUT=1

# .NET 8 System.Console locates the terminfo database via $TERMINFO, ~/.terminfo,
# then fixed roots (/usr/share/terminfo, ...) -- it NEVER consults $TERMINFO_DIRS.
# Inside this rootless Distrobox container /usr/share/terminfo has no 'xterm'
# entry (only /run/host/usr/share/terminfo/x/xterm does), so .NET loads no
# terminfo, CursorAddress (cup) is null, Console.SetCursorPosition silently
# emits nothing while still caching the move, and PSReadLine's full-buffer
# redraw never repositions to the prompt origin -> the interactive "smear".
# CPR (ESC[6n) is unaffected because .NET hard-codes it.  Point .NET at the
# host terminfo tree so cup is emitted and the redraw is correct.  (Root cause
# confirmed 2026-07-06 via strace: openat of the host xterm entry + 26 CUP
# writes appear, smear gone.)
if [ -d /run/host/usr/share/terminfo ]; then
  export TERMINFO=/run/host/usr/share/terminfo
fi

# Let pwsh handle the TTY directly.  PSReadLine (PowerShell 7's readline
# engine) sets raw terminal mode itself and handles all echoing; running
# stty -echo before launch creates a double-echo conflict with PSReadLine.
pwsh -NoLogo -NoProfile
#+END_SRC

#+BEGIN_SRC powershell :tangle linux/.config/redstone-9x/powershell/basic-repl.ps1 :mkdirp yes
$host.UI.RawUI.WindowTitle = "Windows PowerShell"
Remove-Module PSReadLine -Force -ErrorAction SilentlyContinue

while ($true) {
    [Console]::Write("PS $($PWD.Path)> ")
    $line = [Console]::ReadLine()
    if ($null -eq $line) { break }
    if ($line.Trim() -eq "exit") { break }
    if ($line.Trim().Length -eq 0) { continue }

    try {
        Invoke-Expression $line
    }
    catch {
        Write-Error $_
    }
}
#+END_SRC

** Bash and Zsh PowerShell-frame launchers (Run-box safe)

=bash= and =zsh= typed in the Run box open the PowerShell-frame urxvt, like the
Terminals menu and desktop shortcuts.  Unlike =cmd=/=powershell=, these names
ARE real shells that scripts constantly resolve via PATH — and =~/.local/bin=
is first on the session PATH, so the Run-box symlinks =bash=/=zsh= -> these
launchers shadow the real binaries for every bare-name lookup.  The launcher
therefore passes through to the real shell for anything that is not an
unambiguous GUI launch: any arguments (=bash script.sh=, =zsh -c …=), a tty on
stdin (a user typing =bash= inside a terminal keeps normal nesting), or piped
stdin (=echo cmd | bash=).  Only =--window= (menu/desktop entries) or a bare
no-arg call with stdin on =/dev/null= and =DISPLAY= set (the Run box) opens the
styled terminal.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-bash :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -u
# Resolve the REAL shell by walking PATH past our own directory (the symlink
# `bash` -> this script lives in ~/.local/bin, which is first on PATH).
self_dir="$(cd "$(dirname "$0")" && pwd)"
shell_name="bash"
real=""
IFS=: read -ra _dirs <<< "${PATH}"
for _d in "${_dirs[@]}"; do
  [ "${_d}" = "${self_dir}" ] && continue
  [ -x "${_d}/${shell_name}" ] && { real="${_d}/${shell_name}"; break; }
done
[ -n "${real}" ] || real="/bin/${shell_name}"

if [ "${1:-}" != "--window" ]; then
  # Passthrough unless this is an unambiguous GUI launch (Run box): no args,
  # stdin is /dev/null, DISPLAY present. Everything else gets the real shell.
  if [ $# -gt 0 ] || [ -t 0 ] || [ -z "${DISPLAY:-}" ] \
     || [ "$(readlink -f /proc/self/fd/0 2>/dev/null)" != "/dev/null" ]; then
    exec "${real}" "$@"
  fi
fi

exec redstone-9x-run urxvt -name redstone-bash-powershell -title "Bash" \
  -geometry 80x25 +sb -bg rgb:01/24/56 -fg rgb:ee/ed/f0 -cr rgb:ee/ed/f0 \
  -fn "xft:Cascadia Mono:size=11:antialias=true,xft:Consolas:size=11:antialias=true" \
  -e "${real}"
#+END_SRC

* Audacious profile

Redstone seeds only baseline Audacious Winamp-interface preferences.  The
launcher projects the skin corpus into Audacious' guest-local skin directory.

Skin *selection* used to be excluded from scheme control here on the grounds that
it was user preference — that decree was lifted on Mètsàtron's instruction on
2026-07-25, and the skin is now a scheme layer like the GTK theme or the sound
pack.  =redstone-9x-scheme-apply= maps it by =SCHEME_ID= dynasty (BeOS → =BeOS=,
Windows 3.1 → =Likon__Old_Mac_OS=, 95 → =Winamp_9x=, 98 and the Plus! set →
=Windows98=, 2000 → =Windows_Style=, XP → =WinXPamp=, KDE → =Nostalgia_9x=,
SerenityOS → =9xStyle= with the eleven dark variants on =combustion_TM=, CDE and
its palettes → =Lightamp=).  Two escape hatches remain, so this is a default and
not a seizure: a =.scheme= may set =AUDACIOUS_SKIN= to any other file, and
=AUDACIOUS_SKIN=none= restores the old behaviour of leaving the guest's own
choice untouched.

One hazard is handled explicitly rather than papered over: Audacious rewrites
=config= wholesale when it exits, so a write performed under a running instance
would be silently reverted the moment the player closes.  The apply step detects
a live =audacious= and says the skin lands on its next start, instead of claiming
a success that the next exit would quietly undo.  It does not kill the player —
a theme switch is not worth stopping someone's music.

** Wine tool dispatcher — redstone-9x-wine

One env-wrapped entry point for every Wine tool.  It sources the same three Guix
profiles and Wine environment as =redstone-9x-run=, then dispatches to a tool
chosen either by an explicit first argument (how the IceWM menu calls it, e.g.
=redstone-9x-wine winecfg=) or by its own invoked name (how the Run-box PATH
shims call it — =~/.local/bin/explorer= is a symlink to this script, so typing
=explorer= in the Run box lands here with =$0= = =explorer=).  Native profile
binaries (winetricks, wineboot, msiexec, regsvr32) are exec'd by ABSOLUTE path so
a same-named PATH shim can never recurse into itself; the =.exe= tools go through
=wine=, which is never shadowed.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-wine :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -euo pipefail

GUIX_PROFILES="${HOME}/.guix-extra-profiles"
WINCOMPAT="${GUIX_PROFILES}/room-windows-compat/room-windows-compat"

source_guix_profile() {
  local profile="$1"
  local status=0
  local had_nounset=0

  case $- in
    *u*) had_nounset=1; set +u ;;
  esac

  GUIX_PROFILE="$profile"
  export GUIX_PROFILE

  if . "$profile/etc/profile"; then
    status=0
  else
    status=$?
  fi

  (( had_nounset )) && set -u
  return "$status"
}

for _prof in desktop-common room-gaming room-windows-compat; do
  source_guix_profile "${GUIX_PROFILES}/${_prof}/${_prof}"
done

export DISPLAY="${DISPLAY:-:93}"
export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"
export WINEPREFIX="${WINEPREFIX:-${HOME}/.wine-redstone}"
export WINEDEBUG="${WINEDEBUG:--all}"
export DOTCORTEX_DIR="${DOTCORTEX_DIR:-${HOME}/DotCortex}"

# Pick the tool: explicit first arg when invoked as redstone-9x-wine, otherwise
# the name we were called by (a PATH shim symlink).
self="$(basename "$0")"
if [ "${self}" = "redstone-9x-wine" ]; then
  tool="${1:-explorer}"
  shift || true
else
  tool="${self}"
fi

case "${tool}" in
  # Native profile binaries — absolute path so a same-named shim can't recurse.
  winetricks)
    if [ "$#" -eq 0 ] && command -v zenity >/dev/null 2>&1; then
      exec "${WINCOMPAT}/bin/winetricks" --gui
    fi
    exec "${WINCOMPAT}/bin/winetricks" "$@" ;;
  wineboot|msiexec|regsvr32|winedbg|winepath)
    exec "${WINCOMPAT}/bin/${tool}" "$@" ;;
  # Friendly aliases.
  ie|iexplore) exec wine iexplore.exe "$@" ;;
  uninstall|addremove) exec wine uninstaller.exe "$@" ;;
  cmd|command) exec wine cmd.exe "$@" ;;
  # Everything else is a Wine built-in .exe reached through the wine loader.
  *) exec wine "${tool}" "$@" ;;
esac

* Program tree — the menu as a browsable directory (2026-07-25)

Mètsàtron's idea, and a historically exact one: CDE's *Application Manager* was
literally a filesystem tree of actions rendered as an icon browser, and Windows 3.1's
Program Manager groups were =.grp= files doing the same job.  This projects the
=Programs= menu into =~/Programs/= as real directories and =.desktop= files, so the
same software is reachable two ways — pull down the menu, or open a window and
navigate.  With a menu this large the second way is often faster, and it means a
game can be launched without the menu collapsing.

** Why this is cheap rather than a parallel universe

Three properties make it a projection rather than a fork:

1. *The menu is unambiguous.* A grammar census of the tangled =linux/.icewm/menu=
   returns =menu=38 prog=256 menuprog=4 separator=14=, 38 opens balanced by 38
   closes, and — the number that matters — *zero* unrecognised lines.  Four keywords
   describe the whole file, so a parser has nothing to guess at.
2. *One source.* The tree is emitted FROM the menu, so it cannot drift.  Add a game
   once and it appears in both.
3. *Theme-following is free.*  A =.desktop= =Icon== is a NAME, resolved at render
   time through the active icon theme — the same machinery the desktop icons already
   use.  Switch scheme and the tree re-themes with nothing regenerated.

** Folder icons are generic, and that is correct

Verified against the actual binaries rather than assumed: PCManFM 1.4.0 and
libfm 1.4.0 contain no =.directory= string at all (KDE's convention, not libfm's),
and libfm reads =metadata::emblems= but *not* =metadata::custom-icon= — folder
icons come only from the =folder= icon name / =inode/directory= mime.  So every
directory shows the theme's generic folder.

That is not a compromise: Program Manager groups and CDE App Manager drawers were
generic containers too.  The =folder= icon is itself theme-resolved, so folders look
Win95 under Win95 and CDE under CDE, while the programs carry the distinctive art.

** Ordering and dynamic menus

*Ordering is alphanumeric* (Mètsàtron's call).  The menu's authored order is lost —
a file manager sorts by name — but for a Program-Manager feel alphabetical is what
the eye expects anyway.

*=menuprog= entries are snapshotted.*  Ports and Lutris generate their submenu at
open time by scanning the library; a static tree cannot represent that faithfully.
The projector runs each generator and freezes its output, which is why the tree must
be regenerated rather than written once — =loom redstone:programs= re-runs it, and
so does every =redstone:refresh=.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-program-tree :mkdirp yes :shebang "#!/usr/bin/env bash"
# Project the IceWM Programs menu into a browsable directory tree.
#
# Reads the GUEST's menu (tokens already substituted, so Exec lines are runnable)
# and emits ~/Programs/<Menu>/.../<Item>.desktop. Derived output: the tree is
# rebuilt wholesale every run, never merged, so a removed menu entry disappears.
set -euo pipefail

SOURCE="${REDSTONE_MENU_SOURCE:-${HOME}/.icewm/menu}"
ROOT="${REDSTONE_PROGRAM_TREE:-${HOME}/Programs}"
MENU_NAME="${REDSTONE_PROGRAM_MENU:-Programs}"

[[ -f "${SOURCE}" ]] || { echo "redstone-9x-program-tree: no menu at ${SOURCE}" >&2; exit 1; }

python3 - "${SOURCE}" "${ROOT}" "${MENU_NAME}" <<'PY'
import os, shlex, subprocess, sys, tempfile, shutil

source, root, menu_name = sys.argv[1], sys.argv[2], sys.argv[3]


def parse(lines):
    """IceWM menu -> nested dict. Four keywords, nothing else in the grammar."""
    tree = {"kind": "menu", "name": "", "icon": "", "items": []}
    stack = [tree]
    for raw in lines:
        s = raw.strip()
        if not s or s.startswith("#"):
            continue
        if s == "}":
            if len(stack) > 1:
                stack.pop()
            continue
        try:
            tok = shlex.split(s, comments=False)
        except ValueError:
            continue
        if not tok:
            continue
        kw, rest = tok[0], tok[1:]
        if kw == "menu" and s.endswith("{"):
            node = {"kind": "menu", "name": rest[0] if rest else "",
                    "icon": rest[1] if len(rest) > 1 else "", "items": []}
            stack[-1]["items"].append(node)
            stack.append(node)
        elif kw in ("prog", "menuprog"):
            stack[-1]["items"].append({
                "kind": kw, "name": rest[0] if rest else "",
                "icon": rest[1] if len(rest) > 1 else "", "exec": rest[2:]})
    return tree


def safe(name):
    # '/' is the only character a filename genuinely cannot carry; keep the rest
    # so the tree reads like the menu.
    return (name.replace("/", "-").strip() or "unnamed")


def write_desktop(path, name, icon, argv):
    # Exec is a .desktop field code string: a literal % must be doubled or the
    # launcher eats it as a field code.
    cmd = " ".join(shlex.quote(a) for a in argv).replace("%", "%%")
    with open(path, "w") as f:
        f.write("[Desktop Entry]\n"
                "Version=1.0\n"
                "Type=Application\n"
                f"Name={name}\n"
                f"Exec={cmd}\n"
                f"Icon={icon}\n"
                "Terminal=false\n")
    os.chmod(path, 0o755)


def snapshot_menuprog(node):
    """Run a dynamic generator and parse its emitted menu fragment."""
    try:
        out = subprocess.run(node["exec"], capture_output=True, text=True,
                             timeout=60).stdout
    except Exception as e:
        print(f"redstone-9x-program-tree: {node['name']}: generator failed: {e}",
              file=sys.stderr)
        return None
    return parse(out.splitlines())


def emit(node, path, counts):
    os.makedirs(path, exist_ok=True)
    for it in node["items"]:
        if it["kind"] == "menu":
            emit(it, os.path.join(path, safe(it["name"])), counts)
            counts["dirs"] += 1
        elif it["kind"] == "prog":
            if not it["exec"]:
                continue
            write_desktop(os.path.join(path, safe(it["name"]) + ".desktop"),
                          it["name"], it["icon"], it["exec"])
            counts["progs"] += 1
        elif it["kind"] == "menuprog":
            sub = snapshot_menuprog(it)
            if sub is None:
                continue
            emit(sub, os.path.join(path, safe(it["name"])), counts)
            counts["dirs"] += 1
            counts["snapshots"] += 1


tree = parse(open(source, errors="replace").read().splitlines())
target = None
for it in tree["items"]:
    if it["kind"] == "menu" and it["name"] == menu_name:
        target = it
        break
if target is None:
    print(f"redstone-9x-program-tree: no top-level menu {menu_name!r} in {source}",
          file=sys.stderr)
    sys.exit(1)

# Build into a sibling temp dir and swap, so a half-written tree is never visible
# and a crash mid-build leaves the previous tree intact.
counts = {"dirs": 0, "progs": 0, "snapshots": 0}
staging = tempfile.mkdtemp(prefix=".program-tree-", dir=os.path.dirname(root) or ".")
try:
    emit(target, staging, counts)
    old = root + ".old"
    shutil.rmtree(old, ignore_errors=True)
    if os.path.exists(root):
        os.rename(root, old)
    os.rename(staging, root)
    shutil.rmtree(old, ignore_errors=True)
except Exception:
    shutil.rmtree(staging, ignore_errors=True)
    raise
print(f"redstone-9x-program-tree: {counts['progs']} programs in {counts['dirs']} "
      f"folders ({counts['snapshots']} dynamic snapshot(s)) -> {root}")
PY
#+END_SRC
