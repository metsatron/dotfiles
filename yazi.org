* Purpose

This file declares the Yazi terminal file manager's config so navigation, preview, and theme stay declarative and tangle into the Linux overlay the same way =rofi.org= does for the launcher suite. Yazi merges any config supplied here over its own compiled-in defaults, so every block below is intentionally a *minimal diff* against stock rather than a full recreation of the shipped file — an empty or omitted key means "use the binary's own default," which is the idiomatic way to configure Yazi and avoids drift when the crate version moves.

Install lane is DotCortex Lane 1 cargo (=cargo.org=, crates =yazi-fm= + =yazi-cli=), not Guix — =guix search yazi= returns nothing on this machine, and =gitreleases.org= is retired in favour of package-specific manifests, so cargo is the correct and only sanctioned lane here.

* yazi.toml — manager and preview

Only the settings worth stating on purpose: alphabetical sort with directories first (stock-adjacent, just made explicit), hidden files off by default, and preview sizing generous enough for image work. Yazi speaks the kitty graphics protocol natively by detecting the terminal at runtime — no PIL, no ueberzug, no extra config keys required to turn it on. Mouse is left completely unspecified so whatever Yazi ships as its compiled-in default applies unchanged, per the "mouse off unless stock default" instruction — the correct way to satisfy that is to not touch the key at all.

#+BEGIN_SRC toml :tangle all/.config/yazi/yazi.toml :tangle-mode (identity #o644)
[mgr]
sort_by        = "alphabetical"
sort_dir_first = true
show_hidden    = false

[preview]
max_width    = 1200
max_height   = 900
image_quality = 90
#+END_SRC

* keymap.toml — defaults plus nothing

Vim-style navigation (=h/j/k/l=, =g g=, =G=, etc.) is Yazi's compiled-in default, so the correct "defaults-plus-minimal" keymap is zero overrides — any invented binding here would be a guess at a schema this machine has not yet run against a live binary, and Yazi does not need help to already be vim-native. Once =yazi --version= is confirmed post-build, narrow overrides can be added here if a real gap shows up; until then this file exists only so the tangle target is present and stow-managed.

* theme.toml — LainCore DreamWeave

Palette lifted directly from =all/.config/rofi/colors/laincore-dreamweave.rasi= (itself generated from =lc/base16='s =dreamweaver-cc2017= entry in =style.org=), the same canon that already drives Rofi, kitty, Emacs, nvim, and VSCodium. Nothing here is eyeballed — every hex below traces to a =base0X= slot:

| slot            | base16 key | hex       | role in this theme                  |
|-----------------+------------+-----------+--------------------------------------|
| background      | =base00=    | =#1f1f1f= | app/tab-inactive background          |
| background-alt  | =base01=    | =#242424= | tab-inactive bg, status separators   |
| border/dim      | =base02/03=| =#454545=/=#6a6a6a= | borders, permission separators |
| foreground      | =base05=    | =#d2d4d4= | default text, tab-inactive fg        |
| red             | =base08=    | =#dc322f= | cut marker, unset mode, perm write   |
| orange          | =base09=    | =#cb4b16= | archive filetypes                    |
| yellow          | =base0A=    | =#b58900= | find keyword, selected marker, perm read |
| green           | =base0B=    | =#4caf50= | copied marker, select mode, perm exec |
| cyan/accent     | =base0C=    | =#15b8cf= | hovered row, active tab, borders, marked marker |
| blue            | =base0D=    | =#268bd2= | cwd path, directories, perm type     |
| purple          | =base0E=    | =#a681d6= | image/video/audio filetypes          |

Coverage here is restrained on purpose — manager, mode, status, input/select/confirm borders, and a small filetype set. Anything left unset (notify, pick, completion, help, spot) falls back to Yazi's own default theme, which is correct: those surfaces are low-visibility and inventing colours for all of them would be decoration, not design.
