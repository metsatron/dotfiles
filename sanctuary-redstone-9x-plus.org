* What this is

Nineteen genuine Microsoft Windows 98 Plus! desktop themes ([Control Panel\Colors]
format, decimal R G B), extracted from =plus98/PLUS98.CAB= inside =Microsoft Plus!
For Windows 98.iso=, run through the existing =redstone-9x-theme-convert= /
=redstone-9x-classic-build= engine (see the =redstone-9x-serenity-pipeline= skill,
which documents that engine as shared with the SerenityOS Themes submenu) to
produce 19 =Themes > Windows 98 Plus!= submenu entries.

This module replaces the naming of the pre-existing 16-entry "Windows 98 Plus!"
submenu, which does not actually contain official Windows 98 Plus! content — see
=Provenance and the naming correction= below. That submenu's declaration in
=sanctuary-redstone-9x-fvwm95.org= is relabeled in the same change that adds this
module's submenu, so the truthful name ("Windows 95 Plus! / Plus! for Kids") and
the real "Windows 98 Plus!" set both exist, correctly labeled, side by side.

** Provenance and the naming correction

Cross-referencing the pre-existing =plus-*= scheme ids (=plus-baseball= ..
=plus-windows-98=, 16 entries, declared at =sanctuary-redstone-9x-fvwm95.org= lines
~1174-1190) against this pack's real =PLUS98.CAB= shows zero name overlap. The
official Windows 98 Plus! set is licensed/branded content (Garfield, Peanuts,
Doonesbury, FoxTrot, Cathy comic strips; Corbis and PhotoDisc stock-photo packs;
Rock 'n Roll, Jazz, Sci-Fi, Horror, Fashion, Geometry, Architecture, Cityscape,
Falling Leaves, World Travel, Windfall, and the plain "Windows 98" default). The
pre-existing 16 instead trace to *Windows 95 Plus!* (=PLUS_3.CAB=..=PLUS_7.CAB=
inside =Microsoft Plus! for Windows 95.iso=: Sixties, Science, Dangerous Creatures,
DaVinci, Sports, Mystery, PCInside, Nature, Travel — 9 of the 16) plus *Plus! for
Kids* (=Themes/Baseball=, =Jungle=, =Space=, =UndrWtr= — 4 more of the 16), with the
remaining 3 (More Windows, The Golden Era, Windows 98 Plus) of undetermined origin
within those two packs. Ruling (Mètsàtron, 2026-07-27): relabel the pre-existing
submenu to its true provenance rather than merging namespaces; this module's 19
themes become the new, correctly-attributed "Windows 98 Plus!" submenu. The
=plus-*= scheme ids and their theme directories are untouched — only the visible
submenu title and its own menu label change, in =sanctuary-redstone-9x-fvwm95.org=.

** Scope — colors-only, this pass

Per ruling (2026-07-27): wallpapers, sounds, and icons are out of scope for this
pass, exactly like the pre-existing 16 Plus! conversions this module sits beside.
Only =[Control Panel\Colors]= is read; =redstone-9x-theme-convert= always sets
=icon='Win98SE'=, ignores wallpaper keys, and only ever derives the desktop
background as a flat colour. The bucketed prefix files above (comic-strip
character renders, Corbis/PhotoDisc stock photos, per-theme cursors/icons/wavs)
are catalogued for provenance but not applied to the produced theme — the same
tradeoff already shipped and accepted for the existing 16. Wallpapers for these
(and the existing 16) have their own pending lane: harvested to
=~/HelmCortex/NEXUS/sanctuaries/sanctuary-redstone-9x/wallpapers/plus-wallpapers-20260727/=
(canonical NEXUS source archive, 2026-08-07), ruling pending per-theme, tracked
separately from this module.

Amendment (2026-07-27, same night): Mètsàtron ruled the GTK layer confirmed
working live and asked for *startup sound only* — not the full open/close/
minimize/error/logoff event set — for these 19. This is a narrower carve-out of
the "sounds out of scope" line above, not a reversal of it: only the single
=SystemStart= event is wired; every other event file stays absent exactly as
ruled. See =Startup sounds= below for the mechanism and the per-theme table.

*** How the existing convention works (reused exactly, no parallel mechanism)

=redstone-9x-scheme-apply= (=sanctuary-redstone-9x-schemes.org=) reads
=SOUND_SCHEME= from the =.scheme= file (already written by
=redstone-9x-theme-convert= as =SOUND_SCHEME="<scheme-id>"= — no scheme-file
change needed here) and re-points the =~/.local/share/sounds/sanctuary= symlink
at =~/.local/share/sounds/schemes/<SOUND_SCHEME>/= inside the GUEST home (this
tree is guest runtime state, never git-tracked — same boundary as the wine
prefix and other per-guest media). Its *chime fallback* (decree 2026-07-19)
already copies =windows-98='s =startup.wav= into any scheme's dir lacking one,
both at the scheme root and under its own =icewm/= subdirectory — that is the
exact pair of paths this module populates, so a theme that has never been
staged just falls through to the existing fallback unchanged, precisely per
ruling for Windfall. The actual playback is =sanctuary-sound startup=
(=~/.local/bin/sanctuary-sound=), invoked at the end of =redstone-9x-scheme-apply=
after every appearance layer has converged; it reads
=~/.local/share/sounds/sanctuary/startup.{wav,ogg,flac,mp3}= (first match) and
plays it via a =paplay -> ffplay -> play -> pw-play -> aplay= fallback chain —
=paplay= reaches the guest's PulseAudio socket at its default in-guest path, so
none of the Flatpak =/run/flatpak/pulse= gotchas from =sanctuary-gotchas= apply
here (this path was never Flatpak-routed to begin with). Nothing about this
module invents a new sound mechanism; it only populates the two files the
existing mechanism already looks for.

** Known issues

- *GARFIELD.THE had one malformed line*: =InactiveTitle=255 208.128= (a stray
  period where a space belongs). =redstone-9x-theme-convert='s parser requires
  exactly 3 whitespace-separated all-digit tokens per colour line; the malformed
  line failed that check silently (dropped), and =InactiveTitle= is a required
  key, so unmodified conversion aborted with =MISSING KEYS: ['InactiveTitle']=.
  Fixed by writing a patched copy (=InactiveTitle=255 208 128=, the period is
  OCR/mastering noise) via the provisioner below — the original extracted =.THE=
  under =media/plus98/raw/= is never edited in place; the corrected copy lives
  under =media/plus98/patched/= instead.
- 5 of 19 themes (Cathy, Corbis, Doonesbury, FoxTrot, Garfield) have no
  =GradientActiveTitle=/=GradientInactiveTitle= keys. Not a bug: the parser
  already synthesizes a 50%-to-white blend when absent, the same fallback path
  already exercised by the Plus! 95-era conversions.
- *Directory-name collision trap*: =redstone-9x-theme-convert='s output directory
  is derived from its =TNAME= argument (spaces -> dashes), not from the scheme
  id. The official Plus! 98 "Windows 98" default theme's display name sanitizes
  to =Windows-98=, which is byte-identical to the pre-existing, unrelated
  =linux/.icewm/themes/Windows-98/= directory used by the classic =windows-98=
  Desktop Scheme (author "bongo", sourced from Chicago95 — see its own
  =default.theme=). A first pass of this module used that literal =TNAME= and
  silently overwrote the classic theme's pixmaps and =default.theme= in place;
  caught by =git status= showing unexpected =M= entries against an untouched
  sibling file, reverted via =git restore=, and fixed by renaming this theme's
  own =TNAME= to =Plus98-Windows-98= (scheme id unchanged: =plus98-windows-98=).
  Any future addition to this pipeline must check its =TNAME= against existing
  =linux/.icewm/themes/*= and =linux/.themes/*= directory names before running
  the converter, not after.

** Gaps — explicitly deferred, not attempted this pass

- *Windows XP Plus!* (=Microsoft Plus! For Windows XP.iso=): ships 4 real theme
  files but they are Luna-era =[VisualStyles]= themes with no
  =[Control Panel\Colors]= section — colour lives inside a referenced
  =luna.msstyles= binary. =redstone-9x-theme-convert= only parses the classic
  Windows/SerenityOS colour-key branches; reading Luna themes needs a new
  =.msstyles= binary palette-extraction path. Real engine work, out of scope
  tonight per ruling.
- *MODERNE.THM* (Windows 95 Plus!, =Microsoft Plus! for Windows 95.iso=): a
  possible 17th Win95-era theme with no obvious match among the existing 16.
  Deferred per ruling; noted here for a future pass if full Win95 Plus! coverage
  is ever wanted. =WIN95HC.THM= (High Contrast) is an accessibility variant, not
  menu-worthy, and not pursued either.
- *Microsoft Plus! Game Pack — Cards and Puzzles* and *Microsoft Plus! Digital
  Media Edition*: no =.theme=/=.thm= files on either ISO. Digital Media Edition
  instead carries eight Windows Media Player =.wmz= skins — a different content
  class Redstone 9X has no engine to consume. Out of scope.

* Provisioner — redstone-9x-plus98-provision

Host-side, idempotent, modeled on =redstone-9x-msgames-provision='s staging
pattern (marker file, =--force=/=--restage=). Stages a CAB, not a zip: the pack
ships one 99.7 MB compressed / 168 MB uncompressed old-style MS Cabinet whose 1677
members are flat (no directory metadata). Writes the 19 source =.THE= files
through unmodified except GARFIELD, which gets its one malformed colour line
corrected into a separate patched copy — the extracted CAB payload is never
edited in place.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-plus98-provision :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -euo pipefail

SANCTUARY="sanctuary-redstone-9x"
GUESTS_DIR="${XDG_DATA_HOME:-$HOME/.local/share}/dotcortex/guests"
MEDIA="${GUESTS_DIR}/${SANCTUARY}/media/plus98"
MARKER="${MEDIA}/.dotcortex-plus98-complete"

DEFAULT_ISO="${HOME}/HelmCortex/NEXUS/sanctuaries/sanctuary-redstone-9x/iso/microsoft-plus-for-collection/Microsoft Plus! For Windows 98.iso"
ISO="${PLUS98_ISO:-${DEFAULT_ISO}}"

FORCE=0; RESTAGE=0
for a in "$@"; do
  case "${a}" in
    --force)   FORCE=1 ;;
    --restage) FORCE=1; RESTAGE=1 ;;
  esac
done

if [[ -f "${MARKER}" && "${FORCE}" -eq 0 ]]; then
  echo "redstone-9x-plus98: already provisioned (${MEDIA}) — use --force to redo"
  exit 0
fi

[[ -f "${ISO}" ]] || { echo "redstone-9x-plus98: ISO not found: ${ISO}" >&2; exit 1; }
command -v 7z >/dev/null 2>&1 || { echo "redstone-9x-plus98: 7z not found" >&2; exit 1; }

if [[ "${RESTAGE}" -eq 1 || ! -d "${MEDIA}/raw" ]]; then
  rm -rf "${MEDIA}"
  mkdir -p "${MEDIA}/cab" "${MEDIA}/raw" "${MEDIA}/patched"
  7z x -y -o"${MEDIA}/cab" "${ISO}" plus98 >/dev/null
  7z x -y -o"${MEDIA}/raw" "${MEDIA}/cab/plus98/PLUS98.CAB" >/dev/null
fi

mkdir -p "${MEDIA}/patched"
for f in "${MEDIA}"/raw/*.THE; do
  b="$(basename "${f}")"
  if [[ "${b}" == "GARFIELD.THE" ]]; then
    sed 's/InactiveTitle=255 208\.128/InactiveTitle=255 208 128/' "${f}" > "${MEDIA}/patched/${b}"
  else
    cp "${f}" "${MEDIA}/patched/${b}"
  fi
done

touch "${MARKER}"
echo "redstone-9x-plus98: staged — ${MEDIA} (19 .THE files patched into ${MEDIA}/patched)"
#+END_SRC

* Converter — redstone-9x-plus98-install

Loops =redstone-9x-theme-convert= over the 19 patched =.THE= files, one call per
row of the coverage table above. Idempotent per theme: skips a scheme id whose
=.scheme= file already exists unless =--force= is given.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-plus98-install :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -euo pipefail

SANCTUARY="sanctuary-redstone-9x"
GUESTS_DIR="${XDG_DATA_HOME:-$HOME/.local/share}/dotcortex/guests"
MEDIA="${GUESTS_DIR}/${SANCTUARY}/media/plus98/patched"
SCHEMES_DIR="${HOME}/DotCortex/linux/.config/redstone-9x/schemes"

FORCE=0
for a in "$@"; do [[ "${a}" == "--force" ]] && FORCE=1; done

declare -A THEMES=(
  [ARCHITEC.THE]="Architecture|plus98-architecture"
  [CATHY.THE]="Cathy|plus98-cathy"
  [CITYSCAP.THE]="Cityscape|plus98-cityscape"
  [CORBIS.THE]="Corbis|plus98-corbis"
  [DOONBURY.THE]="Doonesbury|plus98-doonesbury"
  [FALLINGL.THE]="Falling-Leaves|plus98-falling-leaves"
  [FASHION.THE]="Fashion|plus98-fashion"
  [FOXTROT.THE]="FoxTrot|plus98-foxtrot"
  [GARFIELD.THE]="Garfield|plus98-garfield"
  [GEOMETRY.THE]="Geometry|plus98-geometry"
  [HORROR.THE]="Horror|plus98-horror"
  [JAZZ.THE]="Jazz|plus98-jazz"
  [PEANUTS.THE]="Peanuts|plus98-peanuts"
  [PHODISC.THE]="PhotoDisc|plus98-photodisc"
  [ROCKROLL.THE]="Rock-n-Roll|plus98-rock-n-roll"
  [SCIFI.THE]="Science-Fiction|plus98-scifi"
  [WIN98.THE]="Plus98-Windows-98|plus98-windows-98"
  [WINDFALT.THE]="Windfall|plus98-windfall"
  [WOTRAVEL.THE]="World-Travel|plus98-world-travel"
)

for src_name in "${!THEMES[@]}"; do
  IFS='|' read -r tname sid <<< "${THEMES[${src_name}]}"
  src="${MEDIA}/${src_name}"
  scheme_file="${SCHEMES_DIR}/${sid}.scheme"
  if [[ ! -f "${src}" ]]; then
    echo "skip ${sid}: no source staged at ${src}" >&2
    continue
  fi
  if [[ -f "${scheme_file}" && "${FORCE}" -eq 0 ]]; then
    echo "skip ${sid}: already converted (${scheme_file}) — use --force to redo"
    continue
  fi
  redstone-9x-theme-convert "${src}" "${tname}" "${sid}"
done
#+END_SRC

* Sound stager — redstone-9x-plus98-install-sounds

Stages each theme's own =SystemStart= WAV (see the coverage table above) into
the guest's sound-scheme directory, reusing =redstone-9x-scheme-apply='s own
convention exactly: =~/.local/share/sounds/schemes/<sid>/startup.wav= and
=.../icewm/startup.wav=, inside the GUEST home — never the host, never a
git-tracked path (same runtime-state boundary as the wine prefix). Sourced
from the RAW extraction (=media/plus98/raw/=, not =patched/= — the malformed
line touched only GARFIELD's colour keys, not any theme's audio). Windfall is
skipped outright: its =.THE= declares no own asset, so the existing chime
fallback in =redstone-9x-scheme-apply= (and in the refresh sweep) supplies
=windows-98='s chime for it, exactly as ruled. Idempotent: skips a scheme
already holding its own =startup.wav= of the expected size unless =--force= is
given, so a prior chime-fallback placeholder (also literally named
=startup.wav=, but copied from =windows-98=, size 693212 bytes) is always
overwritten with the theme's genuine asset.

#+BEGIN_SRC bash :tangle linux/.local/bin/redstone-9x-plus98-install-sounds :shebang "#!/bin/bash" :tangle-mode (identity #o755)
set -euo pipefail

SANCTUARY="sanctuary-redstone-9x"
GUESTS_DIR="${XDG_DATA_HOME:-$HOME/.local/share}/dotcortex/guests"
RAW="${GUESTS_DIR}/${SANCTUARY}/media/plus98/raw"
GUEST_HOME="${GUESTS_DIR}/${SANCTUARY}/home"
SND="${GUEST_HOME}/.local/share/sounds/schemes"

FORCE=0
for a in "$@"; do [[ "${a}" == "--force" ]] && FORCE=1; done

declare -A STARTWAV=(
  [plus98-architecture]="AR_START.WAV"
  [plus98-cathy]="CY_START.WAV"
  [plus98-cityscape]="CS_START.WAV"
  [plus98-corbis]="CP_START.WAV"
  [plus98-doonesbury]="DB_START.WAV"
  [plus98-falling-leaves]="FL_START.WAV"
  [plus98-fashion]="FA_START.WAV"
  [plus98-foxtrot]="FO_START.WAV"
  [plus98-garfield]="GA_START.WAV"
  [plus98-geometry]="GE_START.WAV"
  [plus98-horror]="HC_START.WAV"
  [plus98-jazz]="JA_START.WAV"
  [plus98-peanuts]="PE_START.WAV"
  [plus98-photodisc]="PD_START.WAV"
  [plus98-rock-n-roll]="RO_START.WAV"
  [plus98-scifi]="SF_START.WAV"
  [plus98-windows-98]="WI_START.WAV"
  [plus98-world-travel]="WO_START.WAV"
  # plus98-windfall intentionally absent — no own asset, chime fallback applies
)

for sid in "${!STARTWAV[@]}"; do
  wav="${RAW}/${STARTWAV[${sid}]}"
  if [[ ! -f "${wav}" ]]; then
    echo "skip ${sid}: source wav not staged at ${wav}" >&2
    continue
  fi
  dest_dir="${SND}/${sid}"
  dest="${dest_dir}/startup.wav"
  icewm_dest="${dest_dir}/icewm/startup.wav"
  if [[ -f "${dest}" && "${FORCE}" -eq 0 ]]; then
    src_size="$(stat -c%s "${wav}")"
    dest_size="$(stat -c%s "${dest}")"
    if [[ "${src_size}" == "${dest_size}" ]]; then
      echo "skip ${sid}: startup.wav already staged (${dest})"
      continue
    fi
  fi
  mkdir -p "${dest_dir}/icewm"
  cp "${wav}" "${dest}"
  cp "${wav}" "${icewm_dest}"
  echo "${sid}: staged $(basename "${wav}") -> ${dest}"
done
#+END_SRC
